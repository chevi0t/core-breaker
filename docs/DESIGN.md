# コアブレイカー 設計書（試作 v0.21）

ボーダーブレイク（SEGA、2023年サービス終了）の遊びをPCで再現するファンメイド試作の設計書です。
人間の開発者と、Claude・Codex などのAIがこのファイルを読んでゲームを改造できるように書いています。
公式の素材・名称・ロゴは使いません。数値の多くは有志wikiの値を参考にした仮置きです。

## 1. ファイル構成と動かし方

| ファイル | 中身 |
|---|---|
| `index.html` | ゲーム本体。HTML・CSS・JavaScriptが1ファイルにまとまっている。ビルド不要 |
| `three.min.js` | three.js r128（MITライセンス）。配布zipでは同梱、開発版はCDNから読む |
| `sounds.js` | 効果音のデータ（`window.SOUND_DATA`）。`tools/build_sounds.py` が作る。無くても無音で動く |
| `maps.js` | マップのデータ（`window.MAP_DATA`）。`tools/build_maps.py` が `prototype/maps/*.js` から作る。無いと遊べない |
| `MAPS.md` | マップの書き方と今あるマップの詳細（開発版では `prototype/maps/README.md`） |
| `music.js` | 戦闘中BGMのデータ（`window.MUSIC_DATA`）。`tools/build_sounds.py --music` が作る。無くてもBGMが鳴らないだけ |
| `SOUND-CREDITS.md` | 効果音とBGMの出典とライセンス（開発版では `sounds/CREDITS.md`） |
| `DESIGN.md` | この設計書 |
| `AGENTS.md` / `CLAUDE.md` | AIエージェント向けの作業ルール（CLAUDE.md は AGENTS.md を読み込むだけ） |
| `README.txt` | 遊ぶ人向けの説明 |

- 遊ぶ：`index.html` をブラウザで開く。マウスが固定されないときは `python -m http.server 8000` を実行して `http://localhost:8000` を開く。
- 改造する：`index.html` を直接編集してブラウザを再読み込みするだけ。

## 2. ゲームの骨組み

- 人数の既定値と試合時間はマップで決まる（`MAPS`）。出撃前の1つの選択欄で、全マップを2対2〜50対50に変更できる。台地演習場の推奨は5対5・5分、広域演習場は10対10・10分（v0.10）。プレイヤー＋味方Bot 対 敵Bot。敵コアの耐久（9000）を0にするか、時間切れ時に残りが多い側の勝ち。
- 人数選択（2026-10-23ユーザー指定）：潮路搬送区だけの50対50スイッチを、全マップ共通の2対2〜50対50の選択に置き換える。自分1機＋味方BOT（片軍人数−1）機 対 敵BOT（片軍人数）機。両軍は常に同人数で、マップ変更・再試合でも維持し、再読み込みか推奨人数ボタンで既定値へ戻す。50対50の大破コア消費は既存の1/800を維持する。スコア表は100機すべてを表示し、Tab＋ホイールでスクロールする。
- 三人称視点。機体の耐久は全員10000（wikiと同じく兵装による差はない）。
- 座標：単位はメートル。y が高さ。B陣営のベースは南（+z）、R陣営は北（-z）。自軍は出撃前に選んだ側で、表示色はどちらから出ても自軍が青・敵軍が橙。マップは原則として中心 (0, 0) をはさんで点対称（`asym` のマップは非対称）で、大きさとベースの位置はマップごと（台地演習場は x ±135・z ±240・ベース z=±210、広域演習場は x ±180・z ±300・ベース z=±265）。丘・高台・坂・谷の高低差がある（第4章「マップと地形」）。
- 向き：`yaw = 0` で北（-z、南側から見た敵ベース方向）を向く。`fwdOf(u)` が前方ベクトル。

### 毎フレームの更新順（`loop`）

0. 戦闘中BGM（`bgmTick`：試合中でスイッチがオンなら鳴らし、そうでなければ止める）。
1. リフトの床と乗員を移動（`liftUpdate`）。各機体：行動不能なら `downTick`、大破していれば再出撃待ち、生きていればエリア移動の待機を数えてから（待ち終わると `doTransfer`）`playerUpdate` か `botUpdate`（移動→照準→武器）。行動不能とエリア移動は v0.17。
2. プラント → 戦況アナウンス（`annTick`：残り時間・コアの残り・ベース侵入。v0.15）→ 指示出しの印と返事（`qchatTick`。v0.17）→ スコア（`scoreTick`）→ 防衛砲台 → レーダー → 砲弾・ロケット・投げる物 → 設置物と偵察機（`gadgetUpdate`）→ リペアポッド（`repairing` を毎フレーム作り直す）→ カタパルト → ジャンプパッド。
3. 勝敗判定、見た目の同期（機体の位置、ブースター炎、銃身の形、リペアの光線、損傷の見た目 `damageLook`）、演出（`fxUpdate`、煙と火の `puffUpdate`）、カメラ、HUD（頭上の名前と耐久 `tagsHud` を含む）。

固定の時間刻みにしたい試験では、`loop` 冒頭の `const dt = Math.min(0.05, ...)` を `const dt = 0.05` に置き換える（第8章）。

## 3. データの約束事

### 当たり判定の持ち主

- 弾が当たるメッシュは `hittables` 配列に入れ、`mesh.userData.ref` に持ち主のオブジェクトを入れる。
- 持ち主の `kind`：`'unit'`（機体）、`'turret'`（防衛砲台）、`'barricade'`、`'core'`、`'umbrella'`（傘。弾を止めるだけ）、設置物の `'mine'`・`'sensor'`（`gadget: true`。`damage` は `damageGadget` へ回す）。`ref` がないメッシュは障害物や柱。
- 地面は `hittables` に入れない。`castFrom` が `terrainHit` で地形との交差を先に求め、レイの長さをそこで打ち切る（戻り値の `ref` は `null`）。
- 移動を止める箱は `obstacles` 配列に `{ minX, maxX, minZ, maxZ, top }` で入れる。`top` より上には乗れる。

### 武器スロット（`slotOf` が作る）

`{ w（WEAPONSの定義）, ammo（マガジン内）, reserve（予備の弾数）, reloadT, cd（次弾までの時間）, spin（ガトリングの回転 0〜1）, temp（ガトリングの熱 0〜100）, ohT（オーバーヒートの残り）, conv（狙撃銃の照準の収束 0〜1）, heat（特別装備のSPゲージ 0〜100）, overheat（SPを使い切って満タンまで使えない）, bn（3点射の残り発数）, held（単発の武器で引き金を押したまま） }`

| キー | 使う武器 | 意味 |

`CLASSES` は各兵装の初期装備。v0.11から、各枠の武器を `ARMORY[兵装][枠]`（先頭が初期装備）から選べる（ユーザー指定「武器のバリエーションとパラメータ作って、選択画面作って」）。v0.11は各枠3種類、v0.14で型を足して全172種、v0.15で仕組みの要る系統を足して全194種、AC系統の追加で285種、オリジナルの光波剣を加えて全286種、誘導ミサイル8型を加えて全294種（追加特別装備9型・マップ指定式榴弾砲4型・副武器33型・補助装備35型を含む）。プレイヤーの選択は `loadout[兵装][枠]` に入り、`localStorage` の `coreBreakerLoadout` に保存する（読めない・知らない値は初期装備に戻す。`normLoadout`）。v0.13から、機体（`mechCfg`）と4兵装の武器（`loadout`）の組み合わせを「構成」として3つ `localStorage` の `coreBreakerBuilds`（`{ cur, list: [{ mech, loadout }×3] }`）に持つ（ユーザー決定）。今の構成は `mechCfg` と `loadout` そのもので、変えるたびに `builds.list[builds.cur]` へ写す（`saveBuilds`。`saveLoadout`・`saveMech` から呼ぶ）。`switchBuild(i)` は今の構成を写してから i 番の構成を `normMech`・`normLoadout` で直して入れる。初めて開いたときは3つとも今の機体と武器の写し。`equip` はプレイヤーなら `loadout`、Botなら出撃ごとに枠ごとにランダムで選ぶ。下の表は初期装備。

| 兵装 | 主武器 `main` | 副武器 `sub` | 補助装備 `aux` | 特別装備 `sp` |
|---|---|---|---|---|
| 強襲 assault | アサルトライフル `ar` | グレネード `grenade` | ソード `sword` | 加速装置 `charger` |
| 重火力 heavy | ガトリング `gatling` | ロケットランチャー `rocket` | 弱化グレネード `weaken` | 重砲 `cannon` |
| 遊撃 raid | 二丁拳銃 `pistols` | 狙撃銃 `sniper` | 偵察機 `drone` | 光学迷彩 `camo` |
| 支援 support | ショットガン `shotgun` | 地雷 `mine` | 索敵センサー `sensor` | リペアユニット `repair` |

中身は wiki（PS4版）の各兵装の初期装備に合わせた。重火力の補助装備は、元のゲームでは画面を数秒見えなくする手榴弾だが、オンライン対戦ではないので弱化グレネードにしている（ユーザー了承）。遊撃の特別装備は光学迷彩（ユーザー指定）。支援の副武器（地雷）は wiki で初期装備を確かめられず、仮に選んだ。

`CLASSES` の `hp` は耐久（無ければ10000）。重火力は耐久14000（v0.9.3、ユーザー指定）。v0.9.3 の重火力の歩き・ダッシュ0.85倍（`move`）は v0.12 でやめ、速さはパーツと武器の重量で決まる（「機体パーツと重量」。標準Ⅰのセットで重火力は約0.84倍、支援は約0.98倍）。`physics` は今も `u.moveMul`（無ければ1）を掛けるが、入れる物は無い。

## 4. ルールと数値

数値の出典は [BORDER BREAK (PS4) @ ウィキ](https://w.atwiki.jp/ps4borderbreak/) と [BORDER BREAK @ ウィキ](https://w.atwiki.jp/borderbreak/)（AC版）。距離はマップが小さいぶん縮めているものがある。2026-10-19 から、新しく足す武器とパーツの型はアーケード版の値に合わせる（ユーザー指定：PS4版は終盤に性能のインフレが大きかった。PS4版の扱いはその後で決める）。今入っている数値の多くは PS4版のまま。

### ロックオン（`lockUpdate`）

- 手動ロック（2026-10-23ユーザー指定、2026-10-24捕捉を拡大）：主武器・近接武器を持ち、頭部のロック距離以内（基準 `LOCK_RANGE` 50m）の敵機・敵砲台を、表示円（`ACQ_R`）の半径2倍以内に捉えて右クリックすると即座に捕捉。円の表示サイズは維持し、捕捉範囲だけ `ACQ_R * 2` とする。複数いる場合は照準に最も近い見える敵を選ぶ。ボタンを離しても追従し、もう一度右クリックで解除する。空振り・解除・対象喪失の後に自動捕捉しない。Qはロック中の対象切り替えだけに使う。
- 捕捉時とQで対象を切り替えた時だけ、対象の胴体（`targetPoint`）を画面中央へ合わせる。肩越しの位置、反動、都市の壁で寄ったカメラを含む実際の視点から角度を調整する。反動の蓄積値は消さず、発射済みの弾も曲げない。捕捉後は従来の追従へ戻り、マウスで頭や進行方向を狙える。
- プレロック表示（2026-10-24ユーザー指定）：未捕捉時、右クリックで捕捉できる敵機・敵砲台に半透明シアンの四隅を出し、照準に最も近い可視候補1体だけ明るくする。`lockCandidates`・`lockAcquirable` を右クリックと共有し、距離・索敵延長・表示円の半径2倍・迷彩・機体目線の遮蔽判定を揃える。距離や投影は毎フレーム更新し、表示用の遮蔽確認だけ最大2体/フレームに分散する（強調候補は約80msを目安に優先）。密集時は他候補の遮蔽反映が遅れる場合がある。クリック時はキャッシュを使わず、その時点で見える最も近い候補を再判定する。持ち替え中・全体マップ・武器選択・設定やメニューでは候補を隠す。ロック中はシアンを隠し、太さ4pxのアンバーの四隅が0.15秒で外から閉じ、一度発光して続く0.15秒で安定表示へ戻る。捕捉・再捕捉・Qで対象を替えた時だけ再生し、移動や遮蔽復帰で繰り返さない。動きを減らすブラウザ設定では最初から安定表示。既存の対象情報・遮蔽中の薄表示・ミサイル専用HUDを維持する。
- 外側の円（`KEEP_R` 0.42）から外れるか、距離外・対象撃破・0.6秒の遮蔽で解除。副武器・手に持つ特別装備・近接以外の補助装備への持ち替え、修理ポッド・エリア移動待機・妨害でも解除し、主武器へ戻しても再捕捉しない。主武器と近接の間では維持し、近接限定戦でも右クリックで捕捉できる。持ち替え中は新たな捕捉を受け付けない。武器を持ち替えない加速装置・迷彩などのON/OFFは維持する。
- v0.10.2（ユーザー指定）：ロック中は画角を1.3分の1（`LOCK_ZOOM`、70度→約54度）にして目標を大きく見せる。マウスの感度も画角に合わせて細かくなる。ズームで画面上のずれが大きく見えても外れる角度が変わらないよう、`KEEP_R` を画角に合わせて広げる（`keepScale`）。そのうえで「外れやすければもうちょい外れにくく」の指示により `KEEP_R` を0.34から0.42へ（動き回る強襲Bot相手の20〜40mで、ロックが続く時間が平均約2.2秒から約3.6秒に）。ショートダッシュで振り切れる仕組みは変えていない。
- **弾は照準どおりに飛ぶ（中心へは補正しない）。** ロック中は、目標が動いた角度だけ視点が追う（`LOCK_TRACK` 1.0、1秒に最大 `LOCK_MAX_RATE` 4ラジアン）。相手がショートダッシュ中は35%（`LOCK_TRACK_SHAKEN`）に落ちる。
- v0.9.1（ユーザー指定で強めた）：照準が機体（`LOCK_BODY`：横に±1m、足元から0.4〜3.9m）から外れていたら、機体の端まで毎秒0.8ラジアン（`LOCK_PULL`）で引き戻す（`lockStick`）。中心へは寄せないので、頭に置いた照準は頭のまま。相手のショートダッシュ中は引き戻さない。
- 反動との両立（2026-10-21ユーザー指定）：引き戻しの縦は `pitch + recoil`、横は `yaw + recoilYaw` を使う。反動で外れたときも敵機へ寄せ、手で反動を抑えて機体へ戻した照準はその位置を保つ。武器ごとの反動値と引き戻す速さは変えない。
- v0.15（ユーザー指摘「全体的に地面が平面だから横エイムだけでヘッドショット入っちゃう」）：上に外れたときは頭のてっぺん（3.9m）ではなく肩（`LOCK_BODY.top` 3.1m）まで下ろす（`lock.down` の間は頭の高さでも止めない）。カメラの高さ（`CAM.up` 4.6m）が頭（3.2〜3.95m）より上なので、それまでは平らな所で水平に構えるだけで照準が頭のてっぺんに吸い付いていた（20〜35mで確かめた：v0.14は頭の3.91m、v0.15は胴の3.15m）。下ろし終わった後に自分で頭に置けば頭を追い続ける。地形の起伏はマップ製作のスレッドへ回した。
- 狙撃銃を持っている間はロックしない（wiki）。
- v0.11.2（ユーザー指定）：索敵を受けている敵機（`spotted` に入っている）は `SPOT_LOCK`（1.5倍、仮）遠くからロックできる（プレイヤーは75m）。Botも気づく距離（70m）が1.5倍の105mになる。
- 光学迷彩で消えている敵はロックできない。ロック中に消えたら1秒後に外れる（wiki）。
- Botと防衛砲台の照準も同じ考え方（`trackAim`）：目標の動きを85%だけ追い、ずれが `BOT_LOCK_BREAK` を超えると0.7秒撃てない。光学迷彩の相手はロックできないので、追う割合はショートダッシュ中と同じ35%。

### 誘導ミサイル（ブラウザ版、2026-10-21）

- 強襲副武器の誘導ミサイル `missile`（VP-4系）と重火力副武器の多目標ミサイル `mlrs`（GQ-6系）を各4型追加。全294種。数値はAC版の現行表で、採用行・未採用行・暫定値は `research/weapons/types/guided-missiles.json`、比較は `research/weapons/guided-missiles.md` に分ける。Godot版には自動反映しない。
- `missileLockTick` は通常の `lockUpdate` と別。ミサイル中は通常の視点追従・ロック時ズームをせず、四角い照準内に敵機か敵砲台を捉え続ける。強襲は0.39秒で1捕捉、重火力は0.26秒ごとに最大3〜4捕捉。同じ敵への重ね掛けと複数の敵への振り分けに対応。味方・行動不能機・迷彩中の敵・壁の向こうの敵は新しく捕捉できない。成立時は3秒の索敵を共有する。
- 強襲は1捕捉で弾倉分、重火力は1捕捉につき1〜2発を左クリックで連射する。未捕捉なら1組を直進発射。左を離しても開始済みの組は撃ち切るが、持ち替え・修理ポッド・エリア移動・行動不能では未射出分を止める。右クリックは未発射の捕捉だけを解除する。プレイヤーは次の一斉射に再クリックが必要。
- 完了した捕捉は照準から外しても画面内なら維持。遮蔽・画面外は0.5秒、距離外は2秒で解除。頭部の距離倍率は強襲1.25（暫定）、重火力1.5（AC本文の目安）。索敵の距離延長を重ねない。妨害・持ち替えでも解除する。
- `missileFlight` は照準方向から射出した弾を旋回上限の範囲で曲げる。距離で誘導が強まり、重火力は加速する。発射時点の目標を保持するため、後から捕捉しても直進弾に誘導を足さない。発射者の持ち替え・大破後も飛翔し、目標が行動不能・大破・再出撃した時や追い越した時は誘導を終え、再捕捉しない。壁・地形・傘への通常の衝突で爆発し、射程の終わりでは消える。
- 被捕捉は既存の橙の方向警告、飛来中は弾体の方向から赤い警告を出す。直進弾は警告しない。上部に被ロックオン/被発砲の文字は足さない。飛翔弾は小さな噴射光と煙で示す。
- Botも同じ捕捉・時間・視線・発射処理を使う。爆風を自分で浴びる距離では選ばず、捕捉が揃うのを待ち、連射が終わるまで持ち替えない。既存の通常射撃の弾道補正は追加しない。

### よろけ・ダウン・着地硬直（`jolt`、`land`、`physics`。ユーザー指定、数値は wiki PS4版）

| 定数 | 値 | 意味 |
|---|---|---|
| `STAGGER_DMG` / `DOWN_DMG` | 3500 / 7000 | 射撃と爆発で、1回の攻撃のダメージがこれ以上ならよろけ・ダウン（wiki） |
| `STAGGER_MELEE` / `DOWN_MELEE` | 3000 / 6000 | 格闘（ソード）のよろけ・ダウン（wiki） |
| `STAGGER_TIME` / `STAGGER_PUSH` | 0.65秒 / 9 m/s | よろけで操作できない時間（wiki）、押される速さ（約2m） |
| `DOWN_PUSH` / `DOWN_UP` / `DOWN_LIE` | 14 m/s / 12 m/s / 1.2秒 | ダウンで吹き飛ぶ速さ（約10m、0.65秒）、倒れている時間（wikiに秒数なし、仮置き） |
| `UKEMI_COST` | 32 | 受け身のブースト消費（wikiは「大量」とだけ。仮置きの40の8割） |
| `LAND_SPEED` / `LAND_TIME` | 28 m/s / 0.5〜1秒 | これより速く着地すると着地硬直（約12mの落下）、その長さ（速いほど長い。仮置き） |

- 1回の攻撃：散弾と二丁拳銃は1回の射撃で当たった分の合計（`volley`）、爆風は1つずつ、ソードは1振り。弱化グレネードの倍率とヘッドショットを含めた実際のダメージで判定する。撃破したときは起きない。
- よろけ：0.65秒、移動・ダッシュ・ジャンプ・武器が使えず、攻撃の反対（爆心か撃った機体の反対。近接は刃の進む向き、v0.21）へ押される。重砲や偵察機で屈んでいれば押されない（wiki）。続けて当たるとまたよろける。
- ダウン：後ろへ吹き飛んで倒れ、1.2秒たつと起き上がる。重砲などの構えは解ける。ダウン中によろけは起きないが、もう一度ダウンはする。無敵時間はない（wiki）。吹き飛んでいる間に Space と Shift を同時に押すとブーストを32使って受け身を取り、着地したら動ける。Botは4割で受け身を取る。
- 崩れている間は振っているソードも止まる。リペアポッドを使っている間と、カタパルトで操作できない間は崩れない（wiki）。
- 着地硬直：着地したときの落ちる速さが28 m/sを超えると（約12mの落下。普通のジャンプ（約6.8m）と、高台の崖（10m）を降りるだけなら出ない）、その場で屈んで動けない（撃つことはできる）。着地の直前0.3秒以内にSpaceを押すか、滞空で降下を緩めれば出ない（wiki：着地直前のジャンプで消せる）。カタパルトの着地でも出る。Botは6割で消す。
- 見た目：よろけはのけぞり、ダウンは後ろへ倒れる（`tilt`、機体の向きのあとに傾けるため `group.rotation.order = 'YXZ'`）。着地では足裏を残して腰と膝を曲げ、硬直中は屈む。自機は画面中央に状態を出す。
- このため、ソードの横なぎ（6000、格闘のダウン6000以上）は当たるとダウンを取り、ショットガンは近くで当てるとよろけ（ヘッドショットが混じると7000を超えてダウン）、ロケットの直撃・地雷・狙撃銃のヘッドショット（9000）はダウン、狙撃銃の胴体（3600）はよろけになる。

### ダメージ（`fire`、`damage`、`blast`）

- 出撃直後の無敵（2026-10-24ユーザー指定）：何も攻撃しなければ従来どおり最大2秒。武器を実際に発射した瞬間、近接を振り始めた瞬間に無敵を解除し、その攻撃による自爆や同じフレームの被弾も受ける。主・副・補助の発射、通常/ダッシュ近接、光波剣・杭のチャージ解放、重砲・榴弾砲、遠隔爆弾の起爆、背部自動銃の発砲が対象。命中の有無は問わない。クリックだけで攻撃できない弾切れ・リロード・持ち替え・硬直・クールダウン中は解除しない。チャージ・空転・榴弾砲の地点指定だけでは解除せず、実際の発射/振り始めで解除する。移動・ジャンプ・ロック・索敵レーダー・修理・非攻撃SPの起動でも解除しない。プレイヤーとBotは共通の処理を使う。
- ヘッドショット（頭部の形に当たったとき。v0.12から。それまでは機体の足元から3.3mより上）は `HEADSHOT_MULT` 1.3倍（ユーザーの仮置き）。狙撃銃だけ武器の `head` 2.5倍（wikiのクリティカル倍率）。
- ヘッドショットの命中はボディより派手に見せて鳴らす（v0.9.5、ユーザー指定）：着弾は白い芯と大きな金色の光、広がる金色の輪（`ringTex`）、倍の数（16本）の速い火花。撃った本人には照準に金色の×が広がり「HEADSHOT」の文字が出て、命中音の代わりに `headshot`（slash を高く）と `headping`（beep を高く）を重ねて鳴らす（`impact`、`hitMark`）。
- 機体が撃破されると、その陣営のコアが最大値の1/160（`KILL_CORE`、56.25）減る（元のゲームの仕様。ユーザー指定）。50対50では全マップで1/800（`KILL_CORE_LARGE`。ユーザー指定 2026-10-20「速攻で160人死んでゲームセットになっちゃう」「50vs50の時だけね」）。`setup` が人数から今の試合の値（`killCore`）を決める。
- コスト制（v0.10.9、マップの `vs: { cost, death }`。ユーザーが選んだ、港の倉庫街）：`VS` と `coreMax` が立つと、`buildCores` は撃てる物を作らずゲージだけの `cores` を置き、防衛砲台・レーダー（ベースの境目の線も）・傘を作らない。上のゲージは両軍の戦力（`coreMax` = cost）で、撃破1回で death 減る。港の倉庫街はチーム合計10機先取（2026-10-20 ユーザー指定）：cost=20000・death=2000、制限時間5分。0以下で負け、時間切れは残りの多い側の勝ち（コアと同じ判定）。再出撃はいつもベース側の出撃地点で、残りが death より少ないと耐久が 残り/death 倍（コストオーバー）。ベース侵入・ベース防衛・BRAVE（プラントの無いマップ）の加点は無し。Botは気づいている一番近い敵機へ向かい、見えていない間は止まらずに回り込む。
- 近接限定2対2（2026-10-21ユーザー指定）：マップ選択に「港の倉庫街 〜近接限定〜」（`dock-melee`）を別項目で追加する。既存の `dock` の地形・施設・戦力・制限時間を使い、エンジン側で `meleeOnly: true` の派生を作る。出撃前の「近接限定の武器」で、杭を含む全21種類の近接武器から選ぶ。光波剣のチャージ光波も使える（ユーザーの選択）。兵装を問わず補助枠でその武器を持ち、Botも同じ一覧から選ぶ。主武器・副武器・特別装備は持ち替え・使用を禁止し、重量には使う近接武器だけを加える。4枠の構造と通常ルールの装備保存は維持し、限定ルール専用の武器選択はページを開いている間だけ保持する。HUDは使えない枠を薄くし、中央のSPゲージを隠す。Botは射撃・設置・修理の行動をせず、斬れる間合いまで接近する。勝利条件は通常2対2と同じチーム合計10機先取、5分。
- コアでダメージが入るのは上の色の付いた結晶（`core.glow`、中心の高さ19m）だけ。黒い支柱と台座は弾を止めるが無敵（v0.10.6、ユーザー指定）。結晶は横に広い八面体（v0.10.7、ユーザー指定「コアもっと大きく」：横の半径8.5m・縦4.2m）で、支柱（上の半径5m）より外へ張り出すので、傘の下の近くからは張り出した下面を撃つ（中心を狙うと支柱に当たる）。`core.pos` は結晶の中心。攻撃役のBotはコアの前12mに立ち、`coreAim`（中心から自分の方へ水平に6m・1m下の下面）を狙う。
- コアへのダメージは機体への威力の1割（`CORE_RATE`）。ロケットはコアに直撃したときだけ効く。ソードはコアに当たらない（wiki）。
- 爆風は爆心で最大、半径の端で半分。敵機・敵砲台・バリケード・敵の設置物に効く。
- 爆発の見た目（2026-10-26ユーザー指定）：`boom` の単色球を、白熱する短い閃光・複数の膨らむ火球・水平の衝撃波・放射状の火花と軌跡・立ち上る暗い煙へ変更。通常は最長1.3秒、小さい炸裂は1.05秒で消す。従来の表示中心（入力位置+高さ2m）、`k=0.5` の小さい爆発、`explode`/`explodeS` の音を継承し、爆風の威力・半径・遮蔽・視界揺れ条件を変えない。表示の輪は爆風判定の境界ではない。
  - `boomUpdate` は火球・煙・火花の粒・火花の線・衝撃波を共有5バッチへまとめる。同時表示は最大32件で、上限時は遠い/古い演出を優先して置き換える。距離と同じ場所の連続爆発に応じて細粒を減らす。全資源を使い回し、各爆発でGPU形状・材質・テクスチャを作らない。
  - 形と色の揺らぎには独立した視覚用乱数を使い、資源生成も `visualAlloc` で戦闘用乱数から分離。時間から位置・拡大・減衰を求め、更新頻度で軌道を変えない。奥行き判定を保ち、壁越しに透かさない。`clearBooms` が再試合・マップ変更で表示を消す。外部画像を使わずテクスチャを生成する。

### ソードの当たり判定（`swordTick`、`bladeSweep`、`bladeHits`。ユーザー指定）

- 刃は実際に振る。毎フレーム、前のフレームの刃の角度から今の角度までの扇形（中心は機体、半径 `BLADE_IN` 1.4m〜`reach` 4.8m、高さは足元から `height`）を求め、そこにかかった相手（機体は半径1.3m・高さ4m）に1回だけ当たる。
- 横なぎ：前方150度（左75度から右75度）を0.15秒で払う。刃の高さ2.6m。構え0.1秒、振り全体0.5秒。
- 回転斬り：ダッシュ中に振ると、基本の踏み込み設定は前へ16m・0.6秒で、ダッシュの勢いも引き継ぎながら2回転して周りを斬る（1回転だと進路の右側の敵を取りこぼすため）。v0.9.3（ユーザー指定）で基本の踏み込みを11mから16mに伸ばし、ブーストの残りに関係なく出せて消費もなく、踏み込んでいる間はブーストが毎秒50回復する。刃の高さ2.0m。回し終わると基本1秒の硬直があり、その間は移動入力・ジャンプ・通常のダッシュができない（下記の横ダッシュ解除を除く）が、残った勢いで滑る（チャンスも隙も大きい）。
- 踏み込みの速さ（v0.13.1、ユーザー指摘「攻撃方向にスライドして伸びていかない」）：武器由来の目標速度は、出だしが平均の1.35倍、終わりは0.65倍。ダッシュ中の技は振り終わってもピタッと止まらず、`SLIDE_TIME` 0.6秒のあいだ止まり方をゆるくして（`SLIDE_DECEL` 4。普段の地上は10）勢いのまま滑る。横なぎの踏み込みは普段どおり止まる。
- ダッシュ近接の慣性（2026-10-22ユーザー指定「軽量機でダッシュ近接するとスピード落ちちゃう」）：ショート・ロングダッシュから近接へ移るとき、速度を武器の固定速度へ上書きせず、実際の水平速度と進行方向を保持する（`swing.dashAttack`）。踏み込み中も武器の目標速度より速ければ `SLIDE_DECEL` で滑らかに減速・旋回し、遅ければ従来の加速で踏み込む。勢いは速度へ加算し直さず、連続攻撃でも進入速度と武器の最大目標速度を超えて加速しない。軽量機は速さを生かして実移動距離が伸びる。横・後ろへのダッシュは元の方向の勢いを残し、ロック誘導で瞬時に方向転換しない。プレイヤーとBotで共通とし、通常斬り・武器の威力／間合い／時刻／硬直／ブーストの消費と回復・通常移動の数値は変えない。
- ダッシュ近接の硬直解除（2026-10-26ユーザー指定）：最後の振りが終了して硬直に入ってから0.3秒後、現在の機体の向きに対する横方向のクイックブーストで残りの硬直を解除できる。左右と斜め45度までを対象とし、前後・無方向・ジャンプ・歩き・Shiftを押し続けるだけでは解除しない。構え・斬撃・連撃途中と通常近接の硬直は対象外。成功時だけ振りの戻りと滑りを終了し、通常どおりブーストを消費して横へ踏み出す。再攻撃までのクールダウンは維持する。過熱・ブースト切れ、被弾/着地/電撃硬直、ポッド使用・エリア移動・構え・カタパルト操作不能中は解除しない。プレイヤーとBotで共通の `shortDash` を使い、`meleeRecovery` で硬直の元になった振りを追跡する。硬直終了・被弾で攻撃中断・電撃・再出撃/装備更新で追跡を消す。加速装置からの攻撃・チャージ近接にも適用する。
- 加速装置ON中の近接（2026-10-23、ユーザー指定）：加速装置が作動しSPが過熱していない間も、ショート/ロングダッシュと同じく各武器のダッシュ技を選ぶ。ON中は停止していても適用し、OFFやSP過熱後は通常攻撃へ戻す。進入時の水平・鉛直の速度を保ち、既存の踏み込み・慣性・各武器のモーションと威力を使う。近接開始で加速装置をOFFにせず、踏み込み中は既存の処理でSP加速を止める。光波剣・充填近接は従来どおり入力を離すまで振らない。プレイヤーとBotで共通。`charger_melee_check.js` は全近接・全加速装置、ON/OFF/過熱と通常ブースト、慣性、光波、実入力を確認する。
- ロックオン誘導（`meleeHome`。v0.13、ユーザー指定「本家に寄せる」）：振り始めにロック中の敵（Botは狙っている敵）が踏み込みの届く所（`lunge` か `step`＋`reach`＋機体の半径）にいれば、その敵の方へ向かって振る。
  - 横なぎにも踏み込みが付く：敵が刃の6割の所に来るまで、最大 `step`（ソード4m・大剣3m・スピア4m）を振っている間（構え＋振り）に進む。0.3m未満なら踏み込まない。刃と機体の向きはその敵が基準（`aimed`。視点が少しずれていても敵を中心に払う）。
  - 踏み込んでいる間も、その敵の方へ毎秒 `homing` ラジアンまで曲がる（回転斬り・突進突き1.8（大剣1.5）、横なぎ6（大剣5））。目の前（機体2つぶん＋0.6m）まで来たら追うのをやめ、踏み込みの勢いのまま抜けていく（v0.13.1。v0.13 では止まっていた）。敵が横より後ろ（約100度）へ回ったら追わない。横へ逃げても曲がってくるので、回転斬りはジャンプで避ける。値は仮。
  - Botも同じ（狙っている敵へ誘導する）。Botがソードを振り始める距離は変えていない。
- ジャンプで足元が刃より0.3m以上高ければ当たらない。ジャンプ（最高約6.8m）なら回転斬りを避けられる。Botは近くで敵が回転斬りを始めると6割の確率でジャンプして避ける。
- 上下の斬り（v0.21、#14 の Codex の案をユーザーが了承「良いじゃない進めましょ」）：振り始めの照準の点（ロック中はその敵、Botは狙っている点）へ向けて、刃を上下30度（`SWING_TILT`）まで傾ける（`swingTilt`）。刃は機体の中心（高さ `height`）から円すいの面を通り、相手の中心までの距離 d で高さが d×tan(傾き) 変わる（`bladeHits` の `slope`）。振り始めで決まり、振っている間は変わらない。ジャンプ中の敵や高低差のある敵を斬れるが、上げすぎると地上の敵の頭を越えて当たらない。回転斬りはジャンプで避けられるように水平のまま（ユーザー指定）。刃・手・軌跡も同じ傾きで描き、上へ斬るときは胴を反らす。
- 近接の吹き飛ぶ向き（v0.21、ユーザー「ダメージ食らった方向と逆に飛んだら自然に見えるんじゃない？」）：刃が来た向きの逆、つまり当たった所での刃の進む向きへ、少し外向きを混ぜて押す（`swingPushFrom`。接線1に外向き0.6）。横なぎで左から右へ払えば右へ、回転斬りは回る向きへ飛ぶ。突きのように振りの幅が狭いほど外向きだけになる（幅90度以上で接線をすべて、それより狭ければ比例）。射撃は撃った機体の反対、爆風は爆心の反対のまま（どちらも弾が来た向きの逆）。
- 振りの見た目と操作（v0.21 で確かめた）：どの近接武器も、最後の振りが終わってから振り全体（`time`）までで構えに戻り、同じ時に硬直が解けて次を振れる（`tools/test/melee_check.js` が全部の型で確かめる）。大剣の回転斬りだけ、振り0.7秒＋硬直1.3秒が `time` 1.9秒を超えていたので、`time` を2.0秒にした。
- 防衛砲台とバリケードにも当たる。コアには当たらない（wiki）。

### 操作の仕様（ユーザー指定）

- SP残量：照準円のすぐ下に、文字も枠もない黄色い横棒（`#aimSp`）だけを出す（ユーザー指定 2026-10-20「ＳＰゲージは黄色い棒だけでいいよ」）。持っている武器によらず特別装備枠（`slots.sp.heat`、共通0〜100%）を読み、スコープ中も表示する。左下のSP表示は残す。棒の色は左下と同じで、作動中は緑に光って点滅、迷彩被弾時は赤、使い切った後の再充填中（満タンまで使えない）は暗い色。撃破・行動不能中は隠す。画面サイズに合わせて照準円の外側の弧の下へ配置し、中央の操作メッセージもその下へ避ける。
- 武器の持ち替え：マウスのサイドボタン（戻る・進む）を押している間、画面中央に十字の武器選択が出る。マウスを上で主武器、右で副武器、左で補助装備、下で特別装備（2026-10-20 ユーザー指定で補助と特別を入れ替え）、離して決定。ホイール（順送り）と1〜4キーでも持ち替えられる。持ち替えは0.8秒（`SWITCH_TIME`）。リロードは持ち替えても続く。
- 主武器・近接武器の右クリックはロック／解除のトグル。副武器・特別装備の右クリック（スコープ・ミサイル捕捉解除・遠隔起爆・自己修復・砲撃中断）と全体マップの防衛指示を優先し、ロック操作を兼ねない。
- 投げる物（グレネード・弱化グレネード・地雷・センサー）：照準の所へ山なりに投げる。落ちる所に黄色の円（`aimMark`）が出る。届かないときは届く所まで。
- ロケットランチャー強装型（`rocketH`、VR-8H、2026-10-25ユーザー指定）：この型だけ銃口から40mで推進を終了し、噴射炎を止める。その後は初速45m/sからの慣性と下向き加速度24m/s²で落下し、弾体も進行方向を向く。水平射撃の落差は40mで0m、60mで約2.37m、80mで約9.48m。上を狙うと山なりに撃てるが自動補正はしない。威力・爆風・弾数・装填時間・従来の寿命3秒を維持し、プレイヤーとBotで同じ弾道を使う。wiki転記値は変更せず、型生成後の本作調整として適用する。ショットガン速装型は対象外。
- 加速装置：**選んだ時点で作動し、もう一度選ぶと止まる**（左クリック不要。v0.9.5、ユーザー指定）。持っている武器は持ち替えない。作動中はShiftを押し続けると、ロングダッシュの代わりにSPを使って向いている方へ進む（押した瞬間のショートダッシュはいつもどおり）。横の入力で少し曲がる。加速しながら撃てる（ユーザー指定）。SPを使い切ると止まる。SP加速中も通常ブーストは、最後の通常消費から0.5秒待って毎秒50回復し、満タンで通常ブーストの過熱も解除する（2026-10-23ユーザー指定）。SPの消費・再充填と通常巡航の消費は独立。
- 重砲：選ぶと構えて動けない。左クリックで撃つ。撃ち切るか右クリックで元の武器に戻る（SPが1発ぶん無いときも戻る）。
- 光学迷彩：**選んだ時点で姿を消し、もう一度選ぶと解除**（左クリック不要。v0.9.5、ユーザー指定）。持っている武器は持ち替えず、消えている間も使える。
- 光学迷彩・加速装置の作動と停止（`toggleSp`）：1〜4キー、サイドボタンの武器選択、ホイールのどれで選んでもよい。続けて切り替えられるのは0.5秒ごと。リペアポッドの上、よろけ・ダウン中は切り替えられない。ホイールでSPを選んだ次の回しはSPの隣（下へ回せば主武器）へ進む。作動中は、右下の武器一覧の特別装備の名前（「（作動中）」付き）と、左下のSPの文字・SPゲージが緑に光って0.7秒周期で点滅する（v0.9.6、ユーザー指定。`#wpn .act`、`#sp.act`）。
- 偵察機：選ぶと屈んで動けない。左クリックで打ち上げ、元の武器に戻る。
- ソード：止まっているか歩いているときは横なぎ、ダッシュ中（ショートでもロングでも）に左クリックで回転斬り。ロック中の敵がいれば、横なぎでも回転斬りでもその敵へ踏み込み、踏み込み中も追う（v0.13）。
- 狙撃銃：右クリックを押している間スコープ。止まっていると照準が収束する。覗かずに撃つと大きくばらつき（wiki「スコープを覗かずに…とんでもない方向に弾がスッ飛んでいく」）、HUDに「覗かないと大きくばらつく」と出る。
- リペアユニット：左クリックで照準の先の味方機と自軍の防衛砲台・レーダー、右クリックで自分を回復。ゲージを使い切ると満タンまで使えない。リペアポッドの上でも使え、ポッドと効果が重なる（v0.9.3、ユーザー指定。ポッドの上で自分に使うと毎秒約2300）。
- 兵装の選択：出撃前の画面と、撃破後の再出撃画面（Z・X・C・V）。v0.15（ユーザー指摘「不快度高い」）から撃破されてもマウスの固定を外さない。再出撃地点は数字キーかホイール（下で前線寄り）で選び、数え終わると自動で出撃する（クリックは要らない）。Esc などで固定が外れたときだけ「画面をクリックで操作に戻る」と出る。
- キルカメラ（v0.16、ユーザー指定「撃破されたら最初の半分は倒した相手をカメラで映す、後半は今と同じフリーカメラ」）：撃破されると、再出撃までの待ち（5秒）の前半（`KILLCAM` 0.5）は、撃破された場所の側から倒した相手（機体か防衛砲台）を12m離れて少し上から映す（`KC_DIST`、間に壁や地面があればその手前。相手は画面の上の方、`KC_LOOK`）。その間、再出撃の画面は下の端へ寄せ、一番上に相手の名前・兵装・残り耐久・距離と再出撃までの秒を出す（`#killcam`）。後半はそれまでと同じく自分の周りを見回すカメラで、倒した相手の方を向いて始まる。自爆では映さない。
- 撃破武器（2026-10-21ユーザー指定）：キルカメラの相手名の下に「撃破武器：武器名」を型名まで表示する（`#killcamWeapon`）。銃・砲弾・近接斬撃・光波・爆撃・設置武器・残留する熱や連鎖爆発には、攻撃を作った時点の名前を渡す。相手が持ち替え・再出撃してもその攻撃の名前を維持し、行動不能から大破まで保持する。自機の再出撃・蘇生で前の記録を消す。固定砲台は「防衛砲台」、原因の名前を渡さない特殊な呼び出しは「不明な攻撃」。幅700px以下または高さ540px以下ではキルカメラ中の再出撃パネルを画面幅に広げ、兵装選択を2列にして名前と武器を収める。威力や当たり判定は変えない。
- M で全体マップ（v0.15）：ミニマップと同じ物（地形・障害物・プラント・ベース・砲台・レーダー・ポッド・カタパルトの向き・味方と見えている敵・自機の向き）を画面の高さの8割で出す。もう一度 M で閉じる。地形はミニマップの3倍の細かさで、マップを替えると作り直す（`bigBg`）。v0.17 から、開いている間はマウスでマップの上のカーソル（自機の所から始まる）が動き、左クリックで「ここへ向かえ」、右クリックで「ここを守れ」をその地点に送る（視点は動かず撃てない。マウスの固定が外れているときはマップを直接クリック）。
- G 長押しで指示出し、H でエリア移動、行動不能の間は F ですぐ大破（v0.17。「指示出し・蘇生・エリア移動」の節）。

### マップ（`MAPS`、`buildMap`。v0.10でマップ選択を追加、v0.10.1でマップのデータを別ファイルに。ユーザー指定）

- マップのデータは `prototype/maps/<id>.js`（1ファイル1マップ）にあり、`python3 tools/build_maps.py` が中身を確かめて `maps.js` にまとめる。index.html は `maps.js` の `window.MAP_DATA` を読み、項目がそろったマップだけを `MAPS` に `order` 順で並べる（足りないマップは警告を出して外す。1つも無ければ「maps.js が読めない」と出して止まる）。
- **項目・座標・点対称・地形の種類の書き方、今あるマップ（台地演習場・広域演習場）の詳細、確かめ方は `prototype/maps/README.md`（配布zipでは `MAPS.md`）**。マップはマップ製作のスレッドが持ち、エンジン（index.html）は「ボーダーブレイクPC再現」スレッドが持つ。公開ページの `maps.js` はマップ製作のスレッドが出し、エンジン側の公開では `maps.js` を送らない（`prototype/maps/` には作りかけのマップがあり得るため）。配布zipは公開中の `maps.js` を取ってきて `python3 tools/build_zip.py <版> --maps <そのファイル>` で作る。
- 選んだマップは `localStorage` の `coreBreakerMap` に残り、次に開いたときもそのマップで始まる。無くなったマップIDなら最初のマップになる。
- 任意の項目（v0.10.3、マップ製作スレッドの依頼で「丘の市街地」のために足した。書き方の詳細は maps/README.md）：
  - `subtitle`：副題。マップ選択の名前が「名前 〜副題〜」になる。
  - `variants: { キー: { name, plants, plantPods, catapults, … } }`：配置違い。地形と `layout` は元のまま、書いた項目だけ上書きした版を、ID `マップID-キー`・名前「名前 〜name〜」・`order` は元の直後で `MAPS` に並べる。マップ選択では、配置違いのあるマップを1行にまとめて折りたたむ（v0.21、ユーザー「折りたためるようならんかな」）：見出しは元の名前、全部の配置に共通する説明、プラントの数の幅（選んでいれば選んだ配置の値と「選択中：配置の名前」）。クリックで開くと配置ごと（名前は副題か `variants` の name。副題が無い元のマップは「基本」）のカードが並び、そこで選ぶ。開いた状態はページを開いている間だけ覚える（`mapGroupsOpen`）。`MAPS` の元と版には `group`・`groupName`・`variant` を付ける。
  - `layout` の6番目の要素：建物の種類 `'house'`（切妻屋根・窓。壁と屋根の色は自軍側の座標のハッシュで決まり、点対称の建物は同じ色）、`'wall'`（石壁）、`'tower'`（石の塔、細い窓と胸壁）。当たり判定は箱のまま、屋根と胸壁は見た目だけ。模様は3m（`CELL`）ごとに繰り返す（`tileUV`）。屋根は色ごとに1つのメッシュにまとめる。
  - `bridges: [[x, z, 幅, 奥行き, 上面の高さ, 厚さ], …]`：layout と同じく中心と大きさで、点対称に足す。上面の高さは海抜。地面に埋めず、上面から厚さぶんの板にする。障害物に `bottom`（上面 − 厚さ）を持たせ、`resolve` は頭が `bottom` より下ならくぐれるとして押し出さない。`groundAt` で床に立てる。下でジャンプすると `ceilingAt` で頭が床の底に当たって止まる。カメラも床の下に収める。弾と視線は床に当たる。
  - `water: [[x, z, 横の半分, 奥行きの半分, 高さ], …]`：半透明の水面。見た目だけ（当たり判定なし）。ミニマップと見取り図では青。
  - `nav: { nodes: [[x, z] または [x, z, y], …], links: [[i, j], …] }`：Botの通り道。自軍側の半分を書き、点対称に足す（`'~3'` は3番の点対称の節点、原点の節点は1つ）。節点の3番目 y は歩く高さ（海抜）で、橋の床の上の節点に書く（省くと地面の高さ）。Botは目標までまっすぐ歩けない（`clearPath`：登れない段差と障害物の箱を0.5mごと〔v0.10.9 まで2mごとで短い急な崖を見落としていた〕に見る。歩いて乗れる橋の床は地面に数え、箱はその区間の足元より0.6m以上高い時だけ塞ぐので、上を歩く橋の下の橋脚は普通の箱でよい。v0.10.4）と、自分から見通せる近い節点と、目標を見通せる近い節点（どちらも近い順に6個まで調べる）を結ぶ最短路（ダイクストラ法）をたどる。リンクの長さには機体ごとの1〜1.4倍のばらつき（`navW`）を出撃ごとに掛け、迂回路も使う。節点に5m以内で着いたら次へ、次の節点が見通せて近ければ飛ばし、目標が見通せたら残りを飛ばす。5秒ごとか目標が15m動いたら引き直す。v0.10.9（ユーザー指摘の崖づまり）：通り道に入る節点は `navEntry` が選び、近くの節点へまっすぐ歩けなければ周り（8・16・28m、12方向）の経由点 `navVia` を先に通る。向かう節点へ歩けなくなったら（0.5秒ごとに確かめる）と、詰まって横へ逃げた後は引き直す。nav の無いマップでは目標（120m以内）へまっすぐ歩けないときだけ `detour` が同じように経由点を探す。
- `stepTo` は1回に0.5mずつ進める（v0.10.3）。ショートダッシュやカタパルトの速さだと1コマで2m以上進み、厚さ2mの壁を通り抜けていた。
- Bot：10機の兵装は `BOT_CLASS`（強襲3・重火力3・遊撃2・支援2）、役割は `BOT_ROLE`（攻め4・プラント4・守り2）。プラント役は、プラントが4つ以上あるマップでは、まだ自軍のものでないプラントのうち自軍ベースに近い1つ目と2つ目に分かれて向かう。通常のマップデータは1陣営10機まで。全マップの人数選択では、兵装・役割の10機ぶんの並びを人数まで繰り返す。

#### 共通

- 高さは |z| が `baseLine` から25mの間で0に近づき、ベースの周りは平ら。
- 高さはマップを作るときに1m格子へ焼き（`bakeTerrain` → `heights`）、`terrainH(x, z)` が補間して返す。地面のメッシュは2m格子。
- 移動：`physics` は水平移動を `stepTo` で1軸ずつ試し、動いた距離の1.1倍より地面が高くなる所（約48°より急な斜面）へは進めない。下り坂では、接地していて落ちる速さがなければ地面に沿って歩く。
- 弾と視線：`terrainHit` がレイに沿って1.5mずつ進み、地面の下に入ったら二分探索で交点を詰める。丘や盛り土の向こうは撃てず、見えない。
- 施設・出撃地点・砲台の照準・砲弾の着地判定は `terrainH` を使う。プラントの範囲は水平16m以内かつプラントの地面から6m以内。

### 昇降設備（オーナーの了承：2026-10-19、#8 で追加）

- `jumpPads` は `[x,z,y]` の `at`、基準面からの理論上の上昇高 `rise`、起動半径 `radius`（既定3m）、Botの着地先 `exit` を持つ。接地した機体を垂直に射出し、水平速度は0、鉛直初速は `sqrt(2*GRAV*rise)`。その後の移動・衝突・着地は通常の `physics` を使う。ブースト消費や壁抜けによる移動補助は加えない。
- `lifts` は `from`・`to`（`[x,z,y]`）、床の `size`、速度 `speed`（既定5m/s）、端で待つ `wait`（既定2秒）を持つ往復床。ループの機体更新前に床と接地中の乗員を同じ差分で移動する。床は既存の障害物・橋の床としても扱い、弾・頭上・歩行の判定を共有する。乗員の経路が塞がる場合と、床が別の機体を押し潰す場合は停止し、空けば再開する。
- 両施設は中立で、プレイヤーとBot、両陣営が同じ接触判定と移動ルールを使う。ジャンプパッドは空中操作、リフトは歩く・ジャンプで離脱できる。HUDとミニマップに種類と状態を表示する。
- Botは通常ジャンプで届かない高い目標へ接続する設備を選ぶ。パッドの射出中は十分な高さに上がってから着地先へ向かい、リフトは到着まで乗り、乗り場が空いていなければ横で待つ。索敵や射撃の情報を増やさない。項目が無い既存マップの判断は変えない。
- `asym` の展開は橋と同じ。再試合ではリフトを始点に戻し、マップ切替では設備を廃棄して作り直す。試験場は `mobility`（`testOnly: true` なのでプレイヤーのマップ選択には出さない。試験からは `selectMap` で選べる）。白煙循環区の配置は従来の検証条件を保つ。
- 概要の出典：[公式の施設紹介](https://borderbreak.com/game/intro/facility/)。速度・停止時間・寸法・モデルは本作独自の仮置き。公式の画像・モデルは同梱しない。
- ジップライン（v0.21、ユーザー指定「欲しいのはapexのジップライン設備なんだよな USEで上にシャーって」。リフトは「タイマーで上がり下がりする床」として残す）：`ziplines: [{ from, to }]`（`[x,z,y]`。低い方が下の乗り場、高い方が上の端）。下の柱（足元に光る輪）と上の柱の間に、機体の頭の上（`ZIP_HAND` 4.4m）の高さで綱を張る。綱の近く（足元から綱の線まで `ZIP_REACH` 3m 以内、上の端の近く1割を除く）で E を押すと掴み（`zipGrab`）、`ZIP_CATCH` 0.2秒で綱へ寄りながら `ZIP_SPEED` 16m/秒で昇る（`zipRide`）。上に着くと、上の端から綱の向き（水平の向き。綱が真上なら機体の向き）へ足場の始まりを探し、その2m奥の降り場（`zipLanding`）まで押し出して降ろす。途中で Space か E を押すと手を離して少し跳ね、よろけ・ダウン・電撃を受けると落ちる（`zipDrop`）。離したあと `ZIP_CD` 0.6秒は掴めない。昇る間は銃を撃てるが、近接・重砲などの構える物・榴弾砲とダッシュは使えず、ブーストは回復する。Botも同じ決まりで、高い目標へ行くときにジャンプパッド・リフトと並べて選び、下の乗り場の近くで掴む（途中では離さない）。中立で両陣営が使え、ミニマップには線と下の乗り場の丸で出す。数値は本作独自の仮置き。白煙循環区は、リフトの3か所をジップラインに替える（マップのデータはマップ製作のスレッドが出す）。試験は `tools/test/zipline_check.js`。

### 自動生成マップ（Issue #1、段階1〜5）

- 決めたこと（#8 のマージ、2026-10-20）：今の生成器は、決まった障害物の並びを少し動かして地形を作る。`docs/codex/mapgen.md` STEP1 の「地形そのものを作る」生成は後の PR で行う。対戦の記録・リプレイ・動画などの生成物はリポジトリに入れず、作り直す手順と小さな要約だけを置く（#8 の全記録はブランチ `codex/1-mapgen` の 38b1798 に残る）。

- `tools/generate_map.js --seed N` が、熱交換施設を題材にした非対称の地形と、同じ地形を使う3つ以上の配置を生成する。地形と配置は別のシードで再現し、施設候補・初動距離の一次検査・戦術的な配置差・各配置の通り道を確認する。
- `--theme tidal` は工業港の生成テーマ（`tools/tidal_mapgen.js`）。既定の `tidal7` は10対10・600秒、370×1136m。採用された長方形を縦へ延長し、高架上下・倉庫・沿岸路・展望台から3配置を生成する。青の常設基地前には工場街、橙の野戦拠点前には住宅地を置く。正面ゲートへの通路に加え、建物間・連絡橋下・坂やパッドから上る屋根を侵入路にする。基地は異なる建材・高さ・配置で作る。橙基地の陸側には14mの山と、8mの側壁を越える10mの足場・基地内の下り坂を設ける。指定した正の地形の `keepBaseHeight` だけ基地の平坦化後も高さを残す。`tidal_mountain_check.js` は軽量・重量機の徒歩往復と射出台の基礎を検査する。侵入経路の任意の `pointRadius` を小さくした陣営は、狭い足場の角を飛ばさず、各経由点の高さと半径を満たしてから進む。省略した経路は従来どおり。中央高架は20mの斜め1本とし、両端の坂と2基のリフトを接続する。B–C間は地上14m壁・橋上塔・積み荷で射線を分割する。既存の矩形床を2m間隔で並べ、表示と衝突を一致させる。`tidal_frontline_check.js` は視認と実弾・遮蔽両脇・倉庫屋根と橋の間の徒歩往復を検査する。A–B間に6群、C–E間に8群の段積みコンテナを追加し、地上の接近路を分ける。`tidal_approach_check.js` は実弾・迂回路・地上標本への視認、`tidal_respawn_band_check.js` は出撃乱数の範囲端まで本体の出撃処理で検査する。`tidal6` は段積みコンテナの追加前、`tidal5` は斜め高架・B–C遮蔽の追加前、`tidal4` は山の追加前、`tidal3` は街区追加前、`tidal1` は基地拡張前の710m版。実走目標は高さも照合し、橋上では下の地面でなく足元の面の傾斜を測る。`tidal_check.js` は両軍の再出撃域と単独Botの占拠、`base_defense_check.js` は索敵から帰還・情報失効、`tidal_raid_check.js` は4種類の単独侵入とレーダー攻略、`tidal_district_check.js` は街路・門・屋根の射線と屋上からの補給点の露出を検査する。交戦下の結果・限界は `mapdesign/tidal/` に記録する。
- `asym: true` の場合は `terrain`・`layout`・`bridges`・`water`・`barricades`・`nav` を全域で指定する。自動の点対称展開を行わず、nav の参照は通常の節点番号だけを使う。ベースの砲台・レーダー・ポッド・カタパルトは従来どおり自軍側の座標を両軍へ展開する。この項目が無い既存マップの地形・施設・Bot 判断は変えない。
- 通行検査には本体の `terrainH`・`clearPath` を使う。歩ける到達高さも確かめ、同じ平面座標の上下階を別の節点にする。軽量機・重装機の実際の `physics` で主要経路を往復し、既存の施設検査で両陣営の隠れたポッドと nav を検査してから保存する。失敗時は上限付きで別の地形シードを試し、理由を保存する。既存の手書きマップは上書きしない。

- 機体：右手 `gun` に今の銃、二丁の武器は左手 `gun2` にも。近接を選ぶと銃を隠し、`blade` を右手、二刀は `blade2` を左手に構える。選んでいない近接武器は背中へ納める。加速装置・光学迷彩・リペアフィールドは背中 `pack`。重砲は背中に畳み、選ぶと0.65秒（`CANNON_DEPLOY`）で右肩へ起こす（`cannonDeploy`。基部 `mount` は背中に残る）。
- 銃口（`muzzle`）は持っている形の先端。重砲は起こした砲身の先（`CANNON_TIP`）。
- 銃口は胴の半径（1.3m）より1.4〜3.25m前にあるので、`muzzleClamp` が胴の中心（銃口と同じ高さ）から銃口までを調べ、地面・壁・ほかの機体に当たったらその5cm手前を銃口にする（v0.20。それまでは壁に張り付くと壁越しに撃てた）。Botの照準の追従（`trackAim`）は弾を出さないので戻さない。
- 主武器は実際に発射したときだけ白い芯と前方へ噴く発砲炎を出す（ユーザー指定、2026-10-20）。実弾は橙、光学は青緑。連射・3点射・散弾・二丁・充填後の光弾にも同じ `shot` から出し、散弾は粒ごとに増やさず1射につき銃口ごとに1つ。寿命0.08秒（散弾0.1秒）で縮んで消え、移動・構え・反動と壁際の補正済み銃口に追従する。手描きCanvasの共有テクスチャと6三角形の共有メッシュを使い、各銃口の材質とメッシュを再利用。光源・当たり判定は追加しない。持ち替え・撃破では表示を止め、試合/マップ切替では機体と一緒に材質を廃棄する。プレイヤーとBot共通。
- 武器の形も当たり判定に入る（隠れている形は `castFrom` が飛ばす）。肩に起こした重砲に当たってもヘッドショットにならない。
- 投げる物は飛んでいる間も置いた後も武器の形（チームの色を半分混ぜた `toolMat`）。自動砲台は1.5倍（`SENTRY_SCALE`）で、砲身の先から撃ち、砲身の高さ（地面から1m）から見る。偵察機も形を1.4倍で使う。

レールライフルは上下のレール、パルスバーストライフルは3本の放熱板、コイル機関砲は環状のコイルで見分けられる。いずれも箱と円柱によるオリジナルの形で、型ごとの差し色も従来どおり。

### 光波剣（ユーザー指定、2026-10-20）

強襲の補助装備にLJ-6「光波剣」1型を追加する（`waveSword`、ルミナ技研）。数値の原典は今回のオーナー依頼で、wikiから追加する武器とは分ける。

- 直接の斬撃は通常3000、ダッシュ中の回転斬り6000（オーナーの最新指定）。重量230kg・間合い4.8m・攻撃時刻・踏み込み等は標準ソードを継承する。
- 左長押し1.2秒で満充填し、離すと振る。早く離せば斬撃のみ。満充填では振りの中間で威力2000の光波を1発だけ出す。充填保持の制限とSP消費はなく、既存ソードの初期装備は変えない。
- `chargeWave` は光波の威力・弾速・射程・幅を持つ任意項目。弾速70m/s、射程60m、幅1.8mは本作の調整値。光波は離した瞬間の照準方向へ直進し、追加の誘導・頭部倍率・爆風・貫通はない。近距離では斬撃と光波がそれぞれ命中する。
- 光波は既存の `shells` で管理し、専用の分岐だけで幅内5本と横方向の遮蔽を調べる。最初の機体・地形・壁・傘・バリアで消え、コアには損傷を与えない。部位装甲・バリアには通常の射撃ルールを使う。再試合・マップ切替で他の弾と一緒に片付ける。
- 持ち替え・ポッド・被弾硬直・電撃・エリア移動・撃破で充填を取り消し、発射前に硬直を受けた振りの光波も中止する。満充填を保持しても、入力を離すまで勝手に発射しない。
- 専用の導光レール形状、充填中の発光、HUDの充填%/準備完了、比較の光波威力/射程を表示する。Botも満充填と照準を待って離し、中距離で光波を使う。

### 機体の関節と動作（2026-10-20、ユーザー指定）

- `makeMechRig` に腰・胸・頭と左右の股関節/膝/足首、肩/肘/手首を持つ。`limbPose` は手足を届く位置へ曲げ、`skinMech` が部位の頂点と法線を更新する。装甲は引き続き4メッシュで、動いた同じ形を射撃のレイが判定する。関節10個は六角の軸受として部位内へ統合する。元の装甲の描画予算に、軸受240三角形と分割フレーム/掌48三角形、ブーツと膝側の分割面（最大10箱分）を加える。全混成機の実測最大は80箱相当・2880頂点。元の1.5倍を超える分は、10対10の処理負荷の回復を条件にレビューで採用する。
- `mechPose` の歩行周期は機体の実移動距離から進め、前後・横移動で足の運びを変える。壁際で進めない間、空中、ダッシュ、硬直、死亡中は歩行周期を進めない。停止時は歩幅を戻し、空中/ダッシュは脚を畳む。
- `land` は硬直しない着地にも見た目用の衝撃を記録し、腰を沈めて戻す。硬直・重砲等の構え・エリア移動待機は腰を0.6m、ポッド使用中は0.15m下げる。着地や近接の沈み込みが重なった時の合計は0.64mまでとする。脛の装甲は元の高さ0.95mで分け、ブーツ側を足首に残し、膝側を脛へ追従させる。直立時の外形は保ち、脚メッシュの実頂点の最下点を検査する。歩幅に応じた腰下げで接地脚の伸び切りも抑える。モデル全体を地面へ沈める処理は廃止する。操作・落下・硬直・ブーストの数値は従来どおり。
- 銃は通常の両手持ち、大型銃の低い構え、狙撃銃の高い構え、二丁の左右持ちを作り分ける。手を銃の握り位置へ合わせ、背部装備も胸に追従する。`muzzle` は同じメッシュの位置と回転を使い、屈みを二重に引かない。照準への補正は足さない。
- `bladePose` は構え→予備動作→攻撃→振り抜き→戻しを作る。通常剣/大剣は腰をひねって薙ぎ、特殊の回転斬りは従来の回転角へ機体を向ける。槍/杭は腕を引いて突き、細剣は各段、短刀/爪は各手の段を動かす。近接中は足を前後に開く。柄を手に固定し、待機中の刃は#13の元の寸法、格納時はその寸法以下とし、攻撃中だけ間合いへ伸ばす。この関節導入時点では攻撃の角度・高さ・時刻・段数・威力・誘導・踏み込み・硬直の定義は変更しない。後続の専用ダッシュ技は次節の指定を適用する。
- `equip` と蘇生で動作の蓄積を初期化する。プレビューも同じ構えを使い、見えている形の範囲からカメラを合わせる（長い槍や大剣も枠内へ収める）。二刀のプレビューは本戦の `hittables` へ追加しない。
- 参考動画のURL・確認区間・採用点・採用しない性能値は `research/animation/README.md`。公式の映像・モデル・モーションデータは取り込まず、動きはコードで作る。ダッシュ斬り・吹き飛び等の追加提案は [#14](https://github.com/chevi0t/core-breaker/issues/14) でClaude/オーナーへ共有する。
- 関節の逆運動学は親の座標内で解き、作業用ベクトル/回転を共有する。変わった骨の頂点だけ更新し、頭は剛体行列で動かす。骨は回転と移動だけなので法線にも同じ回転を使う。外接球は関節の届く範囲を包含する固定球とし、毎フレーム全頂点を走査しない。非表示機と試合停止中は本戦の構え/スキン処理を省く。装備変更・再出撃・カスタマイズ時の明示的な初期化は行う。
- レビューで採用した挙動：両腕を前へ出すため通常銃の正面被弾が胴から腕へ寄る（レビュー時の計測では胴41→30%、腕20→31%）。格納した近接は通常時の被弾面を小さくする。動いた腕/武器に当たる投擲物の反射もゲームプレイへ影響し、胴へ投げた連鎖ボムが敵から離れる場合がある。地面を狙う動作確認とは分け、これらを構えに伴う変更として採用する。壁越し射撃の既存不具合はオーナーがマージ後に別途直す。

### ブースターの噴流（2026-10-26）

- 単一の水色の円錐を、背部ノズルに沿った左右の青い外炎・白熱した芯・点火リングに置き換える。1機1メッシュ・864三角形、全機で形状を共有し、材質は機体破棄時に解放する。素材はコードで生成し、追加画像や音源はない。

- 自機は距離で省略しない。他機は180m以上で点火リングと長さの小刻みな揺らぎを省略し、350m以遠では噴流を隠す。継続噴射でオブジェクトや粒子を増やさず、戦闘の乱数を消費しない。既存の音・移動・消費・カメラは維持する。
- `booster_visual_check.js` で実移動との同期、モード差、連続点火、停止・死亡・再出撃、迷彩、壁の遮蔽、資源共有と解放を確認する。生成した `model.json` を `tools/booster_preview.py` に渡すと、本体の更新処理を使う確認画面を作れる。

### 機体パーツと重量（`PARTS`、`mechStats`。v0.12、Codex 版から）

- 頭・胴・腕・脚をそれぞれ6シリーズ×Ⅰ・Ⅱ・Ⅲの18型から選ぶ（全部位で72パーツ）（機体カスタマイズの「機体」タブ）。4つの兵装で共通で、`localStorage` の `coreBreakerMech` に残り、次の試合から使う。重量・装甲・脚の速さ・重量耐性は wiki PS4版の各部位の最初の型の強化前（軽量＝シュライクⅠ、標準＝クーガーⅠ、重装＝ヘヴィガードⅠ）。頭のロック距離と射撃補正、胴のブーストとSP、腕の反動吸収と携行弾数は Codex 版の補正。名前と形はオリジナル。
- Ⅱ・Ⅲ型（#3）：`PART_VARIANTS` にACの「採用型÷Ⅰ型」の比を持ち、本作のⅠ型に掛けて `PARTS` へ足す。頭・胴・腕・脚の各部位に6型追加。重量と重量耐性は整数、ロック距離とブーストは小数1桁、歩行とダッシュは2桁、倍率は4桁に丸める。出典・採用理由・Ⅰ型の版の差は `research/parts/types/README.md`、全性能と重量超過例は `game-stats.md`。SP回復性能の基準値と巡航はAC表に項目がなく本作Ⅰ型を継承し、加速時間やSP供給率を代入しない。元のⅠ型は変更しない。
- 保存データ：従来の `light`・`standard`・`heavy` を保持し、新型は `light2`・`light3` 等。`normMech` は各部位の `PARTS` に実在するキーを受け付け、不明なキーは標準Ⅰへ戻す。既存の機体・構成の保存形式は同じ。形とセットボーナスは型を問わずシリーズで決まる。
- 頭：ロック距離（60・50・40m。索敵を受けた敵は `SPOT_LOCK` 倍）、射撃補正（ばらつきを `aim` で割る）。胴：ブースト容量（120・100・80）、SP回復性能（80・100・120を100で割り、重装の追加供給1.1倍を掛ける＝0.8・1・1.32倍。SP残量は全胴100%）。腕：リロード時間（0.91・1・1.18倍）、持ち替え（`SWITCH_TIME` 0.8秒÷`swap`）、反動吸収、主武器・副武器の携行弾数（0.75・1・1.25倍、装填ぶんを含む）。脚：歩行・ダッシュ・巡航（wiki の m/s を、標準型がこれまでの `WALK`・`BURST`・`DASH` になる比で換える）、重量耐性（3700・4650・6450kg）。
- 重量：4部位と4つの武器（`WEAPON_KG`、wiki の強化前）の合計が脚の重量耐性を超えると、40kgごとに1%遅くなる（wiki「移動速度と重量超過」。上限100%、速さには下限）。初期装備・ハウンドⅠの4部位セットでは重量耐性が4800kg（セット+150kg込み）。強襲4340kg・遊撃4630kgは超えず、重火力5430kgは630kg超過で約0.84倍、支援4900kgは100kg超過で約0.98倍。
- 射撃反動（ユーザー指定、2026-10-20）：主武器100種に縦・横反動を設定する。マグナムは単発の強い跳ね、ガトリングは連射中の縦横の暴れを出す。撃ち止めて0.1秒後から縦横とも0.06rad/秒で戻る。腕部の反動吸収で縦横の加算角を割り、上限は縦0.24rad・横±0.14radを同じ倍率で割る。副武器など未設定の物は従来の縦反動（毎秒0.04、上限0.08÷反動吸収）を維持する。持ち替え直後に残った反動を小さい上限へ切り詰めない。
- 主武器の反動値は `PRIMARY_RECOIL_DEG` から度→ラジアンで設定し、AC表の実数44種を採用。マグナム基本型2.75°/±0.60°は実数不明のため本作調整。表に無い型は系統の基準と既存の反動比から暫定設定する。威力・連射・精度・重量などは維持する。対応と不明値は `research/weapons/primary-recoil.json`、実射の比較は `media/primary-recoil/`。
- 縦横の反動は銃の構え・カメラ・実際の弾道へ反映する。プレイヤーの視点へ既に含まれる角を差し引いて二重加算を防ぎ、同じフレームの連射でも次弾に加算する。ロックの引き戻しは縦横とも反動を含んだ実際の照準を基準に、既存の毎秒0.8radの範囲で敵機へ寄せる（2026-10-21ユーザー指定）。マウスで敵へ戻した照準を、反動を除いた角度の判定で押し戻さない。発射時の跳ね上がりと反動の回復は維持し、相手のショートダッシュ中は従来どおり引き戻さない。Botも同じ反動・回復を使い、狙点から1.2m以上外れる反動が残る間は主武器を撃ち止める（進行中の3点射は完了、溜め武器は従来の判断）。カスタマイズで縦・横の反動を比較できる。
- 塗装（`PAINTS`）：チームの色と5色。チームの色以外に塗っても細い帯にチームの色が残る。Botはいつもチームの色。
- Botの機体（`botMech`）：試合ごとに頭・胴・腕は各部位の全18型からランダム、脚はその兵装の初期装備で重量超過が300kg以下になる全型からランダム（無ければ重量耐性が最大の型）。
- 画面は v0.13 の3列（「シリーズと型、メーカー」の節）。兵装のボタンには重量超過を出す（`overNote`）。

### 機体・装備設定の保存と復元（2026-10-26ユーザー指定）

- 機体設定がいつの間にか初期化されるという報告への対応。Cookieへの置き換えではなく、既存のlocalStorage保存を強化する。通常の再読み込み/ブラウザ再起動での消失は公開版のChromium試験では再現せず、実際の報告の原因は未確定。旧版で機体キーだけの書き込みを失敗させると、構成キーに正しい機体が残っていても再読み込みで初期機体へ戻ることを確認した。
- `coreBreakerBuilds`を正本にし、`{format:'core-breaker-settings',version:2,revision,savedAt,cur,list:[{mech,loadout}×3]}`を1回の書き込みで保存、直後の読み戻しで確認する。`mechCfg`と4兵装の`loadout`を別々のキーから組み立て直さない。旧形式の場合はこれまでの機体/装備/3構成を読み、初回の変更からv2へ移す。互換の`coreBreakerMech`・`coreBreakerLoadout`は保存成功後に写すが、v2起動時は正本を優先する。
- 直前の正常な保存を`coreBreakerBuildsBackup`に置く。正本が壊れた場合はバックアップから読み込み、画面で知らせて再保存できる。読み込みだけでは破損した正本を上書きしない。旧形式の機体/装備キーと、完全な構成スナップショットが食い違っている場合は両方を残し、構成側を「前の保存に戻す」で選べるようにする。復元は現在の保存と入れ替えるので、復元自体も取り消せる。
- カスタマイズ画面に保存状態を表示する。保存禁止や容量不足の時は「保存済み」と表示せず、画面内の設定を保ち、再試行とファイル書き出しを案内する。バックアップの保存に失敗しても正本の書き込みは試みる。
- 別タブの`storage`通知で更新を反映し、遅れて届く通知はその値で巻き戻さず保存先の最新レコードを読み直す。同期前に古いタブから操作された場合は、前回把握していた設定との差分だけを最新の3構成へ統合する。同じ項目は後の操作を優先し、変更していない項目を古い初期値で戻さない。旧版のタブは`revision`を更新しないため中身も比較する。未保存の設定がある場合は自動で捨てず、再試行時に統合する。
- 「設定を書き出す」で、保存できない場合も含めた画面上の3構成と現在構成をJSONへ保存できる。「設定を読み込む」は本作形式・3構成・部位/兵装の既知キーを検査し、適用前に不正な入力を拒否する。現行の武器や機体の性能は変えない。書き出しファイルにはパイロット画像・名前・音量などを含めない。
- ブラウザの保存データ自体が消去された場合、閉じた画面の設定を自動で取り戻す保証はできない。書き出したファイルがブラウザ/端末間の保管・移動手段になる。サーバーへの設定送信やCookieは追加しない。

### シリーズと型、メーカー（`SERIES`、`PART_SERIES`、`MAKERS`。v0.13、ユーザー決定）

方針は Claude Doc「武器・機体のバリエーションとカスタマイズ画面の方針（たたき台）」（ユーザーが「基本おすすめ通り、セットボーナスは欲しい」と決めた）。

- 2段：撃ち方・形・働きが同じ物のまとまりが「シリーズ」、その中の数値違いが「型」。型の違いは数値だけで、新しい仕組みは足さない。
- 武器（`SERIES`）：`{ maker, types: [[武器のキー, 型番], ...] }`。型番はオリジナル（例 SR-7、LC-3D）で、名前は「型番＋武器の名前」。v0.13 の48種は1種1シリーズ、特別装備の同じ仕組みの物（加速装置・重砲・光学迷彩・リペアユニット）だけ1シリーズに型が2〜3つだった。大剣（`blade`）はソード系の上位の型（SE-9「ソード・大剣」。v0.13.1、ユーザー指定）。`se.cat` は武器の名前の「・」の前、`label` は後ろ。v0.14で wiki の各系統の型と Codex 版の主武器の系統を足した（次の節）。
- パーツ（`PART_SERIES`）：`{ maker, name, desc, types: [PARTS の型のキー], set }`。スウィフト・ハウンド・ブルワークに、ハリアー・プリズム・バスティオンを加えた6シリーズで、それぞれⅠ・Ⅱ・Ⅲ型（`PARTS[部位][型].series` / `model` / `label` が起動時に入る）。形は各部位の `series` で選び、追加3系統は低い襟と前傾の膝、三眼と段状パネル、厚い胸と荷重支柱で作り分ける。スウィフトは細い脚・斜めの薄い装甲と小さい頭、ハウンドは釣り合いの取れた胸と角形の頭、ブルワークは厚い胸・脚の装甲と肩の盾を持つ。混成機も同じ接続位置を使う。装甲は部位ごとに1メッシュ、頭部は高さ3.2〜3.95mに収め、武器の取付位置は共通。性能とセットボーナスの値は形から独立している。
- メーカー（`MAKERS`）：架空の5社（シルフ精機＝軽く速射の効く銃と刃物、ガルド重工＝重く頑丈な実弾兵器、ルミナ技研＝エネルギー兵器と高出力の装置、ボルカ火工＝爆発物と設置物、アイリス電子＝索敵・迷彩・修理の電子装備）。名前と割り当ては Claude の案。
- セットボーナス（`setBonus`、`mechStats`）：頭・胴・腕・脚が同じシリーズなら（型は問わない）、そのシリーズの `set = { text, fx: [[部位, 項目, 'mul' か 'add', 値], ...] }` をパーツの数値に掛けてから重量・速さを求める。本家はアーケード版だけにあり、PS4版はシリーズごとのチップに置き換えた（`research/parts/setbonus.md`）。値はアーケード版 wiki のブランドごとの表（https://w.atwiki.jp/borderbreak/pages/24.html 、2018年3月のBB.NET表記。v0.13.1、ユーザーが示した）：スウィフト＝シュライク（ブースト+5、歩行+0.45m/s）、ハウンド＝クーガー（射撃補正+5%、重量耐性+150）、ブルワーク＝ヘヴィガード（装甲+3%を各部位。被ダメージ倍率から0.03引く。もう1つの DEF耐久+250 は本作に DEF が無いので入れない）。初期の機体はハウンドで揃っているので、何も変えなくても射撃補正+5%・重量耐性+150が付く。
- 機体カスタマイズの画面（`renderCustom`）：上に兵装のタブ（`#cuTabs`）と構成1〜3（`#cuBuilds`。メニューにも `#ovBuild`）。左の列（`renderSlotList`）に部位4つと武器の枠4つ（重量と付けている物）。中の列（`renderSeries`）に選んだ枠のシリーズをメーカーごとにまとめ、開くと型の行（主な数値 `keyStats` と重量）。並べ替えで軽い順・重い順の平らな一覧にもできる。右の列（`renderDiff`）に回るプレビュー（`mechPreview`：マウスを乗せている物を付けた姿。武器の枠を選んでいればその武器を持つ）、今の物の数値と、マウスを乗せた型との差（`itemNums`、`mechNums`。良くなる方は緑の▲、悪くなる方は赤の▼）、セットボーナス（付く・外れるも出す）、塗装。下に重量のバー（`#cuWBar`）と兵装ごとの重量表（`#cuMore`）。↑↓キーで型を移り、Enter で付ける。付けた物はすぐ保存する。

### 被ロックオン警告（`lockWarning`。v0.11.1、Codex 版から）

- 自分をロックしている敵機・防衛砲台の方向を、照準外周の半径1.5倍の位置にある橙の三角で示す。メカニカルは武器メーターの外周を基準にする。上部の「被ロックオン／被発砲」・機数表示と、円環への方向の文字は廃止（2026-10-21ユーザー指定）。1.4秒ごとに警告音 `lockWarn`。
- ロックしている敵が実際に発射したときだけ、その方向を0.26秒間赤くし、三角を一回り大きくする。ロック中は幅12px×高さ16px・不透明度55%、発砲時は幅16px×高さ22px・不透明度65%で、どちらも細め・半透明。配置半径は固定し、ほかの方向のロックは小さい橙のまま。`shot` と防衛砲台の実射から通知するため、再装填中・充填中・持ち替え中のトリガー入力では赤くならない。命中の有無には依存せず、ロックなしの射撃は無警告。再出撃・試合開始で発砲強調を消す。
- ロックしない武器（`noLock`：狙撃銃・重砲・偵察機）で狙っている敵と、光学迷彩中の自分は数えない。

### 被索敵の警告（`spotWarning`。v0.11.2、ユーザー指定）

- 敵のレーダー（敵ベースに入っている間）・センサー・偵察機・索敵ソナーに映されている間、ミニマップの下に「被索敵」と、索敵している物と残りの秒数（レーダーはベースにいる間ずっとなので秒数なし）を出す。映され始めたら1回 `spotWarn` を鳴らす。
- 索敵している物は `spot(team, e, keep, by, src)` の `src`（'レーダー'・'センサー'・'偵察機'・'索敵ソナー'）で `spotSrc[陣営]` に残り秒数つきで入る。
- 敵ベースのレーダーに探知されたときの「探知されています」の表示（v0.9.3）は、この警告にまとめた。上部の赤い帯は自軍ベースへの侵入警告だけ。

### 設置物と索敵（`gadgetUpdate`）

- 地雷とセンサーは `gadgets` に入り、撃って壊せる。地雷とセンサーは起動まで1秒（`armT`）。1人が置ける数（`max`）を超えると古い物から消える。地雷は地面に置かれ、センサーは当たった所（壁・地面・機体なら足元）に貼りつく。
- 索敵：センサー（0.25秒ごと、球）と偵察機（水平距離）が見つけた敵機を `spotted[陣営]` に残り秒数つきで入れる。ミニマップでは、自機の80m以内の敵は丸（光学迷彩中の敵は出ない）、索敵で見つけた敵は赤い ◇（光学迷彩中でも出る。wiki）。味方のセンサーと偵察機は黄色い円で範囲を出す。
- 索敵済み敵機の画面表示（2026-10-24ユーザー指定）：自軍の `spotted` に有効時間が残る敵機の胴体中心へ橙の◆を表示する（`spottedHud`）。壁越し・ロック距離外・光学迷彩中でも表示し、味方が得た索敵情報も共有する。未索敵の敵・味方・砲台や設置物・行動不能/大破した敵・画面外やカメラ後方には出さない。期限切れ・撃破・試合の作り直しで消える。自機の妨害中・撃破/キルカメラ・全体マップ・武器選択・設定/メニュー中は隠す。4種類のHUDと全武器枠で共通。マーカーのDOMを再利用し、追加の遮蔽レイは使わない。◆は位置情報だけで、壁越しや迷彩中のロックを許可せず、索敵の範囲・有効時間・スコアを変えない。
- 索敵装備のパルス（2026-10-24ユーザー指定）：索敵が作動するタイミングで、発信部から約3mまで広がって消えるシアンの波を繰り返す。通常センサーは周囲、扇形センサーと展開式レーダーは実際の扇形方向、滞空センサーと偵察機は下向き、索敵カーテンは鉛直の円盤面へ出す。偵察機は上昇中も表示し、飛行中は発信部へ追従する。敵を発見したかどうかにかかわらず作動を示し、破壊・退場・レーダーの持ち替えで消える。これは短い作動演出で、実際の索敵範囲を示すものではない。壁による深度判定を行い、当たり判定・索敵の範囲や周期・共有乱数に影響しない。描画をまとめ、同時表示数を制限して多人数戦での負荷を抑える。携行レーダーは、迷彩中かつ未発見の敵機のものだけ表示しない（味方と独立した設置物・偵察機は表示）。表示は0.75秒以上の間隔・0.6秒継続で、200m以内の近い装備から最大48個まで。
- 偵察機はまだ撃ち落とせない。
- Botの狙い（v0.11.2、ユーザー指摘「設置物にタゲが行かない。優先されすぎても困るが、壊さないのはもっと問題」）：見えている敵機（70m、索敵を受けていれば105m）がいちばん。ただし自分を撃っている自動砲台が、その敵機より近ければ先に壊す。敵機が見えなければ55m以内の防衛砲台、無ければ見えている敵の設置物（`botGadget`。自動砲台60m・センサー50m・地雷と遠隔爆弾30m、自軍のコアに貼りついた遠隔爆弾は60m。自動砲台は距離を0.7倍に見積もって先に選ぶ）。重火力はロケットを設置物にもよく撃つが、重砲は撃たない。設置物を狙う点（`targetPoint`）は自動砲台が砲身の高さ（1m）、ほかは0.2m。
- v0.11の設置物：遠隔爆弾は当たった所（壁・コア）に貼りつき、プレイヤーは遠隔爆弾を持っている間に右クリックで全部起爆（`detonateRemotes`）、Botは敵機が爆風の6割の距離に来たら起爆する。敵のコアに貼りついていればコアにも当たる。自動砲台（`sentryTick`）は地面に置かれ、0.3秒ごとに range 以内で見えている（光学迷彩は `noticed`）一番近い敵機を選び、持ち主の弾として撃つ。浮遊機雷は地雷と同じ動きで、1.6m浮かんで7m以内に反応する。滞空センサーは `dur` 秒で消え、扇形センサーは置いたときの持ち主の向き（`g.dir`）の前方だけを見る。索敵ソナーは設置物にならず、炸裂（`blast` の `scan`）した瞬間だけ映す。
- 設置物破壊のスコアは、遠隔爆弾を地雷、自動砲台をセンサーと同じに数える。

### 光学迷彩（`camoTick`、`reveal`、`cloakHit`、`cloakLook`、`noticed`。ユーザー指定）

- 見えやすさ `vis` は、止まっているとだんだん下がって0.04に近づく（約1秒で半分）。動くと速さに応じて揺らぎながら上がり、歩きで約0.4、ダッシュで0.55。撃つかソードを振ると0.8、被弾すると0.6まで上がり、そこからまた下がる。
- 見た目：機体の不透明度を `vis² × 0.8` にし（止まっていればほぼ0、歩きで約0.13、ダッシュで約0.24、撃った直後は約0.5）、揺らいでいる間はちらつかせる。味方（自機を含む）には最低0.3で薄く見える。ブースターの炎と発砲炎などの光る演出（加算合成）は消えない（wiki）。消えている間、自機の画面中央に見えやすさを出す。
- 背景の歪み（`cloakPass`、v0.21、ユーザー指定 2026-10-20「もっと見えづらくしていい。効果最大だと背景が歪んでるからここにいるのがわかる」）：本描画のあと画面を写し取り（`copyFramebufferToTexture`）、迷彩中の機体の面（レイヤー `CLOAK_LAYER`）だけを、写した背景を面の向きへずらして描き直す。正面の面はほとんどずれず、輪郭に近い斜めの面ほど大きくずれ、少し波打つ。平らで模様のない所ではほぼ見えず、壁の角や地面の線の上では線が途切れて見える。壁の向こうの機体は深度で隠れる。迷彩中の機体がいないフレームは何もしない。試験は `tools/test/camo_check.js`。
- 被弾すると、ダメージ4000（`hitHp`）でSPが尽きる割合でSPを余分に使う（アサルトライフル1発で約8.5%、10発ほどで解除。v0.9.1でユーザー指定）。自機ならSPゲージが赤く光る。SPが尽きると解除。撃破されても解除。
- Botと防衛砲台は、光学迷彩中の敵機には距離が `8 + vis × 80` m より近くないと気づけない（止まっていれば約11m、歩いていれば約40m、撃った直後は約70m）。プレイヤーは画面で見て探す。

重火力・遊撃・支援の特別装備に各1系統3型を追加し、全213種。旧204種の性能と各枠の初期装備は保持する。

Botは交戦時にバリア・自動銃を起動し、交戦が終われば停止する。傷ついた味方か行動不能の味方が近ければビーコンを設置し、不要になれば回収する。ビーコンを持つ味方と、既に設置されたビーコンも蘇生待ちの判断に含める。新装備はリペアポッド使用中に停止する。

AC現行表と本作の採用値は `research/weapons/types/special.json`、原表・仕様・暫定値の根拠は `research/arcade/weapons/special-equipment.md`。非使い切り充填の不明値は通常充填と同じにし、ビーコンの耐久6000と追加消費は旧検証を元にした本作の暫定値として区別する。

### マップ指定式の榴弾砲（2026-10-19、#2第3便）

重火力の特別装備にVH-6シリーズ4型を追加し、全217種。既存の重砲（肩から山なりに撃つ装備）は維持する。

- SP選択で構えて拡大マップを開き、移動・ダッシュ・ジャンプ・旋回を止める。マウスでマップの照準だけを動かし、左クリックで爆撃中心を指定。その後は離しても自動連射し、再クリックで中心を変更する。緑の円が射程、黄色／赤の円が照準の誤差範囲（赤は射程外）。射程外を指定しても撃たずSPも減らない。
- 右クリックは構えの切り替え中、発射前、連射中にも即中断し、直前の武器へ戻る。SPを残せば `chargeKeep` で早く充填できる。使い切るか次弾に足りなくなると自動で戻る。発射済みの弾は中断・持ち主の撃破後も落下する。
- `artilleryTick` が1発ごとにSPを使い、`barrages` に飛翔中の弾を登録、`artilleryUpdate` が上昇→転送→垂直落下を進める。着弾2秒前に火柱・火の粉と落下音を同時に出す。発射筒の形と演出はオリジナル、音は既存素材を使う。

- Botも同じ `selectWeapon`・`artilleryConfirm`・`weaponsTick` を使う。見えている敵や争奪中の敵プラントを狙い、自分や味方の近くを避ける。砲撃中の機体は目標へ向き直さない。ポッド使用中・スタン中・転送中は撃てない。

ACの現行表・発射間隔の本文・採用理由と暫定演出値は `research/arcade/weapons/artillery.md`、採用値と未採用型は `research/weapons/types/artillery.json`。単発強装型の非使い切り充填は不明。3点射型は同じシリーズの数値違いにはせず、後続の別系統として記録する。

### Botの補助装備・特別装備（`botAct`）

`baseDefense` を指定するマップでは、守備役を `posts` の別地点へ置き、被攻撃プラントへの自動エリア移動を止める。生きているレーダーの侵入情報か、本人が視認した近い敵へ対応する。`alertRadius` 内で通常の索敵情報に映った接近者がいれば、`responseRadius` 内で基地に近い占拠役を最大 `reinforcements` 機戻す。帰還は既存の移動・エリア移動待機で行い、索敵失効後は見えていない敵を追わない。手動指示、回復、蘇生は通常の優先度。指定しないマップの判断は従来どおり。

`raidRoutes` を指定すると攻め役へ正面・潜行・レーダー攻略・屋根の経路候補を分ける。分岐点は通常のnav・昇降・physicsで通り、上層の目標を地上から達成扱いしない。レーダー攻略はアンテナを普通の武器で狙い、射程外・遮蔽中なら接近する。射程省略時は本体射撃の400m、減衰がある銃はその距離まで近づく。速度重視は交戦中も前進を優先する。レーダー破壊後はコアへ向かう。`botRepairRange` は補給先を選ぶ距離（省略時90m）で、縦延長版では160m。

Botはプレイヤーと同じ装備を同じルールで使う。数秒ごとに次の条件を見て、当てはまれば `act` を作り、その枠に持ち替えて使い、終わったら元に戻る。

| 兵装 | 使う場面 |
|---|---|
| 強襲 | 15〜40mの目標へ副武器（3点射は撃ち切るまで）。交戦していなければ加速装置を作動させ、遠い移動では加速して進む |
| 重火力 | 40m以内の敵機へ補助装備の手榴弾（衝撃散弾銃は15m以内で撃つ）。30m以上離れた目標へ、SPが満タンなら重砲を撃ち切る |
| 遊撃 | 35mより遠い敵には狙撃銃を使い、その場で止まってスコープを覗き、照準が6割まで収束してから撃つ（止まっている間はショートダッシュで避けない。v0.10、`u.snipe`）。交戦していなければ、敵ベースの方へ偵察機を打ち上げるか索敵ソナーを30m先へ投げる。自動砲台は自軍のプラントか守りの役のとき、40m以内に無ければ足元の6m先に置く。SPが満タンなら光学迷彩で消えて進む |
| 支援 | 自軍のプラントにいて近くに無ければ、センサー（滞空センサーは前方60mへ）と地雷・遠隔爆弾を置く。リペアユニットは今までどおり。リペアフィールドは、自分か効果範囲内の味方の耐久が9割未満、または行動不能の味方がいれば作動させ（SP3割以上）、いなくなれば止める（交戦中も） |

### 指示出し・蘇生・エリア移動（v0.17、ユーザー指定）

**指示出し**（`QCHAT`、`qchatSend`、`qchatTick`。ユーザー指定「G 長押しの円形メニュー（マウスの向きで選び、離すと送る）と、全体マップをクリックして地点を指す」）

- G を押している間、画面の中央に8つの言葉を円く並べる（`#qchat`）。マウスを真ん中から22以上動かした向き（上から右回りに8方向）を選び、G を離すと送る（真ん中のままなら取り消し）。メニューの間は視点が動かない。
- 送った言葉は味方の右の欄に出て、短い音（`chat`）が鳴る。敵の言葉は出ない。
- 言葉、従う機数、秒は Claude が決めた。

| 言葉 | 印 | 従うBot | 秒 |
|---|---|---|---|
| ここへ向かえ | 照準の先 | 近い順に3機。その地点の6m以内まで行く | 40 |
| 敵を発見 | 照準の先 | 近い順に1機。その地点へ | 20 |
| ここを守れ | 照準の先 | 近い順に2機。その地点の周り10mで戦う | 45 |
| 援護をたのむ | なし | 200m以内の2機。送った機体の12m以内へ来る | 30 |
| ありがとう・後退する・ごめん・了解 | なし | なし | ― |

- 印（`pings`）は黄色の光の柱で、全体マップとミニマップには輪、画面には言葉と距離が出る。10秒で消え、1陣営3つまで。全体マップを開いている間は、照準の先の代わりにマップのカーソルの地点に出す。
- 従うBotの1機目が「了解」と返す。
- 指示はカタパルトへ向かう途中より優先する。リペアポッドへ下がるときと、行動不能の味方を起こしに行くときは、そちらを先にする。援護を頼んだ機体が撃破されると指示は終わる。
- 試合をやり直すと、印と指示は消える。

**蘇生**（`kill`、`wreck`、`downTick`、`revive`。ユーザー指定「耐久0で約10秒倒れたまま、その間にリペアユニットで起こせる。大きな一撃なら即大破」）

- 耐久が0になった機体は、その場に倒れて行動不能（`downT`）になる。`REVIVE_WAIT` 10秒たつと大破し、機体が消えて再出撃までの5秒を数え始める。
- 撃破の一撃が `REVIVE_BIG`（ダウンと同じ7000）以上なら、倒れずにすぐ大破する。散弾は1回の射撃の合計で見る。自爆もすぐ大破。
- 行動不能の間に味方のリペアユニットで `REVIVE_NEED` 3000修理されると起き上がる。耐久は3割（`REVIVE_HP`）、3秒無敵（`REVIVE_INVUL`）。
  - 修理量3000と無敵3秒は wiki の再始動の値。耐久3割はユーザーに示した値。
  - 起こす修理には、味方を直すときの1.2倍が掛からない（wiki）。
  - リペアユニットは、照準の先の行動不能の味方も相手に選ぶ（地面から0.8mの所を狙う）。
  - リペアフィールドも範囲内の行動不能の味方を蘇生する（2026-10-21、対象から除外されていた不具合を修正）。標準/広域型は毎秒1000で約3秒、高出力型は毎秒1300で約2.31秒。蘇生中の対象も味方の人数と追加SP消費に数える。修理ポッド使用中はフィールドを停止し、自己蘇生・敵軍・大破済みは対象にしない。
- 数える時：撃破のスコアと撃破数・大破数は倒れたとき。コアの1/160（コスト制のマップは戦力）とキルカメラは大破したとき。
- 行動不能の機体には弾も爆風も当たらない。ロックオンもできず、プラントの占拠にも数えない。
- 見た目：後ろへ倒れたまま赤く点滅し、ときどき煙が出る。
- プレイヤーが行動不能になったとき：
  - F ですぐ大破し、再出撃へ進める。
  - 画面の真ん中に、大破までの残り秒、修理の進み、起こせる一番近い味方とその距離を出す。
  - 起き上がると「蘇生されました」と知らせる。
- Bot が行動不能になったとき：
  - 120m（`REVIVE_CALL`）以内に起こせる味方がいなければ、1秒で大破する。起こせる味方とは、使用可能なリペアユニット・リペアビーコン・リペアフィールドを持つ機体。フィールドは未起動でも待機対象にするが、過熱/SP切れ・修理ポッド中は除く。
  - 起こせるのがプレイヤーなら「救援をたのむ」と言い、その場所に印（「行動不能 名前」）を出す。
- リペアユニットを持つBotは、120m以内の行動不能の味方を起こしに行く。リペアポッドへ下がるとき以外は何より先にする。
- リペアフィールドを持つBotも同じ優先度で接近する。停止距離は効果範囲より2m内側（最長10m）にして、半径9mの高出力型が範囲外で止まることを防ぐ。
- 起こすとスコアは貢献 +1（「スコア」の節）。

**エリア移動**（`startTransfer`、`doTransfer`、`botTransfer`。ユーザー指定「H で待機してから、ベースかプラントへ。耐久・弾は持ち越し、ベースの中では半分の時間で兵装も変えられる」）

- H でその場に屈んで待機し、待ち終わるとベースか自軍のプラントへ移る。もう一度 H で取り消し。出る場所は再出撃と同じ（`spawnPos`）。
- 始められるのは地上で動けるときだけ。空中・カタパルト・よろけ・ダウン・ソードの振りの途中・リペアポッドの上ではできない。
- 待っている間は動けず撃てず、ダウンすると取り消しになる。
- 待ち時間は重さ（`stats.weight`）で決める。
  - 4700kg（`AREA_KG0`）までは2.5秒、超えた分は1kgごとに4.5/730秒、最長10秒。
  - 標準のパーツと初期装備なら、強襲（4340kg）と遊撃（4630kg）が2.5秒、支援（4900kg）が約3.7秒、重火力（5430kg）が7秒。ユーザーに示した「重火力7秒、ほか2.5秒」に合わせた。
- 自軍ベース（`BASE_LINE` より奥）で始めると、待ち時間は半分になり、兵装も変えられる（Z・X・C・V）。兵装を変えると武器は全量になり、耐久はそのまま。
- 待っている間は、画面の下に移動先の画面を出す（再出撃と同じ。数字キーかホイールで選ぶ）。その一番上に残り秒（`#rtXf`）。最初の移動先は、ベースの外ならベース、ベースの中なら最前線のプラント。
- 耐久・弾・SPは持ち越す。撃破ではないのでコアも減らない。移った先では最大2秒無敵（出撃と同様に攻撃開始で解除）。
- コスト制のマップ（ベースもプラントも無い）では使えない。
- Botの使い方（`botTransfer`）：敵を狙っていないときだけ使い、1度使うと40秒は使わない。攻め役は使わない。
  - 守り役は、自軍ベースのレーダーが敵機を見つけていて、自分がベースから150m以上離れていればベースへ。
  - 占拠役と守り役は、敵が入ってゲージが動いている自軍のプラントから150m以上離れていれば、そのプラントへ。

### 頭上の名前と耐久・損傷の見た目（v0.18、ユーザー指定）

ユーザーの指定（2026-10-19、本家の画面写真を添えて）：「ダメージエフェクト、および行動不能時の破損エフェクトが欲しいです」「敵味方の体力残量の視認性が悪いです」「敵の体力残量の視認可能距離はロックオン距離に依存のこと。味方は150m以内固定で映してください」。

- 頭上の名前と耐久（`tagsHud`、`tagOf`。`#tags` の中の `.utag`）：機体の頭の上（倒れていれば低い所）に名前と耐久のバーを陣営の色で出す。
  - 名前の左に、現在の出撃兵装 `u.cls` のオリジナルマークを表示する（2026-10-20、ユーザー希望）。強襲＝稲妻、重火力＝3本の砲口、遊撃＝照準、支援＝修理工具。色は陣営色を継承し、形で区別する。SVG線画を本体に直接持ち、公式/外部素材は使わない。同じマークを出撃・再出撃の兵装選択にも添え、名称と対応を学べるようにする。頭上は17px、遠距離は15px。兵装や名前が変わったときだけDOMを更新し、行動不能/蘇生中も兵装を保つ。Botの作戦上の `role` や、次の出撃用 `nextCls` は表示しない。
  - 敵：自分の頭部のロック距離（索敵を受けている敵は `SPOT_LOCK` 倍。ロックできる距離と同じ）より近く、間に壁が無いとき（`TAG_SEE` 0.2秒ごとに `canSee` で確かめる。索敵を受けている敵は壁越しでも）。光学迷彩中と行動不能の敵は出さない。壁と索敵の扱いは Claude の判断（壁越しに見えると居場所が分かってしまうため）。
  - 味方：`TAG_ALLY` 150m 以内なら壁越しでも。行動不能の味方は「行動不能」と、蘇生の進み具合（`reviveAcc / REVIVE_NEED`）を緑のバーで出す。
  - バーの白い部分は減ったばかりの耐久で、`TAG_LAG` 0.6秒たってから縮む。耐久3割以下は点滅、`TAG_FAR` 100m より遠いと小さく薄く。自分が大破している間とキルカメラの間は出さない。

- 損傷の煙と火（`damageLook`、`puff`、`puffUpdate`、`sparkBurst`）：耐久が `DMG_SMOKE` 50%以下で薄い灰色の煙、`DMG_FIRE` 25%以下で黒い煙と小さな火と火花。煙は風下（+x、`WIND`）へ少し流れる。光学迷彩中の機体と、カメラから `PUFF_FAR` 220m より遠い機体は出さない。煙と火は使い回すスプライト（`PUFF_MAX` 320個まで。足りなければ出さない）。
- 行動不能（v0.17 の蘇生）：倒れた瞬間に小さな爆発と火花と煙（`downBurst`）。倒れている間は装甲が焦げた色（`armorMat.color`）になり、赤く点滅し、黒い煙の柱と火と火花が出続ける。起き上がるか大破すると色が戻る。
- 値（割合・秒・個数・色）は Claude の仮置き。

### 効果音（`SFX`、`sfx`）

- 音は [Openverse](https://openverse.org/) から自由に使えるライセンス（CC0、CC BY）のものを選ぶ（ユーザー指定）。出典は `sounds/CREDITS.md` に書く。NC・ND・SA と公式の音は使わない。
- 開発版のフォルダ：音の元ファイルは `sounds/src/<名前>.*`、`python3 tools/build_sounds.py` で `prototype/sounds.js`（mp3 を base64 にしたもの）を作る。ファイルを直接読まずに script で読むのは、index.html をダブルクリックで開いたとき（file://）も鳴らすため。
- 音の名前（13個）：ar、pistol、sniper、shotgun、rocket、explode、swing、slash、hit、dash、reload、beep、heal。場面ごとにどの音をどの音量・高さで鳴らすかは `SFX` の表（同じ音を高さを変えて使い回す。例：ジャンプとカタパルトは dash）。
- 武器の射撃音（v0.11.3、ユーザー指定「Codex 版から射撃音を」）：Codex 版の音は同じ13個のファイルで、増えていたのは `magnum`（pistol を低く大きく鳴らす設定）だけだったので、それを足し、同じ音を使う武器は `SFX_TUNE` で音の種類と高さ（`w.sfxRate`）を武器ごとに変えた。`sfx(名前, 位置, 鳴らした物, 高さ)`。
- `sfx(名前, 位置, 鳴らした物)`：自機から遠いほど小さく（`range` で0）、左右に振り分ける。同じ物が同じ音を `gap` 秒より短い間隔で鳴らさない。初回の警告音は起動直後でも鳴らす。`ui` の音は距離に関係なく鳴る。
- 同時音数は周囲24・自機4・UI4の計32まで。満杯なら小さい周囲音を近くの大きい音へ譲り、警告・被弾・戦況通知を通常の命中通知より優先する。50対50では周囲音だけ0.5倍・最大16音にし、自機・UIの各4枠を維持する。周囲音には圧縮（閾値-16dB、比5:1）、全体の出力にはピーク圧縮（閾値-2dB、比20:1）を入れる。人数による加算を音量設定だけに任せず、距離・方向と警告の聞き取りやすさを維持する（2026-10-21ユーザー指定）。
- 移動音（2026-10-21ユーザー指定）：歩行の左右の足が接地する半周期ごとに、既存の金属音 `hit` を低く短くして鳴らす。周期は見た目と共通の実移動距離で進め、壁での空踏み・停止・空中・ブースト・硬直・死亡・プレビューでは鳴らさない。軽い着地も落下速度3m/s以上から鳴らし、強い落下ほど大きく低い音にする。着地直後0.12秒は足音を抑えて重複させない。歩行速度・落下・着地硬直の規則は従来どおり。
- 短い噴射音はダッシュ0.24秒・ジャンプ0.20秒・加速装置の開始0.26秒に合わせてフェードする。巡航・滞空・加速装置の持続中は、既存CC0の `rocket` の0.12〜0.42秒を0.04秒クロスフェードした共有バッファを低音量で繰り返す。継続中も距離・左右の位置を更新し、停止・燃料切れ・撃破・ポッド・マップ変更・再出撃・一時停止・非表示・消音では0.04秒で消す。既存の音数枠を共有し、退けられた噴射音の再試行は0.12秒ごとまで。移動音の高さにはゲーム用乱数を使わず、足音の左右差と機体重量で小さく変化を付ける。新しい外部音源や保存項目は追加しない。
- ブラウザは操作の後でないと音を出せないので、最初のクリックかキー入力で `initAudio` が準備する。N キーで効果音と音声アナウンスを消す（v0.15まで M。M は全体マップになった）。
- 戦況アナウンス（v0.15、ユーザーが選んだ「本家から移植」の一番）：画面の上の方（`#announce`）に2.6秒出し、短い電子音（`annGood`・`annBad`・`annInfo`）を鳴らす。メニューのスイッチ「音声アナウンス」（`localStorage` の `coreBreakerVoice`）がオンなら、ブラウザの読み上げ（`speechSynthesis`、日本語の声があれば）でも読む。出す物：作戦開始、プラントの占拠・中立化（自軍・敵）、自軍のプラントが敵に占拠され始めた（同じプラントは20秒あけて）、自軍コアが攻撃を受けている（20秒あけて）、敵コアへの攻撃を確認（30秒あけて）、コアの残り50%・25%（コスト制のマップは除く）、ベースへの敵機侵入（15秒あけて）、残り時間3分・1分・30秒・10秒（試合がそれより長いとき）。一度に3つまで。文言は Claude が決めた。
- 戦闘中BGM（v0.10、ユーザー指定）：ユーザーが選んだ OpenGameArt.org の曲「Nightmare(prototype)」（Centurion_of_war、CC0）1曲（`sounds/music/bgm.ogg`、19.2秒）を、試合中だけ繰り返し鳴らす（音量0.32、始まりは1秒で大きく、試合が終わると0.6秒で消える）。メニューのトグルスイッチ「戦闘中BGM」で切り替え、`localStorage` の `coreBreakerBgm` に残る。N キーの効果音オフとは別。ogg は繰り返しの継ぎ目が出ないよう再圧縮せず `music.js` に base64 で入れる。ogg を再生できないブラウザ（古いSafariなど）ではスイッチの横に「このブラウザでは再生できません」と出る。操作説明の最後に謝辞（「Author: Centurion_of_war さんの nightmareheavy.ogg を使わせていただいています。ありがとうございます」と出典。ユーザー指定の書き方）。
- 鳴らす場面：発射（武器の `sfx`）、防衛砲台の発射、爆発（`boom`）、リロード完了、ソードの振り・命中、自分の命中（ヘッドショットは `headshot` と `headping`、v0.9.5）・被弾、ダッシュ、ジャンプ、カタパルト、ロックオン、プラント占拠、リペアポッド、リペアユニット、持ち替え。

### 画面とメニュー（v0.10、ユーザー指定）

- 参加人数（2026-10-23ユーザー指定）：全マップで、片軍あたり2〜50機を、1つの人数選択欄で出撃前に選ぶ。選んだ人数を両軍へ同じように適用する。自軍は自分1機＋選択人数−1機のBOT、敵軍は選択人数ぶんのBOT。選択欄とBOT数の内訳を表示し、マップ変更・出撃側変更・再試合でも維持する。推奨へ戻すボタンと再読み込みでマップの既定人数へ戻す。新たな保存項目は加えない。近接限定も対象で、コスト制の10機先取や制限時間は変えない。片軍50機の場合の大破コア消費は既存50対50と同じ1/800、それ未満は1/160を使う。`match_size_check.js`で全配置の人数上下限・中間人数と両出撃側・100行スコアを検査する。

- 初期画面はメニュー：「操作説明」（ルールとキー操作、謝辞を別の画面に分けた）、「マップ選択」（見取り図・人数・プラント数・時間・説明つきのカード。選ぶとメニューへ戻る）、「機体カスタマイズ」（v0.11で武器のカード、v0.12で機体のタブ、v0.13で3列の画面と構成3つ。「シリーズと型、メーカー」の節）、「戦闘中BGM」のトグルスイッチ。兵装（強襲・重火力・遊撃・支援）のボタンと「出撃する」はメニューの下に残している。
- 出撃側（ユーザー指定）：メニューで南側（B）・北側（R）を選ぶ。非対称・対称・コスト制のどのマップでも選べる。既定は南側で、マップ変更と再試合では選択を維持し、再読み込みで南側に戻る（保存データは追加しない）。選んだ陣営はプレイヤー1機＋Botを選択人数まで、相手は全機Bot。出撃位置・向き・再出撃・エリア移動・索敵・自軍/敵軍の名前・勝敗と結果のコア/戦力表示はプレイヤー陣営に従う。
- 陣営の表示色（ユーザー指定）：出撃する側によらず自軍を青、敵軍を橙で統一する。コア/戦力ゲージは左/上が自軍、右/下が敵軍で、スコア表も自軍を先に出す。プラント、基地・門・砲台・レーダー・傘、機体のチーム色と頭上の名前、マップの基地と機体、戦闘ログ・表彰、陣営色を使う通常弾の軌跡・砲弾・光波・設置物にも適用する。自機の地図記号は青い丸に白い縁と向きの線を付ける。機体カスタマイズのチーム色も常に青。任意の装甲塗装と、エネルギー弾など装備固有の色は維持する。出撃先の見取り図は選択直後、試合の色は次の出撃時に切り替える。`renderTeamView` が表示色と既存の施設マテリアル・標識を更新し、地形・乱数・当たり判定・所有陣営IDは変更しない。
- 画面は `#overlay` の中の `.page`（`#pgMenu`・`#pgHelp`・`#pgMap`・`#pgCustom`）を `showPage(id)` で切り替える。戻るボタンか Esc でメニューへ。試合の結果もメニューの画面に出る。
- オプション（`#pgOptions`、2026-10-21ユーザー指定）：全体・効果音・BGMの音量を0〜100%、縦視野角を60〜100°（標準70°）で調整する。音量の既定100%は従来の全体0.8・BGM0.32を基準にし、再生中の音にも滑らかに反映する。全体音量は読み上げの音量にも反映する。視野角はダッシュ時+12°/+7°、ロック・スコープの倍率の基準となる。キルカメラは従来の60°。F3で戦闘を一時停止して開き、「戦闘に戻る」・F3・Esc・戻るで同じ試合へ復帰する。押しっぱなしの移動・射撃を残さない。設定は独立した `localStorage.coreBreakerOptions` に `{master,sfx,music,fov}` で保存し、既存の装備・BGM・音声スイッチの保存値は変えない。範囲外は制限し、壊れた保存値は標準へ、保存不可でもその場の設定は使える。
- コンソール（ユーザー指定）：メニューの「コンソール」（`#pgConsole`）で、配置図付きの4種類から選ぶ。既定の「標準」は現行の配置。「アーケード」はユーザーの参考画像（2026-10-20「アーケード画面もこれを参照してもうちょっと近づけて」）に寄せ、左上に重ねた両軍のコアの棒と秒で数える残り時間、その下に BATTLE の札を付けた記録、左下に機体の札（兵装の頭文字の印・名前・兵装）と縦に伸びる斜めの耐久ゲージ（ブースト・SPの行は出さない。ブーストは照準の弧、SPは照準の下の棒と特別装備の枠）、右下に大きめのマップと菱形の武器枠。武器枠の並びは十字の持ち替えと同じ（上が主武器、右が副武器、左が補助装備、下が特別装備）で、持っている武器は緑で大きな数字（右下の大きな数字と同じ値）、ほかは弾倉の残り（剣は∞、SPを使う物は%）。特別装備の枠はSPの残りの分だけ黄色で満ちる。画面幅1000px以下ではプラントの表示を右上へ寄せる。「フライト」はユーザーの星の翼の参考画像（2026-10-20）に合わせ、下中央に太いブーストとSPの2本を上下に並べ、右側に主・副・補助・特別装備の4枠を縦表示する。装備ごとに丸い図形の印と数字キー、残弾・装備名・再装填や充填の状態、残量の棒を出す。マップは右上、耐久は左下、速度・対地高度は照準の左右、方位は照準の上。小さい画面でも縦4枠と2本のゲージを維持し、印や文字の大きさを調整する。「メカニカル」は照準左右の4枠の淡い緑の武器メーター、見えているロック対象の耐久と距離、両端の速度・対地高度、左下の耐久、右下の4枠の残弾と状態、下中央の横長ブーストと機体方位に追従する目盛り。公式素材を使わず、表示上の名称も本作独自とする（参考資料と対応は `research/hud-consoles.md`）。
- コンソールの切り替えは `body.dataset.console` とCSSで既存のHUDを再配置し、同じ数値と状態を表示する。照準円の判定はすべて共通。フライトのSPは下中央のブーストの下に置き、ほかの3種類は照準円の下の黄色い棒で表示する。方位は機体の向き（北=0°、東=90°）、速度は機体の実速度（上下を含むm/s）、対地高度は足元から直下の地面・床までのmで、ゲームの性能に影響しない。飛行計器と照準の武器メーターはスコープ中・行動不能・撃破中に隠す。メカニカルのブーストはスコープ中も表示する。短い画面で警告が出るときはフライトの方位だけを隠して警告を優先する。追加の配置では武器情報と基地侵入の警告の実際の高さを読み、マップや通知を重ねない。メカニカルの通知は対象の耐久表示を避けて左上へ並べ、短い画面では通知を速度計より優先する。
- フライトの下中央の2本は既存のブースト・SPの行（`#boostRow`・`#spRow`）をCSSで移したもの。ブーストは最大値に対する割合、SPは共通0〜100を表示し、過熱・作動・被弾の状態も同じ処理で反映する。右の装備の棒は残弾またはSP、再装填・冷却は復帰の進み具合を表示する。
- メカニカルの武器メーター：内側の左が主武器、右が副武器、外側の左が補助、右が特別装備。通常は残弾（弾数制限のない近接は∞）、特別装備は共通SP0〜100%。再装填は武器の装填秒×腕の倍率に対する進み具合、冷却は復帰までの進み具合を表示する。充填・熱はさらに内側の弧に出し、右下の各枠にも実際の残り秒・割合を表示する。敵耐久・距離は `lock.target` が生存し `lock.visible` の間だけ表示する。
- メカニカルの視認性（ユーザー指定、2026-10-20）：明るい地形に白い細線が埋もれたため、通常の計器を淡い緑にし、選択中の武器は明るく太くする。武器メーターは暗いレールに残量を重ね、照準の文字には暗い縁取りを付ける。周辺の文字も影を強め、数値のある範囲に半透明の暗い下地を敷く。警告の赤・再装填の青・充填と作動の緑は維持する。明暗両方の背景と小さい画面で確認する（比較記録：`media/mechanical-contrast/`）。
- 選んだコンソールだけを独立した `localStorage.coreBreakerConsole` にID（`standard`・`arcade`・`flight`・`mechanical`）として保存する。未保存・不正な値・読み込み不可の場合は標準から始め、保存できない環境でも切り替えは使える。戦闘中はF2でこの順に巡回し、選んだ種類をログに表示する。試合・装備・既存の保存データは切り替えない。
- 仮パイロット（ユーザー指定、2026-10-20）：メニューの「パイロット」（`#pgPilot`）で猫8匹から選ぶ。キジトラ（垂れ目）、サバトラ（切れ長）、黒猫（ボス）、白猫（桜耳の保護猫）、茶トラ（笑い顔）、三毛（いたずら顔）、ハチワレ（照れ屋）、シャム（眠たげ）。画像は本作用に生成した4列×2行の透過PNG（`prototype/avatars/cats.png`、制作記録は同じフォルダの `CREDITS.md`）。`python3 tools/embed_pilot_avatars.py` で画素を変えずにHTMLへ埋め込み、CSSで8匹を表示する。画像用の追加通信や外部ファイルがなくても表示できる。
- 選んだ猫のIDは独立した `localStorage.coreBreakerPilot` に文字列で保存する。未保存・不正なID・保存APIが使えない場合はキジトラ。兵装・機体の保存形式には加えない。全コンソールのパイロット欄、スコア表と結果、撃破相手が機体の場合のキルカメラに顔を出す。顔に重なる兵装の頭文字は表示せず、兵装名を別に表示する（ユーザー指定、2026-10-20）。Botは陣営と機体番号で8匹を固定割り当てし、乱数や戦闘性能は変えない。選択は兵装・マップ・再出撃をまたいで維持する。
- アーケードHUDの猫画像は従来の約3倍（通常156px、幅1000px以下120px、幅700px以下96px）とし、下にプレイヤー名、その下に兵装名を並べる。ほかのコンソールの顔の大きさは維持する。最初の画面（`#pgMenu`）にプレイヤー名の入力欄を置き、20文字までを独立した `localStorage.coreBreakerPlayerName` に保存する。空欄・未保存・読み込み不可なら「あなた」。日本語変換中の入力は確定まで保持し、入力中のキーをゲーム操作へ渡さない。プレイヤーの名前はマップ・兵装・再出撃をまたいで維持し、HUD・スコア・表彰・戦闘ログでは入力をHTMLとして解釈しない。
- アーケードのひし形の武器枠は、武器名の前に対応する数字キーを表示する（1=主武器、2=副武器、3=補助装備、4=特別装備）。並びは上・右・左・下のまま、キー操作と同じ `SLOTS` の順序から番号を作る。
- 猫の透過PNGの下へ不透明な背景色を敷かない。アーケードの肖像・耐久欄も背景を塗らず、顔の輪郭の外と表示の隙間から地形を見通せるようにする（ユーザー指定、2026-10-20）。名前と数値には既存の文字の影を使い、耐久の見出しも明るく表示する。
- マップを替えると今の試合（機体・弾・設置物）を片づけ、次の「出撃する」で新しい試合になる。

### 基礎操作チュートリアル（2026-10-26ユーザー指定）

- メニュー先頭の「チュートリアル」から説明画面を開き、「練習を始める」で専用の平らな演習場へ出る。通常のマップ一覧・`maps.js`には登録しない。プレイヤーと静止標的の2機だけを生成し、対戦人数の設定にかかわらず標的は移動・攻撃しない。時間切れや勝敗判定はなく、自爆で大破した場合は同じ課題の開始位置へ戻す。
- 強襲の初期機体・初期4装備を、その演習の機体だけに適用する。`mechCfg`・`loadout`・保存した構成を書き換えず、マップの保存も行わない。終了時に元のマップ・出撃兵装・出撃側・人数を復元し、通常対戦のメニューへ戻る。通常対戦を始める操作はプレイヤーが行う。
- 13課題：視点、歩行、ジャンプ、ブースト、主武器の命中、Rで再装填、右クリックでロックと解除、副武器の命中、近接の命中、加速装置でSPを使った移動、全体マップ、プラント占拠、コアの結晶へのダメージ。移動・射撃・装填・SP消費・占拠・コアの判定は本体の処理を使い、課題の順序と達成確認を`TUTORIAL_STEPS`・`tutorialTick`が受け持つ。
- 左上の案内に課題・操作・進み具合を表示し、目標には既存の光の柱を使う。達成後はEnterで次へ進む。時間経過や説明を閉じる操作だけでは達成扱いにしない。課題ごとに機体・標的・弾・ブースト・SPを初期化し、未着弾の弾を持ち越さない。
- Escまたはウィンドウからフォーカスが外れた時は一時停止。戻る・現在の課題をやり直す・スキップ・終了を選べる。スキップは達成と区別して終了画面に件数を出す。F3の設定画面からも同じ課題へ復帰する。ポインタロック喪失時の停止と、押しっぱなしの移動・射撃の解除も演習に限定して扱う。
- 完了/途中終了/再挑戦の状態はセッション内だけに持ち、保存キーは追加しない。`tutorial_check.js`で13課題の実入力、誤達成防止、停止・やり直し・再挑戦・スキップ・大破復帰、終了後の設定と保存値、通常50対50への復帰を確認する。

### 武器の型（`WEAPON_TYPES`、`makeType`。v0.14、ユーザー指定「兵装ふやしてこっか」「主武器バリエーションに関してはCodex版からある程度移植できると思うので検討願います」）

- 型の選び方：wiki（PS4版）の各系統の表（`research/weapons/*.md`）から、元にした武器と撃ち方・働きが同じで数値だけ違う行を、シリーズが4種までになるよう選んだ（Claude が選んだ。選んだ行・選ばなかった行と理由は `research/weapons/types/*.json` にあり、`WEAPON_TYPES` の行はそこから作った）。入れなかった物：コラボ・イベントの珍しい品、撃ち方が違う物（3点射・チャージ・誘導・分裂・2連装・切り替え）、数値の足りない行。遠隔爆弾（リムペットボムは貼りつく）には型が無い。
- `WEAPON_TYPES[元の武器のキー] = { w0, types: [[型の名前, wiki の値, 説明], ...] }`。`w0` は元にした wiki の型の強化前の値、行の終わりのコメントは wiki の名前（画面には出さない）。起動時に `SERIES` の後で `makeType` が型を作り、`WEAPONS`・`WEAPON_KG`・`MODEL_OF`・`ARMORY`（同じシリーズの後ろ）・`SERIES` に足す。
- 数値：「wiki の値 ÷ `w0`」の比を、本作の元の武器の値に掛ける（本作で強化・縮小した分、例えばショットガンの強化や爆発半径の0.82倍は型にも残る）。重量は wiki の値そのまま。整数の物（弾数・発数・所持数）は丸める。
  - 所持数（count）：補給できない物（`mags` が1）は `mag`、ほかは `mags`。`proj.max` が元の所持数と同じなら一緒に変える。
  - 偵察機：range → `dist`、dur → `hover`。滞空センサー：range（届く距離）は弾速の2乗に比例するので弾速に比の平方根を掛ける。弱化グレネード：dur → `weak.time`。加速装置：power → `speed`。自動砲台：銃の値は `proj.gun` へ。散弾の砲台は `pellets` を足し、ばらつき0.07と距離の減り `[10, 30, 0.3]`。
  - SP：満タンまでの秒の比で、使い切らなかったときの秒も変える（wiki に値があればその比）。
  - 精度（acc）・反動（recoil）のランク（E-〜S）は、1段上がるごとに `spread`（狙撃銃は `sway` も）と反動を0.88倍。反動は `baseKick`（元の武器の既定）に掛けて `recoil` に書く。
  - 近接：wiki の値は連撃の合計なので比の平方根を掛け、横なぎ9600（どの型でも2回は要る）・ダッシュ斬り20000が上限。重さの比 k で、構え・振り・硬直を k^0.35 倍、間合いを k^0.12 倍、ダッシュ中の踏み込みを k^0.3 で割り、誘導を k^0.35 で割る。値の決め方は仮（Claude の判断）。
  - 射撃音の高さ（`sfxRate`）は威力の比の −0.12 乗（重い弾ほど低い）。
- 名前：「元の武器の名前の・の前＋・＋型の名前」（例：アサルトライフル・強装型）。型の名前は軽量型・連射型・強装型・大容量型・精密型・速装型・広域型・持続型・瞬発型・高出力型・重装型と、巡航型（加速装置）・即応型（光学迷彩）。キーは元のキー＋1文字（`TYPE_LETTER`、例 `arH`）、型番も元の型番＋同じ文字（例 SR-7H）。形は元と同じ系統で、型（0・1・2）を順に変える。
- ショットガン速装型（`shotgunQ`、2026-10-25オーナー指定）：装填6発を維持し、1回の操作で3発を撃ち切る3点バースト、拡散率は変更前の1/3（0.08→0.026666…）。バースト内は0.1秒間隔、組の開始から次の組までの周期は現行の1秒に合わせる（内部600発/分・組間の追加待ち0.7秒）。威力・散弾数・予備弾・装填時間は現行値を維持。押し続けると周期ごとに次の組を撃ち、離しても開始した組は撃ち切る。元のwiki転記値は変更せず、型生成後の本作調整として適用する。

## 5. 守ってほしい設計方針（ユーザーの決定）

1. ロックオンは弾を中心へ補正しない。撃つ側はヘッドショットを狙う技量、撃たれる側はショートダッシュでロックを外す技量が勝負になるようにする。ただし追従が弱すぎるのは不可。
2. コアの傘は障害物。ダメージの距離減衰や「傘の外からは無効」といった規則を足さない。
3. リペアポッド使用中は行動不可。
4. 兵装ごとの4枠（主武器・副武器・補助装備・特別装備。v0.8でユーザーの了承を得て4枠にした）。v0.11から各枠の武器を選べる（`ARMORY`。v0.14で型を足して全172種、v0.15で全194種、AC系統の追加で全285種）。数値は仮置きで、wikiに寄せる方向で調整する。ただしショットガンとソードはユーザーの指摘で wiki より強くしている（戻すときは先に確認）。
5. 公式の素材・名称を使わない（機体、音、ロゴ、武器名の固有名詞）。武器は一般名（アサルトライフル等）で呼ぶ。
6. Botもプレイヤーと同じルールで動かす（ロックの追従、ポッドの行動不可、弾数制限など）。

## 6. 改造のしかた

- **武器の数値を変える**：`WEAPONS` の値を変えるだけ。HUD・Bot・補給は自動で追従する。

- **地形を変える**：マップのファイルの `terrain` に起伏を足す（自軍側の半分だけ書けば敵軍側は点対称に足される。中心 (0,0) のものは1つだけ）。施設（プラント・ポッド・砲台・カタパルト）は置いた場所の `terrainH` に乗るので、座標を変えるだけでよい。坂は傾き1.1（約48°）を超えると登れない壁になる。
- **当たる物を足す**：メッシュを `hittables` に入れ、`userData.ref` に `kind` 付きのオブジェクトを入れ、`damage` に分岐を足す。
- **効果音を足す**：`sounds/src/` に音を置き、`tools/build_sounds.py` の `SOUNDS` と `index.html` の `SFX` に名前を足し、鳴らしたい所で `sfx()` を呼ぶ。出典は `sounds/CREDITS.md` に書く。
- **数値の出典を書く**：wikiの値を使ったら、定義の横のコメントに元の武器名と値を残す。

### ミラージュデバイス（2026-10-26、Issue #71）

強襲の選択式SP装備として、ユーザー発案のミラージュ4型を追加。選択で起動／停止し、起動中の成功したクイックブーストだけがSPを消費して出発点に静止残像を置く。標準は耐久500・10秒・消費25%。堅牢1500/10秒/40%、省エネ180/6秒/15%、長時間350/20秒/20%。標準・堅牢は機体の色と姿勢を複製、省エネは半透明、長時間は青緑の明滅。詳細と暫定値の根拠は `research/weapons/mirage.md`。

残像は被弾可能な設置物で、攻撃・占拠・修理・スコア対象にはならない。持ち主ごと4体まで、停止・死亡後も寿命まで残る。プレイヤーのロック、Bot/砲台の追従、ミサイル捕捉と飛翔中の誘導を残像へ引き継ぐ。破壊・寿命切れで追尾を解除し、本体に戻さない。待機消費なし、SP不足でも通常QBは可能。発生後1秒待ち、非OH30秒/OH40秒で全回復（胴のSP性能は速度に適用）。各残像はメッシュ1個に統合し、終了時に専用資源を解放する。

### 爆発の描画サイズと爆風半径（2026-10-26）

武器の爆発は`blast`から`spec.blast`を描画へ渡し、火球・煙・火花・衝撃波をその半径に比例させる。衝撃波の最大半径10.15mを基準に`blastRadius / 10.15`を描画倍率とする。衝撃波は短時間で消え、火球や火花の外形も含め、損傷範囲の境界表示としては使わない。従来の通常/小の区分は音・寿命・火花の粒数にのみ使用し、同じ爆風半径なら同じ大きさで描画する。機体/施設の撃破など半径のない呼び出しは従来の倍率を保つ。武器の威力・減衰・半径や当たり判定は変更しない。

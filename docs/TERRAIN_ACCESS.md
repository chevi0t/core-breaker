# 風裂山道：プラントアクセスとベース侵入の修正

未公開のローカル試作。基準は斜面改訂 a4d9fbe。中立Bが赤陣に近過ぎ、ベース前面が開放されていたという指摘への修正。武器・機体・入力・移動性能は変更していない。

## 配置をどう変えたか

A(-65,85)とC(55,-90)は山腹・尾根に残す。中立Bを(5,-45)から(5,0)へ移し、両基地だけでなく、A/Cからの再出撃経路も比較した。谷底はBへの直進、左山腹はAと高所からの射線、右尾根はC・橋上からの射線を担う。坑道は尾根の下を横断できるが、ベース背後へ直結しない。Bは低所なので、尾根側から占拠するには下りる必要がある。

両ベースの前面z=±145に見える防壁を置き、x=-35/+35を中心とする幅26mの左右入口を残した。中央の防壁はコアへの直進・正面射線を遮る。側壁は実際のプレイ可能境界まで接続する。入口間は70mで、一つの狭い穴へ全員を集めない。谷・山腹・尾根から入口を選び直せる。防壁は既存のblocks（体積・描画・弾／機体衝突）の6要素。中央上面32m、側面上面50mは海抜であり壁高そのものではない。右の高い斜面から通常跳躍で越えられた40mの側面案は不採用とした。

地形の10,580三角形は維持し、防壁6体積だけ追加。見えない壁を新設して入口を制限していない。以前からの外周境界は維持。基地から外へ飛ぶカタパルト4基も従来どおり使える。

実歩行のアクセス検査で、初版の最短経路が坑道屋根の横縁に引っ掛かる問題も見つけた。任意のtunnel.rim=5（0〜10m）により屋根側の接続帯を共通生成器で作り、修正。坑道床・天井・有効高は変更しない。他レシピはrim未指定で従来どおり。

## 測定方法

`terrain_access_check.js` は施設適用後の実行時navから、実際の占拠条件（水平16m、プラントより上6m未満）へ歩ける最短経路を求める。距離は3D線分の合計と入口への接続距離。基地・各プラントの両陣営再出撃候補をすべて計算する。直線距離の比較ではない。

表の距離は3つの出撃候補による最小〜最大。歩行時間は中央候補から同じ経路を実物理で走らせたもの。戦闘・ブースト・カタパルトは含まず、初動の最速突撃時間と同義ではない。重量二脚と重量ホバーで計12経路を実走した。旧版の青→C最短路は屋根縁で止まったため、その旧版所要時間は成功値として使っていない。

自陣側の戻りには約10〜15mの差が残る。高さ・遮蔽・回復位置も同一でなく、完全対称化はしていない。まず明白な中立地点の偏りと全方位のコア侵入を修正した段階。勝率・戦術的な優劣は対人試遊で判断する。

## 確認した範囲

- `terrain_access_check.js`：距離24組、重量二脚／重量ホバーの実歩行12本が通過。
- `terrain_base_entries_check.js`：両陣営×軽量／重量／重量ホバー×9接近の54例。左右入口を通れ、正面・側面・橋上／尾根からの通常ブースト＋跳躍では入口以外の突破なし。斜めに進んで壁沿いに滑り、正規の入口へ回った例は合法な通過として記録。12秒の有限の試みで、全機体・全操作の絶対的な封鎖を証明しない。特殊装備・外部からの特殊な空中経路は対象外。
- 主要経路39項目、施設検査、通常BOT戦150秒（46撃破、コア7706/7819、ブラウザエラーなし）。BOT一試合の結果からPvP公平性を断定しない。
- 既存カタパルト4基は目標から約0.3m以内に着地。実行時nav 1,277節点／4,561リンクが接続。
- 全域穴検査はユーザー指定で繰り返していない。今回の性能測定なし。地形・体積の増分が小さいことは実GPUのFPS同等性の証拠ではない。

通常の試遊版生成は `tools/build_terrain_preview.py ... --skip-escape`。出力のvalidation.jsonは穴の全域検査未実施を明記する。差分・画像・生データはローカルレビューZIPに収録。公開操作は行わない。

防壁の表示には任意の `blockKind: "wall"` を使う。生成された `barrier` 体積を既存の構造物用統合メッシュへ入れ、都市建屋の窓模様を付けない。本体の追加はこの汎用描画分類だけ。衝突は既存体積のまま。両側の中央壁で射線を止め、左右入口の射線が通る6例も確認する。

防壁の表示分類を整えた最終版でもBOT戦60秒を再確認した。防壁の外観は簡易な板状の試作であり、山岳基地としての造形の仕上げは残る。

# 機体パーツの型を足す手順（Codex など向け）

オーナーの指定（2026-10-19）：パーツは数値を調べるだけでなく、**性能まで作り込んでゲームに入れてよい**。

## 今の作り

`prototype/index.html`（名前で検索。行番号は変わる）：

| 所 | 中身 |
|---|---|
| `PART_SLOTS`・`PARTS` | 部位（head・body・arms・legs）と型のキー。light・standard・heavyがⅠ型、末尾2・3がⅡ・Ⅲ型。各部位の型は `Object.keys(PARTS[部位])` で列挙する |
| `PARTS[部位][型のキー]` | 性能。全部位に `weight`（kg）と `armor`（その部位に当たったときの被ダメージ倍率）。頭は `lock`・`aim`、胴は `boost`・`sp`・`supply`、腕は `reload`・`swap`・`recoil`・`ammo`、脚は `walk`・`dash`・`cruise`・`cap`（意味は定義の横のコメントと `docs/DESIGN.md` の「機体パーツと重量」） |
| `PART_SERIES` | 6シリーズ（既存スウィフト・ハウンド・ブルワーク、追加ハリアー・プリズム・バスティオン）。`types` がそのシリーズの型のキーの並びで、起動時に順にⅠ型・Ⅱ型・Ⅲ型と名前が付く。`set` はセットボーナス |
| `PART_VARIANTS` | ACの採用型÷基準型の比。既存Ⅱ・Ⅲ型は同系統のⅠ型が基準。追加3系統は標準Ⅰ型/ACクーガーⅠ型を共通基準にⅠ〜Ⅲを生成する |
| `normMech` | 保存した機体（`localStorage` の `coreBreakerMech` と `coreBreakerBuilds`）を読むとき、その部位に無い型を標準Ⅰに戻す |
| `mechStats` | 重量・重量超過・速さ・装甲を出す（重量耐性を40kg超えるごとに1%遅い） |
| `botMech` | Bot の機体（頭・胴・腕は全型からランダム、脚は重量超過が300kg以下になる全型から。無ければ重量耐性が最大の型） |
| `buildMech` | 機体の形。各部位の `series` で選び、同じシリーズのⅠ・Ⅱ・Ⅲは同じ形を使う |
| `renderSeries` など | 機体カスタマイズの3列目（シリーズの中の型を並べ、▲▼で数値を比べる） |

今のⅠ型の値は PS4版 wiki（スウィフト＝シュライクⅠ、ハウンド＝クーガーⅠ、ブルワーク＝ヘヴィガードⅠ）の物で、写した表は `research/parts/*.md`。

**これから足す型の数値の出典はアーケード版 wiki（BORDER BREAK @ ウィキ https://w.atwiki.jp/borderbreak/ ）**（オーナーの指定 2026-10-19：PS4版は終盤に性能のインフレが大きかったので、アーケード版に合わせて移植する。PS4版の扱いはその後でオーナーが決める）。`research/parts/*.md` の値は足す型に使わない。今のⅠ型の値は変えない。セットボーナスはもともとアーケード版の表の値（`research/parts/setbonus.md`、`docs/DESIGN.md`）。

## 1. 調べる

1. アーケード版 wiki から、シュライク・クーガー・ヘヴィガードの各部位（頭・胴・腕・脚）の表を `research/arcade/parts/<部位>.md` に写す。書き方は `research/parts/*.md` に合わせ、出典の URL と取得日を書く。数値は wiki の今の値。Ⅰ型の行も写す（下の比の元になる）。
2. `research/parts/types/{head,body,arms,legs}.json` と `research/parts/types/README.md` に、各シリーズに足すⅡ型・Ⅲ型を書く。形は武器の型（`research/weapons/types/README.md`）に合わせる：`base`（本作の型のキー）、`series`（wiki の系統）、`baseRow`（元にしたアーケード版のⅠ型の値）、`types`（足す型。`label`、`trait` は一言の説明、値）、`skipped`（使わなかった物と理由）。元にする系統は本作のⅠ型と同じ系統のⅡ・Ⅲ（アーケード版に無ければ近い系統）。
3. README に、本作のⅠ型（PS4版の値）とアーケード版のⅠ型の値の差の表を付ける。調べるだけで、Ⅰ型の値は変えない（オーナーが後で決める）。

読めなかった所は「不明」と書き、推測で埋めない。wiki につながらないときは、そこで止めてそう報告する（PS4版の表や覚えている値で埋めない）。

## 2. ゲームに入れる

- 本作の値は「本作のⅠ型の値 × アーケード版の型の値 ÷ アーケード版のⅠ型の値」で決める（武器の `makeType` と同じ考え方）。ランクで書かれた性能は、wiki に書かれた実数（ランクの横の数値や対応表）で数にする。本作に無い性能（DEF 耐久など）は使わない。
- 型のキーを足す（例 `light2`・`light3`。名前は自由）。`PARTS` の4部位すべてに足し、`PART_SERIES[シリーズ].types` に並べる。
- 型のキーを固定しない：各部位の `Object.keys(PARTS[部位])` から選び、`normMech` はその部位のキーの実在を調べる。`botMech` は候補数で乱数を取り、`buildMech` は型のキーを比べない。形はシリーズ（`PARTS[部位][型].series`）か重さの区分で決めるようにし、同じシリーズの型どうしは同じ系統の形にする（細部を少し変えるのはよい。形の作り分けは Issue #4）。
- 前に保存した機体と構成がそのまま読めること（今のキーは残す）。
- セットボーナスはシリーズで決まるので、型が違っても揃えば付く（今のまま）。
- `docs/DESIGN.md` の「機体パーツと重量」「シリーズと型、メーカー」を直す。

## 3. 確かめる

```sh
# まず簡易テスト：main から増えた・変わった武器とパーツだけを試し、Bot 戦を2マップ60秒だけ回す（2026-10-20 オーナーの指定）
node tools/test/quick_check.js origin/main
# 増えたパーツを1つずつ、ほかの部位は初期のまま付け、形・重さ・装甲・部位ごとの被弾・立ち/歩き/屈みの姿勢を確かめる
```

- 全混成の `mech_shapes_check.js`（6系統で1296通り）と4マップ150秒の `bot_battle.js` は時間がかかるので、機体の形の作り方や当たり判定そのものを変えたときだけ回す。

- 機体カスタマイズで、各シリーズにⅠ〜Ⅲ型が並び、▲▼の比べと重量の棒、回る見本が正しく出るスクリーンショット。
- 前のブラウザの保存（`coreBreakerMech`・`coreBreakerBuilds`）を入れた状態で開いても壊れないこと。
- PR の説明に、全部の型の性能の表（重量・装甲・各部位の性能）と、重量超過の例（兵装ごとの初期装備で）を書く。
- 新しい物を足すだけで「任せる所」に収まる PR は、`AGENTS.md` の「自分でマージしてよい変更」の手順で自分でマージしてよい（オーナーの指定 2026-10-20）。今ある物の数値や、全部に効く仕組みを変えたら、今までどおり Claude かオーナーがマージする。

現在の追加3系統の採用記録は `research/parts/types/new-series.json`、全72パーツと重量例は `new-series-stats.md`。SP消費は固定割合で、胴の `sp/100×supply` は回復速度（2026-10-20ユーザー指定）。

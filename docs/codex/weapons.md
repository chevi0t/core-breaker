# 武器を足す手順（Codex など向け）

オーナーの指定（2026-10-19）：武器は数値を調べるだけでなく、**形（モデル）と性能まで作り込んでゲームに入れてよい**。

**数値の出典はアーケード版 wiki（BORDER BREAK @ ウィキ https://w.atwiki.jp/borderbreak/ ）**（オーナーの指定 2026-10-19：PS4版は終盤に性能のインフレが大きかったので、アーケード版に合わせて移植する。PS4版の扱いはその後でオーナーが決める）。PS4版 wiki と `research/weapons/*.md` の値は、新しく足す武器に使わない。本作に今入っている武器の数値（PS4版の値）は変えない。

## 0. 読む物

- `docs/DESIGN.md` の「武器の定義（`WEAPONS`）」の表（キーの意味）、「武器の型（`WEAPON_TYPES`、`makeType`）」「シリーズと型、メーカー」「武器の形」の節
- `research/weapons/*.md`（PS4版 wiki から写した各兵装の武器の表。本作の今の武器はこれが元）、`research/weapons/types/README.md`（型の選び方と、入れなかった物）

## 1. 調べる

1. アーケード版 wiki の各兵装の武器のページから、本作に無い系統の表を `research/arcade/weapons/<兵装>.md`（assault・heavy・raid・support）に写す。書き方は `research/weapons/*.md` に合わせ、出典の URL と取得日を書く。数値は wiki の表の今の値（調整の履歴がある物は最後の値）。
2. `research/weapons/missing.md` に、アーケード版にあって本作に無い系統を書く。系統ごとに、兵装と枠、系統名とページの URL、基本の型の数値、撃ち方の仕組み、本作の仕組み（`WEAPONS` のキー）で表せるか、新しい仕組みが要るか。最後に足しやすい順のまとめを付ける。
3. 同じ `missing.md` の終わりに、本作に入っている系統と型のうちアーケード版に無い物（PS4版だけの物）を一覧にする。調べるだけで、ゲームからは外さない（オーナーが後で決める）。

読めなかった所は「不明」と書き、推測で埋めない。wiki につながらないときは、そこで止めてそう報告する（PS4版の表や覚えている値で埋めない）。

## 2. 1つの系統を足す（`prototype/index.html`）

名前で検索して場所を探す（行番号は変わる）。足す所：

| 所 | 書くこと |
|---|---|
| `WEAPONS` | 武器のキーと定義。基本の型はアーケード版 wiki の値。定義の横のコメントに wiki の武器名と元の値を書く |
| `WEAPON_KG` | 重さ（アーケード版 wiki の値） |
| `ARMORY` | どの兵装のどの枠で選べるか。各枠の先頭は初期装備なので、先頭は変えない |
| `SERIES` | シリーズ `{ maker, types: [[武器のキー, 型番], …] }`。型番はオリジナル（英大文字2つ＋数字、例 `SR-7`）。メーカーは `MAKERS` の5社から、得意な物に合わせて選ぶ（シルフ精機＝軽く速射の効く銃と刃物、ガルド重工＝重く頑丈な実弾兵器、ルミナ技研＝エネルギー兵器と高出力の装置、ボルカ火工＝爆発物と設置物、アイリス電子＝索敵・迷彩・修理） |
| `WEAPON_TYPES` | 型（1系統4つまで、基本の型を入れて）。`w0` がアーケード版 wiki の基本の型の値、型もアーケード版の同じ系統の表から選ぶ。`types` が `[名前, 値, 一言の説明]`。値は `makeType` が「本作の基本の値 × wiki の型の値 ÷ wiki の基本の値」で本作の数値にする。新しいキーの比を取るなら `makeType` に足す |
| `MODEL_OF` | 形 `[形の系統, 型（0・1・2）]`。合う形が無ければ 3. で作る |
| `SFX_TUNE` | 射撃音 `[音の名前, 高さ]`。音は今ある13個（`SFX`）から選び、高さで聞き分けられるようにする |
| `wStats`・`itemNums` | 新しいキーを足したら、機体カスタマイズの説明と数値の比べの行も足す |
| 操作説明（`pgHelp`） | 使い方が新しい物（溜め、設置など）は説明を足す |

画面に出す名前は「型番＋武器の種類の名前」（例「SR-7 アサルトライフル」）。wiki の武器名・系統名は画面に出さない（コメントと `research/` だけ）。

## 3. 形（モデル）を作る

- 武器の形は `buildWeaponGeo(形の系統, 部分)` が作る。箱・円柱・球を組み合わせて頂点の色で塗り、1つの形にまとめる。型（0・1・2）で差し色（`palette`）と細部を変える。
- 新しい系統の形を足すときは、今ある形（`ar`、`gatling`、`sniper` など）の書き方に合わせる。デザインはオリジナルで、元のゲームの武器に似せない。
- 銃口（`muzzle`）は形の先端から取る。二丁の武器は左手の `gun2` にも同じ形が付く。背中の装置・投げる物・設置物も同じ関数で作る。
- 形は当たり判定にも入る（持っていない形は `castFrom` が飛ばす）。大きすぎる形は弾を止めてしまうので、今の形と同じくらいの大きさにする。

## 4. 新しい仕組みが要るとき

今のキー（連射、3点射、単発、溜め、横一列の散弾、炸裂する弾、爆風、設置物など）で表せない撃ち方は、`WEAPONS` に新しいキーを足し、`gunTick`・`shot`・`fire`・`blast`・設置物の処理（`gadgetUpdate`）などで読む。

- 無くてもよいキーにし、ほかの武器の動きを変えない。
- Bot も使えるようにする（主武器は `botUpdate` の撃つ所、副武器・補助・特別は `botAct`）。
- キーの意味を `docs/DESIGN.md` の「武器の定義」の表に足す。

## 5. 確かめる

```sh
python3 tools/test/make_dbg.py dbg
node tools/test/weapons_check.js dbg                        # 全武器を撃って、弾が出て当たるか、エラーが無いか
node tools/test/bot_battle.js dbg city,wide,mesa,dock 150   # Bot が新しい武器を使って「エラー なし」
```

- 機体カスタマイズで、新しい系統が3列目に型ごとに並び、数値の比べ（▲▼）が出ることをスクリーンショットで確かめる。
- 強さの目安：同じ枠の今の武器と、秒間の威力（`dmg × rpm ÷ 60`、散弾は粒の数を掛ける）、弾の総数、重さを並べた表を PR に書く。飛び抜けて強い物（例：マグナムの強装型は強すぎるとオーナーが言い、0.85倍にした）は理由を書く。

## 6. PR

- 系統が多いときは、まとまり（兵装ごと、仕組みごと）で PR を分けてよい。どの PR にも Issue の番号を書く。
- `docs/DESIGN.md` の武器の数（「全194種」など）と、増えたシリーズの説明を直す。
- PR の説明：足した系統と型の一覧（本作の名前と wiki の名前の対応）、強さの表、確かめたこと。

# #1 マップ：自動生成のルーチンを作り、新しい地形と戦場をゲームに入れる

## やること

オーナーがマップ作製のルールとして渡した設計書 `docs/codex/mapgen.md`（非対称・複層型対戦マップ 完全自律生成ルーチン設計書）のとおりに、マップの自動生成のルーチンを作る。それで作った新しい地形1つと、戦術の違う戦場3つ以上をゲームに入れる。

今のエンジンでのマップの書き方と確かめ方は `docs/codex/map.md`。今の作りと設計書の合わせ方（点対称、複層、対戦の数、Bot、登録）は、同じファイルの「自動生成の設計書との合わせ方」にある。

オーナーの指定（2026-10-19）：**テーマ・名前・大きさ・人数・試合時間・プラントの数と配置・地形・施設の置き場所から、Bot の通り道と動き方（Bot のルール）まで、作る側（ルーチン）が決めてよい**。決めたことと理由を `mapdesign/<id>/README.md` と PR の説明に書く。

設計書 §11 の段階（1〜8）ごとに PR を分けてよい。どの PR にも #1 と段階の番号を書く。

今あるマップ（台地演習場＝5対5の台地、広域演習場＝10対10の演習場、丘の市街地＝10対10の川と城のある街、港の倉庫街＝2対2のコスト制）と似すぎないテーマにする。

## 守ること

- `prototype/maps/RULES.md` で「ユーザー指定」と書いた決まり（`docs/codex/map.md` の冒頭にまとめた）を、自動生成のマップにも守らせる。点対称だけは設計書に合わせて外してよい。
- 名前はオリジナル。元のゲームのマップ名・地名・形はそのまま使わない。
- 道路・広場・住宅地は平らに（`paved`）、起伏は `tools/gen_rough.py` で付ける。
- Bot もプレイヤーと同じルールで動く（敵の情報は見えた物・索敵・レーダーだけ）。エンジン（地形の読み込み、`botUpdate`、速い対戦の仕組みなど）を変えるなら、新しい項目が無い今の4マップの動きを変えない。
- 試合数が足りないうちは「勝率未確定」と書く。動かしていない推定の値を、対戦で測った値として書かない（設計書 §6・§11）。

## 確かめること（`docs/codex/map.md` の 5・7）

- `python3 tools/build_maps.py` が通る。
- 戦場ごとに `node tools/test/map_check.js dbg <id>` で★が無い。隠すポッドは敵陣側から0か所。
- `node tools/test/bot_battle.js dbg <id> 150` で「エラー なし」、両軍に撃破があり、プラントの持ち主が試合中に変わる。エンジンを変えたら今の4マップでも回す。
- 生成器の自動テスト（設計書 §11 の段階ごと）とその結果。
- 上から見た図と、map_check のスクリーンショットを `mapdesign/<id>/` に置き、PR に載せる。生成のシード・設定・検証の記録も `mapdesign/<id>/` に置く。

PR は Claude が確かめて承認・マージする。

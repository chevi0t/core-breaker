# 友達ルーム対戦（試験版）

同じ対戦サーバーのURLを開き、6文字の部屋コードで集まる。2〜20人で開始でき、青10機・橙10機の不足枠をBOTが埋める。参加順に青・橙を交互に割り当てる。

## 起動する

Node.js 22以降と、PlaywrightのChromiumが動くLinux/Windows/macOSが必要。

```sh
cd online
npm ci
npx playwright install --with-deps chromium
npm start
```

ブラウザで `http://localhost:8080` を開く。同じLANの友達には、このPCのLANアドレス（例：`http://192.168.1.10:8080`）を伝える。ファイアウォールでTCP 8080を通す。

1. 最初の画面で名前・機体・武器・猫を選ぶ。
2. 「オンライン対戦」→「部屋を作る」。表示されたコードを友達に伝える。
3. 友達も**同じサーバーのURL**を開き、コードを入力して「参加する」。
4. 「準備完了」を押した時点の名前・兵装・装備で参加する。全員が「準備完了」にしたら部屋主が「試合開始」。空き枠にはBOTが入る。
5. 試合後は「オンラインの部屋へ」から、部屋主が「次の試合を準備」。

試合中の退出・切断では、その機体をBOTが引き継ぐ。部屋主が退出すると、残った参加者へ部屋主を移す。全員が退出すれば試合と部屋を破棄する。Escでマウス固定を解除でき、右上の「オンラインの部屋へ」から退出できる。

### 設定

| 環境変数 | 初期値 | 用途 |
| --- | --- | --- |
| `PORT` | `8080` | HTTP・WebSocketの共通ポート |
| `HOST` | `0.0.0.0` | 待受アドレス。自分だけで試すなら `127.0.0.1` |
| `MAX_ROOMS` | `2` | 同時に作れる部屋数。1部屋ごとにサーバーで20機を動かす |
| `CHROMIUM_PATH` | Playwright付属版 | 既存Chromiumを使う場合の実行ファイル |

Chromiumが動くメモリとCPUが必要。描画のGPUがないサーバーでもSwiftShaderで動くが、BOTと当たり判定の計算負荷はある。まず1部屋から実機で負荷を測る。

### Dockerで起動する

リポジトリのルートで実行する。

```sh
docker build -f online/Dockerfile -t core-breaker-rooms .
docker run --rm -p 8080:8080 --shm-size=1g -e MAX_ROOMS=1 core-breaker-rooms
```

### インターネット越しに遊ぶ

上のサーバーを常時動かせるPC/VPSへ置き、同じURLへ全員が接続する。HTTPSのリバースプロキシを前段に置く。例：Caddyの設定。

```caddy
play.example.com {
    reverse_proxy 127.0.0.1:8080
}
```

CaddyはWebSocketの接続も転送する。ドメインのDNSをサーバーに向け、TCP 80/443を通す。別のプロキシを使う場合もHostヘッダーとWebSocketのUpgradeを転送する。ブラウザはHTTPSから自動的にWSSへ接続する。

この実装を追加するだけでは公開URLは発行されない。既存の静的な公開ページや配布zipには対戦サーバーがないため、そのままではオンライン対戦できない。

## 今回の範囲

- 部屋コードでの作成・参加、準備完了、部屋主によるマップ選択・開始・再戦。
- 丘の市街地、広域演習場、潮路搬送区の3配置。すべて10対10。
- サーバー側で移動、射撃、反動、ロックオン、被弾、占拠、施設、出撃、BOT、勝敗を計算。
- 参加者はキー・マウス・武器変更などの操作だけを送る。座標・耐久・ダメージの申告は受け付けない。
- クライアントは20Hzの状態を受け取り、機体の位置を補間して描画。照準はマウス入力を即座に反映し、サーバーが処理した入力番号で整合させる。
- 既存のオフライン対戦と設定保存は継続して使える。

## 現時点の制限

- 試合開始後の途中参加・切断後の再接続は未対応。部屋が待機画面へ戻ってから入り直す。
- アカウント、公開マッチング、観戦、チームの手動変更、ルームのパスワードは未実装。部屋コードは友達にだけ共有する。
- 移動の巻き戻し予測と遅延補償は未実装。遠距離のサーバーでは、移動・被弾に通信時間ぶんの遅れを感じる。
- サーバーの処理能力や回線が足りない場合は同期が遅くなる。20接続の動作試験と、インターネット経由で20人が遊んだときの快適性評価は別に行う。
- サーバーを再起動すると部屋と試合は消える。戦績は永続保存しない。

## 確認する

```sh
npm test --prefix online
node tools/test/online_rooms_check.js
```

後者はリポジトリのルートで実行。実際のHTTP/WSサーバーとChromiumを起動し、2つのブラウザと18接続で20人の枠、BOT引継ぎ、操作の分離、対人射撃、撃破、再出撃、両陣営の勝敗、再戦を確かめる。`CHROMIUM_PATH`も利用できる。

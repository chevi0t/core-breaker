# マップ制作ルール（コアブレイカー）

マップを作る人（人でもAIでも）が守る決まりと、作ってから公開するまでの流れ。ファイルの書き方の細部は [README.md](README.md) にある。
「ユーザー指定」はユーザーが決めたもので、変えるならユーザーに確かめる。「仮決め」はClaudeが決めたもので、理由があれば変えてよい。

## 1. 流れ

1. **頼む**：マップの依頼や直しは「マップ作製」のスレッドに書く（ユーザー指定、2026-10-18）。ゲーム本体（index.html）は「ボーダーブレイクPC再現」スレッドの担当で、マップ作製側は触らない。
2. **書く**：`prototype/maps/<id>.js` に1マップ1ファイル。`<id>` は英小文字・数字・_。
3. **組み立てる**：`python3 tools/build_maps.py`。必須項目、プラントIDのつながり、座標の範囲、地形の種類を確かめ、通れば `prototype/maps.js` を作る（maps.js は手で直さない）。
4. **確かめる**：`tools/test/map_check.js` で施設の置き場所、ポッドの見え方、再出撃位置、カタパルトの着地点、スクリーンショットを見る（使い方は README の「確かめ方」）。
5. **公開する**：公開ページは1つ（https://claude.ai/artifact/EBViVFVaYZFHUNuuF3bBPF）。公開ページの maps.js を出すのはマップ製作のスレッドだけで、エンジン側は maps.js を出さない。名前は「マップ：〇〇」。手順は README の「公開」。
6. **配る**：zip の版番号は本体側が付ける。マップだけで配るときは `<今の版>-map<n>`（例 0.10.1-map1）。
7. **Codex が作るとき**（ユーザーが GitHub + Codex を決めた、2026-10-19）：リポジトリ https://github.com/chevi0t/core-breaker の Issue で頼み、Codex は PR で `prototype/maps/<id>.js` と `maps.js` を出す。PR では 3・4 の結果（build_maps と map_check の出力）を書く。自動生成のルーチンは mapgen.md §11 の段階ごとに PR を分けてよい。Claude が見てマージし、`tools/repo_sync.py from-repo` で共有フォルダへ写してから、5 の公開はマップ製作のスレッドがする。
8. **エンジンの変更が要るとき**（新しい地形の種類、新しい施設、11機以上の陣営など）は、マップ作製側から本体側に頼む。

## 2. 全体の形

| 決まり | 中身 | 出どころ |
|---|---|---|
| 点対称 | 自軍（青）は +z 側、敵軍（橙）は -z 側。地形・障害物・施設は自軍側の半分を書くと、敵側は中央 (0, 0) をはさんだ反対の位置に自動で置かれる。プラントとプラントのポッドは全部書く | エンジンの仕様。市街地マップも「まず左右同じ」（ユーザー指定、2026-10-18）。左右で違うマップは後で別の版として。例外：Codex の自動生成のマップ（docs/codex/mapgen.md、ユーザーが渡した設計書、2026-10-19）は非対称でよく、両側を書く項目をエンジンに足してよい。今の4マップは点対称のまま。非対称でも隠したポッド・再出撃46〜52m・カタパルトで中央へ直行しない・道路は平らは守る |
| 向き | 自軍から敵ベースを見て、左が -x、右が +x | エンジンの仕様 |
| 人数と時間 | 5対5は5分、10対10は10分。1陣営は最大10機 | 仮決め（元のゲームに合わせた）。10機を超えるのはエンジン側の仕事 |
| 大きさの目安 | 5対5で 270m×480m、10対10で 360m×600m 前後 | 今ある2マップ |
| 名前 | 公式のマップ名・地名は使わない。参考にするのは作りの考え方だけで、形や配置をそのまま写さない | ユーザー指定 |
| 外周 | 外周の壁は自動で付く | エンジンの仕様 |

## 3. ベース

| 決まり | 中身 | 出どころ |
|---|---|---|
| 平らな土地 | ベースの境目（`baseLine`）より奥は、地形を書いても平らになる | エンジンの仕様 |
| カタパルト | 各ベースに左右2基ずつ。ベースの台で中央のプラントへ直行させない（中央へ一気に飛べると、脇のプラントの値打ちが無くなる） | 左右2基ずつはユーザー指定（v0.9.2）。直行させないのはユーザーの指摘（2026-10-18、丘の市街地「拠点Cにいきなり飛べるのでB,Dの重要性がものすごく低い」）。着地点は仮決め |
| レーダー | 各ベースの左奥に1つ。壊れていない間、境目より奥に入った敵を知らせる | ユーザー指定（v0.9.3） |
| 防衛砲台・ポッド | ベースの前に砲台（5対5で2基、10対10で4基）、ベースの中にリペアポッド2基 | 仮決め |
| コアの傘 | エンジンが付ける。マップには書かない | エンジンの仕様 |

## 4. プラント

| 決まり | 中身 | 出どころ |
|---|---|---|
| 書く順と持ち主 | 自軍ベースに近い順に書く。いちばん自軍寄りは最初から自軍、いちばん敵寄りは敵軍、ほかは中立 | 今ある2マップの形 |
| 占拠の円 | 半径16m。円の中に障害物を置かない | エンジンの値 |
| 再出撃の場所 | プラントの中心から自軍ベース側へ46〜52m（エンジンが決める）。その場所が崖の上、障害物の中、川の底にならないようにする。真ん中に降ろすのは守りやすすぎるので不可 | ユーザー指定（v0.9.2、「激戦ド真ん中に降ろされる」と言われて遠ざけた） |
| 隠れたリペアポッド | いちばん自軍寄り・敵寄りのプラントのポッドは、プラントの後ろ（自軍ベース側）の高さ5mの土手と深さ2mの窪地に置き、敵陣側から見えないようにする。map_check で見える場所が0か所になるまで直す。形の見本は台地演習場のA（`block` 2つと `trench` 1つ） | ユーザー指定（v0.9.2） |
| ポッドの使い方 | ポッドを使っている間は動けない（リペアユニットだけ使えて効果が重なる） | ユーザー指定（v0.9.3） |
| 誰でも使える | カタパルトはどの陣営の物でもなく、誰でも（敵も）使える。プラントIDはBotが使う台の目印だけ。敵側では点対称の位置のプラントに付く | ユーザー指定（v0.10.5） |
| カタパルトの着地 | 書いた着地点から6m以内に降りること（map_check で★が付いたら直す）。着地点の手前に高い物を置かない | 確かめ方の基準 |

## 5. 地形と障害物

- 使える地形は `mesa`（平らな盛り土）、`block`（崖で囲まれた高台）、`ramp`（z の向きの坂）、`hill`（なだらかな丘）、`trench`（谷・窪地。幅を広く奥行きを短くすれば横向きの川にもなる）。種類を足すのはエンジン側。
- 下をくぐれる橋・高架は `bridges`（板）で作る。下を通すなら板の底と地面の間を5m以上空ける（機体は高さ4m）。橋脚は `layout` の箱で書いてよい（v0.10.4）。橋の床の上に置く通り道の節点には高さ y を書く（README）。水は `water`（見た目だけ）。
- 建物には見た目の種類を付ける（家 `'house'`、壁 `'wall'`、塔 `'tower'`）。仮決め（灰色の箱だと街に見えないため）。
- 戦場を真っ平らにしない（ユーザーの指摘、2026-10-19「全体的に地面が平面だから横エイムだけでヘッドショット入っちゃう」）。平らな所には `tools/gen_rough.py <id>` でゆるい起伏（高さ1.5〜4mの小山と深さ1〜2.2mのくぼみ）を敷く。地形やプラント・ポッド・カタパルトを動かしたら作り直す（`--seed` で別の並びになる）。目安は、30〜150m離れた2点の地面の高さの差が1m未満になる組が4割ほど（以前は5〜7割）。
- ただし道路・住宅地・舗装した広場は平らのまま（ユーザー、2026-10-19「道路とか住宅地とかはデコボコしてたら不自然なので、そこらへん区別しないといけなかった」）。家（'house'）の周り6mは gen_rough が自動で空ける。道路や広場はマップに `paved: [[x0, x1, z0, z1], …]`（自軍側、エンジンは読まない）で書く。町のマップは高低差を丘・城・川などの地形で作り、起伏は空き地だけ。
- 傾きが1.1（約48°）を超える斜面は登れない壁。ジャンプは約4.3m。崖の高台は必ず自軍側から登れる坂を付ける。
- 障害物は箱 `[x, z, 幅, 奥行き, 高さ]`。斜面では低い側まで埋まる。上に乗れる。壊せる壁（バリケード、耐久30000）は別の項目。
- 施設・ポッド・カタパルトは置いた所の地面に乗る。障害物の中や崖の途中に置かない（map_check で★）。

## 6. 作りの考え方（ユーザーの希望、2026-10-18）

ユーザーが目指すマップは「高低差があって都市に見えて、ボトルネックになる激戦区と迂回ルートがあって、プラントとカタパルトの配置次第でバリエーションを増やせる」もの。

- **激戦区**：両軍の最短路が通る場所を1つ作り、そこに中央のプラントを置く。入り口は2〜3本に絞る。
- **迂回ルート**：激戦区を避けて回れる道を左右に。片方は高い所（遠回りだが見下ろせる）、片方は狭い道（近距離向き）にすると性格が分かれる。迂回路は激戦区より2〜4割長いくらい。
- **高低差**：低い所・地上・高台の3段くらい。段の間は坂、高い通路、カタパルトでつなぐ。
- **配置違い**：同じ地形で、プラントとカタパルトの置き方だけ変えた版を作れるようにしておく（版の名前は「〇〇 〜副題〜」）。
- 行き止まりを作らない。障害物や崖で目標へまっすぐ行けない所がある地図には、Botの通り道 `nav` を書く（書き方は README）。map_check の「6. Botの通り道」で★が無くなるまで直す。

## 7. 本体側に頼んでいること

v0.10.3 で Botの通り道（`nav`）、建物の見た目、配置違い（`variants`）、くぐれる橋（`bridges`）、水面（`water`）が入った（書き方は README）。
v0.10.9 で入ったもの（2026-10-18、港の倉庫街のため）：`vs: { cost, death }` があるマップはVS風のコスト制にする。コア・傘・砲台・レーダー・ベースの境目の警報を出さず、コアの耐久の代わりに両軍の戦力ゲージ（`cost`）を出し、撃破されるたびに `death` 減らし、0以下になった側の負け（時間切れはゲージの多い側の勝ち）。再出撃は自軍の出撃位置、Botは一番近い敵機を狙う。コストが `death` より少ない時の再出撃は耐久が 残り/`death` 倍（コストオーバー）。今頼んでいるものは無い。

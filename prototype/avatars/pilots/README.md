# パイロット4状態の静止画置き場

キャラごとに独立したPNGを4枚配置します。動画・アニメーションPNG・スプライトシートは不要です。MOSS4の4状態切替をローカル実装済みです。既存の `../cats.png` と猫表示は維持し、未納入フォルダは読込みません。PNGを置くだけでは自動反映されず、下記の埋め込みとキャラ登録が必要です。

## 配置

```text
prototype/avatars/pilots/
  tabby/               # キャラID。例：既存キジトラ
    normal.png
    boost_left.png
    boost_right.png
    damage.png
```

| 状態キー | ファイル名 | 用途 |
| --- | --- | --- |
| NORMAL | `normal.png` | 通常の顔 |
| BOOST_LEFT | `boost_left.png` | 機体自身の左方向へブーストしたとき |
| BOOST_RIGHT | `boost_right.png` | 機体自身の右方向へブーストしたとき |
| DAMAGE | `damage.png` | やられ顔・被ダメージ用 |

左右はカメラや画面の左右ではなく、機体の前方向を基準にした左右です。画像の左右反転で代用せず、それぞれ別画像を用意してください。DAMAGEは被弾表示中＋その後350ms、撃破/大破中に優先。通常の横歩きはNORMAL、実際の短/長ブーストの横成分で左右を判定。機体の左右成分が移動方向の25%以上なら斜めブーストも対応します。

## 切替対象の条件（今後の連携仕様）

- 既存キャラの画像・登録・表示はそのまま維持します。この構造を追加しただけでは置き換えません。
- `normal.png` だけのキャラは静止画扱いとし、状態によるスプライト切替を行いません。
- `normal.png`・`boost_left.png`・`boost_right.png`・`damage.png` の4枚がすべて揃ったキャラだけを切替対象にします。2〜3枚でも切替を有効にせず、未配置画像の読込や反転による穴埋めは行いません。
- 埋め込み時に4枚の存在と寸法を検査し、不足時はNORMALだけを登録します。

## 画像の規約

- 推奨は **512×512 px、RGBA、透過背景、静止PNG**。同じキャラの4枚は必ず同じ寸法にします。最終配信時に必要なら縮小・圧縮します。
- 4枚とも顔や体の基準位置、余白、縮尺をそろえてください。状態を変えたときに肖像全体が飛び跳ねるのを避けます。
- 背景・文字・HUD枠を焼き込まず、顔や必要な身体だけを収めます。ファイル名は表の小文字ASCIIで固定です。
- 元の高解像度画像や生成途中の画像はここへ置かず、採用する4枚だけを格納します。外部素材を使用した場合は既存の素材方針に従い、出典・利用条件を `../CREDITS.md` へ追記してください。

## キャラの追加・差し替え

1. 既存キャラなら該当IDフォルダへ4枚を置きます。`tabby`（キジトラ）、`silver`（サバトラ）、`black`（黒猫）、`white`（白猫）、`ginger`（茶トラ）、`calico`（三毛）、`tuxedo`（ハチワレ）、`siamese`（シャム）を用意済みです。
2. 新キャラは小文字英数字と `_` の安定したIDでフォルダを追加します。表示名はファイル名に入れません。既存IDを変更すると保存済み選択に影響するため、別IDを使ってください。
3. 4枚を揃えたら、キャラIDと画像一式を実装担当へ渡します。`.gitkeep` は空フォルダ保持用で、画像を置いた後も残して構いません。

## ゲームへの反映

`python3 tools/embed_pilot_sprites.py` で採用PNGをHTMLへ埋め込みます。通常のみならNORMALだけ、4枚完備なら4状態を登録します。画像の画素は変更しません。生成されたPILOT_SPRITESはフォルダから導出され、手編集しません。新キャラを選択肢へ加える際はindex.htmlのPILOTSへ表示名・説明を登録します。MOSS4は登録済みです。既存BOTの猫割当8種は維持します。

`tools/embed_pilot_avatars.py` は従来の猫アトラス専用です。4状態には使いません。HTML埋め込みにより既存Pages/ZIPのオフライン表示を維持し、追加の欠損ファイル通信はありません。現在のMOSS4透過版4枚は1254角、計約7MB。圧縮・縮小は未実施で、配信HTMLはBase64分大きくなります。

# Godot版の構成

この設計はGodot版だけに適用する。ブラウザ版の実装と方針は [../docs/DESIGN.md](../docs/DESIGN.md) にある。両方の開発を続け、片方の変更を自動的にもう片方へ適用しない。

## モジュール

| ファイル | 役割 |
|---|---|
| `scripts/main.gd` | メニューから試合、共通の更新順、カメラ・入力・ロックオン、施設、設定・音声 |
| `scripts/catalog.gd` | 取り込み済みの数値・武装一覧と、セットボーナス・重量超過を含む機体性能 |
| `scripts/world.gd` | 1m地形格子、建物・橋、コア、施設、navの点対称展開とAStar、障害物の空間索引 |
| `scripts/unit.gd` | プレイヤー/BOT共通の出撃・移動・ブースト・状態・装備・ネイティブ関節表示 |
| `scripts/combat.gd` | Godotのレイによる射撃、飛翔弾、爆風、設置物、回復、大破/蘇生 |
| `scripts/bot.gd` | 視線と索敵情報に基づく目標選択、経路追従、武器・移動施設の使用 |
| `scripts/geometry.gd` | 元のオリジナル頂点をArrayMeshにし、Skeleton3D/Skinへ結合 |
| `scripts/ui.gd` | ネイティブControlによる出撃・設定・結果画面と、2D描画のHUD・ミニマップ |

3D描画・レイの衝突判定・骨による描画はGodotが担当する。移動の足場・壁判定は、まず既存の1m地形格子と箱の規則を移植している。新しいGodotシーンの任意メッシュを使う歩行は、現行対戦の再現と区別して拡張する。

## 更新順

60Hzの物理フレームで、リフト→各機の共通形式の操作→ポッド→機体の移動/装備→射出施設→占拠→レーダー/砲台→弾・設置物→勝敗を進める。描画フレームで関節表示、カメラ、HUDを更新する。設定画面の間は試合を止める。

BOTの操作結果もプレイヤーと同じ `wish / boost / jump / fire / alt / aim` を `unit.tick()` へ渡す。BOT専用の移動速度・被弾・壁抜けは設けない。

射撃はカメラの照準位置へ銃口からレイ/弾体を飛ばす。ロックは視点の追従に使用し、弾を敵の中心へ補正しない。コアの結晶だけがダメージを受け、支柱は無敵。半径26m・縁13m・頂点24mの傘は通常のレイを遮る開いた面であり、内外による特別な防護規則を持たない。

## 数値と資産

`tools/export_godot_data.js` はブラウザ版の定義を独立したVMで評価する。ゲーム本体のDOMやゲームループをGodot内で実行する方式ではない。武器・パーツ・配置をJSON、地形をfloat32の格子、元のオリジナル形状を頂点/法線/色/関節番号の配列に変換する。

同じ形状を共有する武器は同じデータを使う。機体は6シリーズ×4部位を混成できる。Godot上ではArrayMeshを再利用し、機体ごとのSkeleton3Dで表示する。関節の姿勢制御は現時点では近似で、元の足裏接地・IKと完全には一致しない。

Godotのレイ用衝突レイヤーは地形/施設が1、機体の部位Area3Dが2。射撃時は自分の部位を除外する。機体の部位衝突は当面の箱であり、元の表示メッシュそのものへの命中判定とは差がある。

比較用の機体性能は元の `mechStats` で計算した値を保存し、Godotの再計算と照合する。通常ジャンプの1/60秒での頂点は元の約6.62104mに照合する。BOT戦の勝率・戦績一致は、この機能検査の合格とは別に扱う。

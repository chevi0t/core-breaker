# コアブレイカー Godot版

Godot 4への移植作業中の版。出撃から移動・射撃・BOT戦・占拠・大破/蘇生・再出撃・勝敗までをGodot上で遊べる。**現状のブラウザ版を完全に再現するという目標は継続中**で、細部の差と未対応は [PORTING.md](PORTING.md) に記録している。

ブラウザ版も引き続き開発する。Godot版は別のプロジェクト・保存先・検証・配布として扱い、ブラウザ版の公開や開発を置き換えない。

## 起動

**`project.godot` 単体では起動できない。** これはプロジェクトの設定ファイルで、ゲーム本体や素材を含む実行ファイルではない。次のフォルダ一式を同じ場所に置く必要がある。

```text
godot/
├── project.godot
├── scenes/
├── scripts/
├── data/
└── assets/
```

1. リポジトリを取得する。PR #37が未マージの間は、`main` ではなく `codex/godot-offline-port` ブランチを選ぶ。[作業ブランチのZIP](https://github.com/chevi0t/core-breaker/archive/refs/heads/codex/godot-offline-port.zip)からも取得できる（非公開リポジトリのためGitHubへのログインが必要）。
2. ZIPの場合は**すべて展開**する。ZIPの中から直接開いたり、`project.godot` だけ別の場所に移したりしない。
3. Godot **4.6.3通常版**（C#/.NET版は不要）のプロジェクト一覧で「インポート」を押し、展開先の `godot/project.godot` を選ぶ。
4. 初回の素材インポートが終わるまで待ち、**F5でプロジェクトを実行**する（F6はシーン単体の実行）。

`godot/` フォルダ一式だけを別の場所へコピーしても動く。`.godot/` はGodotが生成するキャッシュなので、配布やコピーには不要。

「ファイルが見つからない」と出る場合は、`project.godot` と同じ場所に `scripts/main.gd`、`scenes/main.tscn`、`data/catalog.json` があるか確認する。揃っている場合は、エラーに表示されたファイル名とGodotのバージョンを確認する。

リポジトリ直下からのコマンド：

```sh
godot --editor --path godot
```

初回の素材インポート後は `godot --path godot` でも起動できる。取り込み済みのデータ・オリジナルモデル・音源を同梱しているので、遊ぶためにNode.jsやブラウザ版を起動する必要はない。

出撃画面でマップ、出撃する側、名前、猫の顔、兵装、4枠の武器、機体パーツを選ぶ。各マップの通常人数は既存版と同じ（広域・市街地・潮路は10対10、台地・白煙は5対5、港は2対2）。自軍はどちらから出ても青。50対50は潮路でのみ使えるデモ用の選択肢。

## 操作

| 操作 | キー |
|---|---|
| 移動・照準・射撃 | WASD・マウス・左クリック |
| ブースト・ジャンプ/滞空 | Shift・Space長押し |
| 武器4枠・リロード | 1〜4 / ホイール・R |
| スコープ・自己修復・遠隔爆弾の起爆 | 対応する武器で右クリック |
| 次の出撃の兵装 | Z 強襲 / X 重火力 / C 遊撃 / V 支援 |
| エリア移動・ジップライン | H・E（Space/Eで手を離す） |
| マップ・スコア | M・Tab長押し |
| 行動不能から大破へ・再出撃地点の選択 | F・再出撃待ち中のホイール |
| オプション・一時停止 | F3 / Escape |

榴弾砲は4で構え、全体マップ上の射程円内をクリックして砲撃地点を指定する。右クリックで構えを解除する。ポッドは乗って止まると修理・補給し、移動入力で離れる。使用中はリペアユニット以外の攻撃、ジャンプ、ダッシュを禁止する。

## ブラウザ版とのデータの境界

既存の武器286種・パーツ72種・マップ11配置（試験場を含む）の数値と、オリジナルの武器/機体の頂点を取り込んでいる。**登録数は挙動の完全再現や全組み合わせの検証完了を意味しない。**

取り込みを更新するときだけ、リポジトリ直下で次を実行する。

```sh
node tools/export_godot_data.js
```

変換は `prototype/` を読み取るだけで、Godot側のスナップショットを更新する。通常の起動・ビルドでは実行しない。取込元のハッシュと、既存の機体性能による比較値を `data/catalog.json` に保存する。双方の変更を相手へ取り込むかは、その都度レビューする。

Godotの設定は `user://godot_profile.json` に保存し、ブラウザのlocalStorageには触れない。`.godot/` と `builds/` はGit管理外。配布設定は `export_presets.cfg`、ブラウザ版の配布ツールとは別にしている。

## 検証

```sh
python3 godot/tests/run.py --battles all --seconds 150
```

Godotの読み込み、機体性能・移動・被弾・占拠・補給・蘇生等の機能検査、全武器の発射/状態確認、通常の全10配置でのBOT戦を行う。実行エラーは終了コードだけでなくログからも検出する。結果は `dbg/godot-validation/`。ブラウザ版の試験とは別に実行する。

描画できる環境では `godot --path godot --script res://tests/capture.gd` でメニュー・対戦画面・オプションの画像を保存できる（`GODOT_CAPTURE_DIR` で出力先を指定）。

音は [assets/audio/CREDITS.md](assets/audio/CREDITS.md) の皆さまの素材を引き続き使わせていただいている。ありがとうございます。猫・機体・武器はブラウザ版のオリジナル素材を取り込んだもの。

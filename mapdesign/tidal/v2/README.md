# ベースの外周と守備行動（途中設計）

現行は [v3の縦延長・基地非対称版](../v3/README.md)。このメモとbaseline-*は比較用に残す。

2026-10-20。ユーザーは長方形の工業港を採用した。L字への再設計は取りやめ、中央の地形・プラント・昇降設備は維持する。今回変えるのは両軍のベース周辺と、このマップが指定する守備行動。

## 問題と改善仮説

- 従来の基地は広い平地に施設を並べただけで、どこが入口・防衛線・後方施設なのか分かりにくかった。
- 守備役はidx=2/7の2機だが、既存式 `(idx % 5 - 2) * 14` は両方0になる。待機地点もコアの60m前で、当マップではベース境界の外側だった。
- `botTransfer` は守備役にも遠くの被攻撃プラントへの移動を許し、支援の味方追従も守備地点より優先していた。

基地を高さ10mの防壁で囲い、正面の左右に地上の門を残す。門からコア・補給・レーダーまでの内部動線を確保する。壁は普通の当たり判定・射線遮蔽を使い、コアや傘のダメージ規則を変えない。4基の砲台は門前と内部の侵入方向をカバーする。

2機の守備役は別々の門内側で待機し、自動判断では被攻撃プラントへ転出しない。レーダーで実際に検知した侵入者には、近いプラント役を最大2機、通常移動または既存のエリア移動で応援へ戻す。レーダー破壊中に、見えていない敵を知ることはできない。手動指示、退避・回復、蘇生は通常のルールで扱う。

この動作は任意の `baseDefense` を指定したマップへ適用する。他のマップに値を追加しない。基準の地形・旧本体・旧生成器はこのディレクトリの `baseline-*` に保存した。勝率・被害の旧記録はv1へ残し、新しい検証と混ぜない。

## 確認すること

門の往復・コアまでの進入、守備位置への到着、侵入への応答、無警報時の待機、レーダー破壊後の情報制約、守備役の転出禁止、応援の上限と解除を確認する。壁によるカタパルトの衝突、施設や再出撃域への干渉も調べる。M03/M04/M06/M11/M14を引き継ぎ、見た目だけで防衛成功とはしない。

実装・検証中。勝率未確定。

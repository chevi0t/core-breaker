# 上層Cへの前線からのアクセス不足

2026-10-20。ユーザーから「青のBからCが遠いのに、カタパルト等で到達時間を補填していないのか」と指摘を受けたため、登録中のv7を変更せず診断した。

## 設計・検査で抜けていたこと

上層干渉ではB=(-72,136,0)、C=(72,0,22)、D=(8,-136,0)。水平直線距離だけでもB→Cは198.1m、D→Cは150.3m。ただし直線は通行可能な実経路ではない。

カタパルトは全配置で共通の基地4基ずつで、着地点は自陣のA/E付近。上層配置のB→C用の台や、その移動時間に合わせた設備変更はない。プラントの選抜では高さ・数・横方向の分散を評価しており、配置ごとの到達時間差を不合格にする条件は実装していなかった。設計書 `docs/codex/mapgen.md` §4 STEP 5/6が要求する、配置に合わせた移動施設の決定と、各プラント間の移動時間評価が不足していた。

従来の[占拠検査](../final/bot-access.json)は、敵と砲台を止め、他のプラントを自軍所有にして、基地から対象1か所へ移動する機能検査。上層Cの占拠は軽量51.85秒/51.85秒、重量52.05秒/52.1秒だった（青/橙）。「基地から両軍とも占拠できた」を、前線B/Dからの合流にも拡張してしまった。Cの床への初回進入と占拠完了も分けていなかった。

## 今回の実走

`source /workspace/.cloud-setup/core-breaker/env.sh` の後、以下で再現する。ゲーム本体・マップは変更しない。

```sh
python3 tools/test/make_dbg.py dbg/access-diagnostic
node mapdesign/tidal/v7/access-diagnostic/measure.js
```

[実測JSON・毎秒の位置](results.json)、[実行ログ](run.log)。同一機体・装備・速度、軽量強襲と重量重火力。Cだけ中立、他は自軍所有、他機は退避、砲台停止、エリア移動停止。両軍とも機体番号0。各条件1走、計8走。前線中心付近（柱を避けz+3m）出発と、通常の49m後方・横振れ0の再出撃を分ける。どちらも耐久・ブースト満タン。床への到着はCから水平16m未満かつ高さ差2m未満、占拠完了は本体の所有権で測る。移動・施設・Bot判断・占拠は本体の処理を使う。

中心出発の青は軽量・重量とも途中で倉庫パッド0を利用した。橙と、両軍の後方再出撃ではこの寄り道がない。重量機の中心出発では、青は26秒の標本でC用リフトの下側乗り場付近へ到達し、橙は10秒の標本ですでに近くにいる。橙は17秒、青は34秒の標本で乗っており、青が1便遅れる。軽量は青が16秒・橙が8秒の標本で乗り場近くにいるが、両軍とも同じ便に乗り、最終到着時刻の差が隠れる。

リフトは同じ初期位置・待機状態から開始した。開始位相や出発時刻、出撃帯の横振れ・距離全域、占拠直後の残ブーストはまだ振っていない。無交戦の1条件の時刻を、最短到達時間・全条件の差・通常戦の平均・橙4勝の唯一の原因とは扱わない。特に「再出撃なら差がほぼない」はこの位相での観測に限る。

## 次に比較する修正

B側からC手前の乗降・遮蔽地点へ運ぶ前線カタパルトを第一候補にし、途中パッドへの寄り道とリフトを1便逃す条件を減らせるか調べる。ベースから中央への直行を作らず、Bを確保して前進する意味を残す。カタパルトは敵味方とも使えるため、逆侵入と着地の露出も確認する。

配置変更ごとに、基地初動、B/Dからの前進、後方再出撃からの再合流、Cからの撤退・補給を分け、機体とリフト位相を変えて計測する。設備の入口への到着・待機・乗車・離脱・Cの床への到着・占拠完了を分ける。未計測は未合格とし、機能が通った後に上層配置で同条件比較戦を行う。今回の作業ではカタパルトの追加・既存配置の変更は行っていない。

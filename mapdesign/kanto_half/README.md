# 環都駅前・8m級試験

承認済み梅田マップの街を縦・横・高さとも基本1/2にする試作。1km四方から500m四方へ縮め、本体の4m機体を変えずに、実都市に対して8m級の比率で遊べるようにした。

`play.html` をダウンロードしてブラウザで開くと、通信なしでこのマップを選んで対戦できる。元の `prototype/maps/kanto.js` と通常マップ一覧は変更しない。

## 元の案から引き継ぐもの

- 街区の外形、ランドマークの色、駅の白い傾斜大屋根、公園の芝生。建物の階数が減って見えないよう、窓とガラス面の模様の間隔も1/2にする。
- 南西・北東の2基地、5プラント、各基地のカタパルト4基・防衛砲台4基・レーダー・補給2基。
- B→C、D→Cのカタパルトと、中立ジャンプパッド6基。
- 機体・移動速度・武器・占拠半径・施設モデルは既存のゲーム本体のまま。

## 遊ぶための局所補正

縮尺だけを変えると4m機体が通れなくなるため、立体通路の天井を最低5.5m、床厚を最低1mにする。接する上部の床面もそろえる。通常ジャンプで抜けられない深い屋上穴4か所を埋める。通路を一律に潰したり、街区全体を簡略化したりはしない。

プラントは元座標の半分。占拠地点と基地に入る建物の縁だけを切り欠く。橙基地は傘が外周から出ないように3m内側へ移動。基地設備は機体の実寸に合わせて再配置する。補給所の壁は機体に合わせて高さ5mを維持する。

街路の経路は2m格子から再生成し、機体半径の余裕を加える。再出撃は縮めず、プラントから46〜52m、基地では中心から18mの安全な候補を使う。カタパルト・パッドの乗り場は、固定サイズの台を置ける位置へ必要な分だけずらす。Botが目標6m手前で止まっても屋根へ乗れるよう、3か所の屋上目標を4m奥へ移し、天井補正した1か所は出口高さも合わせる。プラント間カタパルトの飛行はB→Cが4.4秒、D→Cが3.6秒。

ユーザーが半縮尺を採用した後、両基地の設備を再配置した。コア・基地半径・街区・プラント・街中設備は同じ。補給2基をコアの左右後方、レーダーを左奥、防衛砲台4基を前と側面へ置き、カタパルトは左右2基ずつ既存の空いた街路へ分散した。設備同士の最小中心距離は青4m・橙4.47mから両軍11.66mへ拡大。カタパルトの着地先と飛行時間は維持し、再出撃候補は射出台と補給台を避ける。新配置の動線に合わせて経路を再生成する。配置確認は `base-layout-review.json`、両基地の図は `bases.png`。

処理元・寸法・補正箇所・データサイズは `generation.json`、素材の出典と謝辞は `CREDITS.md` に記録する。幾何データを縮めても情報量は半分にならないため、ファイルサイズは元の100KB以内の方針を維持する。

## 屋上の観覧車

プラントE近くの赤い上部の箱を、赤い輪・スポーク・支持脚・12個のゴンドラに置き換えた。屋根上の静止モデルをコードから生成し、外部のモデルや画像は使用しない。ゲーム内の半径14m・中心高さ43mは、街で識別しやすくするための近似寸法。土台となる建物の屋根は27mのまま維持する。

輪の内側は空洞で、透過円盤は置かない。1,400三角形を描画1メッシュへまとめ、同じ面を機体・射線・カメラの接触にも使う。旧箱の見えない壁は残さない。元データとの差分と、基地設備・プラント・経路が変わっていないことは `ferris-change.json` に記録する。

## プラントA・Eの屋上防衛

プラントAには青軍、Eには橙軍の固定所属の屋上砲台を各2基追加した。占拠地点と接近路を別々の屋根から撃ち下ろす配置とし、基地の8砲台・地形・プラント位置は維持する。各砲台の射程70m・威力・連射・破壊と修理は既存の防衛砲台と同じ。プラントを奪取しても砲台の所属は変わらない。M24（`mapdesign/LESSONS.md`）に従い、代表射線が通ることと試合全体の公平さは分けて評価する。

| プラント | 陣営 | 屋上 | 座標 `[x,z,y]` |
|---|---|---|---|
| A | 青 | 北側・高さ24m | `[-106,40,24]` |
| A | 青 | 南東側・高さ22m | `[-78,113,22]` |
| E | 橙 | 西側・高さ32m | `[57,-112,32]` |
| E | 橙 | 東側・高さ22m | `[109,-96,22]` |

配置は `rooftopTurrets: [{team,plant,at:[x,z,y],yaw}]`。既存の砲台生成処理に世界座標を渡し、追加台座には底面の高さも指定する。Aの2方向は約146度、Eは約177度離れる。生成時に台座3×3mと周囲0.15mを支持する屋根、上層建物との非干渉を検査する。変更はこの4基の配置情報だけで、`rooftop-turrets-change.json` に差分を記録した。

## 再生成と検査

Python依存は numpy、scipy、shapely 2、mapbox-earcut。Node.js と Playwright/Chromiumも使用する。

```sh
python tools/build_kanto_half.py
node tools/test/kanto_half_check.cjs mapdesign/kanto_half 150
node tools/test/kanto_ferris_check.cjs mapdesign/kanto_half
node tools/test/kanto_rooftop_turrets_check.cjs mapdesign/kanto_half
node tools/capture_kanto_half.cjs mapdesign/kanto_half
node tools/capture_kanto_bases.cjs mapdesign/kanto_half
```

HTMLは `0ef53120d4ca6a43527b103c1544dc84926254ae` のゲーム本体・音・Three.jsを埋め込み、検査用の読み口、窓模様の縮尺補正、観覧車の描画・接触用の層、屋上砲台の配置を足す。移動・戦闘のルールは変更しない。本体の版が異なる場合は生成器が停止する。

試験は実際の機体物理で徒歩、射出台、屋上移動、窪地からの復帰、再出撃、施設利用、外周を確かめ、10対10のBot対戦を行う。短い対戦は動作確認であり、陣営勝率や長期の試合バランスは未確定。

## 確認結果

最終JSONは96,387B（末尾改行を含むファイルは96,388B）。屋上砲台追加前から253B増加し、100KB以内を維持した。500×500m、都市モデル23,735三角形（砲台などゲーム施設は別途生成）。669節点・1,077辺の往復、カタパルト72条件、パッドの機体操作72条件・Bot24条件、基地から全プラントへの徒歩10経路、再出撃160回、補給・砲台・レーダー・外周が通過した。

150秒の10対10 Bot戦で68撃破、63再出撃、全5プラント占拠、カタパルト63回・ジャンプパッド1回を確認。ブラウザエラー・自動外部通信は0。詳細は `half-check.json`、画面は `overview.png` と `tps.png`。Botパッド単体は、敵砲台を見た回避ダッシュを移動不良と誤判定しないよう、敵機と同様に砲台への交戦を一時停止し、描画・当たり判定を残して24条件を確認する。通常対戦では全砲台を有効に戻している。

屋上4基は地上の敵へ下向きの弾を撃ち、初弾で約1,522〜1,585の損傷を与えた。味方への非射撃、プラント占拠後も所属固定、建物による遮蔽、破壊・支援リペアでの再始動、再試合2回での増殖なしを確認。`rooftop-turrets-check.json` に記録し、配置は `rooftop-turrets-A.png` と `rooftop-turrets-E.png` に示す。

観覧車追加時のコミット `3d43651` では、穴と外輪への両方向の射線、旧箱の壁を横切る屋上歩行、再試合2回で形状が増えないことを検査した。記録は `ferris-check.json`、近景は `ferris.png`。今回、観覧車と都市形状が変わっていないことは `rooftop-turrets-change.json` で確認している。

再配置後の基地補給4基へ実機体で徒歩往復し、補給1200回復と意図しないカタパルト射出0を確認。高層棟を挟む橙左側2番のカタパルトも、基地出撃地点から徒歩で5m以内へ到達する。記録は `base-walk-check.json`。この基地検査と `base-layout-review.json` は観覧車追加前のコミット `8294107`、`independent-geometry-check.json` はそのファイルに記載された地形版の記録であり、今回変更していない部分の検証として引き継ぐ。

# マップ設計の知識台帳

次のマップを作る前に読む。狙った戦い方が成立しなかった理由と、次回の生成・検査で確かめることを蓄積する。原設計書 `docs/codex/mapgen.md` の方針そのものと、その方針を十分に検証できていない実装を混同しない。

記録は「仮説 → 観測事実 → 解釈の限界 → 次の設計・検査 → 採否と証拠」の順で残す。古い失敗も削除せず、改善で否定された仮説は結果を追記する。結果にはエンジン・地形・配置・検証器の版、seed、試合数、初期編成、変更した要素を付ける。以下のIDは後続マップでも引用する。

## 次の生成で使う確認順

1. 狙う交戦と、前進・迂回・撤退・補給・防衛の経路を先に定義する（M03/M06）。最短路と退避路が同じ長い射線に晒されていないかを見る。
2. 高さと施設を含む接続を実物理で通す（M01/M02）。通常歩行の経路と特殊移動を区別し、両軍・複数機体で確かめる。
3. 施設の安全性と、各陣営が所有した場合の再出撃位置を検査する。プラント座標だけでアクセス条件を比較しない（M03）。
4. 編成入替と同じ初期状態で対照比較し、直接攻撃・大破・目標の変化を分解する（M04/M05/M07）。勝敗だけを最適化しない。
5. リプレイで「想定した経路が利用されたか」を確認する（M06）。利用・生還を測っていなければ、その効果は未確認と書く。
6. 採用・棄却の両方を実験記録へ残し、次の試作では別seed・未使用の編成でも試す。原設計書の200〜2,000戦・複数戦術による最終選抜は別段階。

## 新しい実験を追記する形

各 `mapdesign/<id>/<版>/README.md` に、日付・仮説・基準版と候補版・変更/固定した要素・実測値・目視場面・採否・未解決点・次回の検査を書く。この台帳には他のマップでも使える結論とその証拠リンクだけを追加し、個別の勝ちseedや座標を普遍的なルールにしない。

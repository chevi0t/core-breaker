# 星路西街区・対戦試遊版

2026-10-24。オーナーが承認した配置案01を立体化し、その後の「この地形で試しに遊べるところまで進める」という指示で対戦用の試作にした。既存の星路駅前を置き換えず、新しい定義`hoshimichi_west`と単独試遊HTMLを生成する。公開ページ・配布ZIP・同梱済みmaps.jsは変更しない。

## 反映したもの

- 700×350mの進入範囲、半縮尺と8m級相当の比率、元の背景900×550mを維持。
- 基地は青(-307,122)、橙(307,-122)。コア、防衛砲台各4基、レーダー各1基、補給各2基、カタパルト各4基を設置。基地設備を左右・前後へ分散する。
- プラントはA(-200,95)、B(-100,5)、C(35,45)、D(100,-45)、E(245,-50)。Aは青、Eは橙、B/C/Dは中立。基地・占拠円・補給室の周辺だけ建物を切り欠く。切り欠いた下層の上に上階だけが残らないよう、一般建物は同じ範囲で上階も整える。
- Dの円外の余白にかかる色付き建物の角約0.96m²は、そのまま保持する。半径16mの占拠円には入らず、ランドマーク全体の位置・色・形は変えない。
- 道路橋2か所を単純な薄い板へ近似。上面は高さ0mで両岸につながり、下面と側面にも同じ形の接触を使う。川全体を埋める処理は行わない。
- A/Eの後方には深さ2mの窪地、歩行用の斜面、前・両側の高さ5mの遮蔽を設け、補給ポッドを配置。入口側は機体の外周が当たらない余白を確保する。
- 基地カタパルトは高角5.2秒。着地点と飛行中の機体寸法を確認し、屋根へ途中着地していた候補を除く。中央Cへ直接降りない。操作禁止時間・ブースト・機体の物理は既存の規則を使う。
- 両軍各プラントの46〜52m後方帯に安全な再出撃点を生成。地上経路は斜めの角抜けを除外し、施設・橋を組み上げた本体でも接続を確認する。

生成されたJSは98,680Bで、施設・再出撃点・経路を含めて100,000B以内。地形JSONは93,070B。承認前の地形JSONと配置案は元資料として上の階層へ残す。

## 確認範囲

`battle-check.json`に実機体による確認を記録する。占拠円内の空き、出撃候補、橋の往復、190節点・384本の全経路の歩行、8基のカタパルトの着地、補給室の出入り、補給と占拠を検査する。A/Eの補給は敵陣側の地上からそれぞれ22点・26点を調べ、見える点は0だった。

通常HTMLではW・Shift・Space・Mの実入力とWebGL描画、追加HTTP通信がないことを確認する。BOT戦の撃破・コア攻撃とエラーの有無は`verification.json`へ記録する。これは動作確認で、陣営勝率や長期のバランスを保証する試験ではない。

## 外観と、まだ検証していないもの

ユーザーの指摘どおり、建物と高架の見た目の取り合い、区画単位の単純化、場外背景の巨大な塊は未整理。今回の試遊版では地上経路と射出・補給などの動作を優先した。高架・屋上の全線移動や全路地の退出を確認済みとは扱わない。次に地形を再構築する際は、この3点を俯瞰と機体視点で確認してから施設配置へ進む。

## 再生成

```sh
python3 tools/build_hoshimichi_west_battle.py
python3 tools/build_maps.py --check prototype/maps/hoshimichi_west.js
node tools/build_hoshimichi_west_battle.cjs /tmp/hoshimichi-west-battle.html
node tools/test/hoshimichi_west_battle_check.cjs /tmp/hoshimichi-west-check
node tools/test/hoshimichi_west_play_check.cjs /tmp/hoshimichi-west-check
node tools/test/bot_battle.js /tmp/hoshimichi-west-check/dbg hoshimichi_west 150
```

Python依存は`tools/requirements-city-map.txt`。単独HTMLは本体・地形・Three.js・音・クレジットを内包し、追加の地形ダウンロードを必要としない。公開用のmaps.jsは、登録作業時に`build_maps.py`で生成する。

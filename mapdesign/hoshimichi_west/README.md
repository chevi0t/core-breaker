# 星路西街区・半縮尺地形案

2026-10-24ユーザー指定。等尺600m四方の秋葉原を新御茶ノ水方向へ延長し、進軍方向へ長い長方形にする。今回は地形と進入範囲の確認段階で、基地・プラント・カタパルトを確定しない。既存の星路駅前や通常ゲームへの登録は変更しない。

## 地形の案

- 詳細な戦場候補は実寸1,400×700m、縮尺1/2で700×350m。中心は経度139.77008・緯度35.6986、地理上の東西を長辺にする。
- 外側に実寸200mずつの背景を足し、取得範囲は実寸1,800×1,100m、表示は900×550mとする。
- 現行の秋葉原駅周辺600m四方を含み、西側へ延長する。建物・道路・川・鉄道の連続性を確認する。街の縦横高さを1/2とし、現行4m機体が現実の8m級に相当する。
- 直線道路の長い射線を折るため、東西の座標に応じて南北へ緩くずらす案と、変形前を比較できるようにする。変形は地面・建物・鉄道・川へ共通に適用する。
- 背景は街並みの外形と色を優先し、細部・通行経路は保持しない。詳細側では建物間を充填せず、元の道路と路地を残す。容量は地形100,000Bを目標に実測する。施設とBot経路の予算は次段階で別に確認する。
- 進入可能範囲と描画範囲を分ける。今回の俯瞰では候補枠を示す。近づいた場所だけに黄色い壁を出す機体共通の接触処理は、本体へ接続する段階で実装・実走検査する。

## 確認の順序

広域PLATEAU取得 → 半縮尺と街区の軽量化 → 地形/進入枠の俯瞰確認 → 基地位置の確認 → プラントと移動設備の確認 → 本体接続と実機体/Bot対戦。

M19/M29（高所への到達と退出）、M30/M31（射出後の操作と水平慣性）は本体接続時の検査対象。半縮尺での路地幅と高架の天井高も実機体で検査する。今回の表示確認だけを通行・対戦の検証済みとは扱わない。

外部素材の出典・利用条件と加工内容はCREDITS.md、入力はresearch/maps/hoshimichi-west-sources.json、取得ハッシュはsource-manifest.jsonへ記録する。

## 確認結果

地形JSONは99,456B（末尾改行込み）。表示範囲900×550m、進入範囲案700×350m、建物等1,954体積。戦場候補を実寸1,400×700mとして、背景まで含め実寸1,800×1,100mを取得した。元の秋葉原600m四方と新御茶ノ水の参照点を範囲内に含む。境界や地面を含む地形単体の値であり、これから配置する施設・Bot経路を合わせた最終容量の保証ではない。

千代田区・台東区だけの初回取得では北西に欠測が残ったため、文京区の建物LOD1・道路・橋梁も追加した。全208タイルを取得し、座標と公表タイル範囲を照合した。最大の標高範囲差は約0.058mで、取得器の0.2m基準を満たした。

建物の輪郭と高さの整数列をまとめて保存し、元の街区の細部を残したままJSONの繰り返しを省いた。現行秋葉原の赤・青・黒・白・ライム色など19個のランドマーク参照形状を使って、重なる棟の色を引き継ぐ。背景だけを実寸120m区画の単純な棟へ寄せた。地形の元座標は保ち、共通の変形ルールを表示時に適用する。長い高架と地面は描画時だけ分割し、別々の補間で道路や建物からずれることを防ぐ。

保存形式は`city-layout-v1`の輪郭・保存面と互換のある内容だが、`volumes`の外側だけを`volumeEncoding:kind-u8-color-u8-y01-i16-rings-u16`で保存する。この新しい整数列の読み取りと長方形の進入境界を通常本体へ接続する作業は未実施。既存の`hoshimichi`、`kanto`、本体・配布物を変更していない。

確認用HTMLは単体・オフラインで開ける。13項目のプレビュー検査で、保存件数、有限値、描画範囲、元の街の包含、参照点、文京区側の建物、色、共通変形と復元、長い板の分割、実描画を確認した。ブラウザエラー0、追加のHTTP通信0。画像はoverview.png（通りを曲げる案）とoblique.png、記録はpreview-check.json。

これは地形確認案。ゲームの機体での通行、細路地の幅、高架下の天井、川からの復帰、境界での接触・近傍警告壁、施設配置とBot対戦は次段階で検証する。

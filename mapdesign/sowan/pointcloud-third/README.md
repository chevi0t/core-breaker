# 双湾展示区・点群による実寸1/3の地形確認版

点群と地理院の建物輪郭から再構築した地形の確認モデルです。ユーザー確認済みの**実寸1/3**、回転40.7度。元の39区画へ北側14区画を追加し、外接範囲は約1330×709mです。

現在は地形確認段階です。基地・プラント・カタパルト、ゲームへの登録、実機体の移動・落下・脱出、BOT対戦は未検証です。PR #64の旧半縮尺マップはまだ差し替えていません。旧案の試験結果を、新しい地形の試験結果として扱わないでください。

## 取得・再構築した内容

- 最初の添付 `filelist.txt` は39件。追加14件と合わせて53区画、公式ZIP合計4,070,402,119バイト、LAS合計7,626,419,316バイト、224,304,636点です。原LASは順番に読み、実寸1m格子へ地表・最高標高・撮影色を集約します。ゲーム用モデルに原LASを同梱しません。
- 北側は、真北ではなく「俯瞰図の上側」。元の取得範囲を実寸300m（ゲーム100m）上へ掃引し、取得できた区画で切り出しました。海上4区画のURLは403で取得できず、海側の端を抑えたため外接範囲の北端増分は約89ゲームmです。元の座標原点を固定しているので、主要建物が拡張に伴って移動することはありません。境界で切れていた建物は、追加データで外周がつながります。
- 地理院の建物輪郭502件を高さと照合。地面しか観測できない63件は高い箱にせず空地にし、点が欠損する1件はPLATEAUの高さを補助資料として使用しています。
- 普通の建物は外周と主要な屋根の段差で表し、囲まれた小さな屋上穴を残す内周は埋めています。道路・水面の輪郭を保ち、プラント位置による地形の切り欠きは行っていません。
- 会議棟の逆四角錐と門状ビルの貫通アーチは、点群で測れた屋根の位置・向き・主要寸法と、外観写真を合わせた独自の簡易形状です。今回も特殊メッシュと確認視点の座標は前稿と同一です。点群で見えない下面を、測量から復元できた形状とは説明しません。
- データセットは2024年公開、LASヘッダーの作成日は2023-10-30です。現況の新築施設がすべて反映されているわけではありません。

## 橋・高架・地面

- 大きな歩道橋：幅の広い橋面と張り出し、下面の曲線桁、壁状橋脚、高欄、リング状照明柱を生成。接続部込みの地図線は約401実寸mで、紹介資料の橋長360mとは測定範囲が異なります。
- 高速道路：アスファルト面・車線・防護壁・桁・橋脚を生成。地上道路と高架を分け、トンネルを高架として描画しません。
- 新交通高架：コンクリート走行路、タイヤの走行帯、側面案内軌条、中央の点検部分、T形橋脚で描き分けます。地下の鉄道や補助線は高架の生成対象から除外します。
- 地表の舗装・道路・芝生は同じ高さ0mで、保存用の5cm格子上の共通境界から面を分割します。上へ浮かせて重ねず、描画用の段差を追加しません。高架・歩道橋・高速道路を平面道路へ重複投影しません。白線と走行帯は描画の深度補正だけで安定させます。確認カメラの近遠クリップも拡大率に合わせます。
- 芝生として抽出された範囲は約432ゲーム㎡だけです。撮影色の緑からの抽出であり、公園全域や植生境界を再現したものではありません。
- 舗装・コンクリート・石張り・芝生の色と凹凸は、固定乱数によるCanvasテクスチャです。外部画像の同梱・通信はありません。岸壁は水域に接する辺にだけ付け、取得範囲の切れ目には付けません。
- 交通構造の高さは点群の標高を平滑化し、平坦化した地面へつなぐ最低高さ・端のランプを補っています。実際の縦断面の精密復元や、機体の通行検査が済んだ形状ではありません。

出典と補完方法は [外観参照記録](../../../research/maps/odaiba-transport-reference.md) にまとめています。

## 容量と表示

`terrain.json` は204,809バイト、`surface-render.js` は12,671バイトで、**地形＋専用描画コードは合計217,480バイト／500,000バイト以内**です。生成テクスチャを画像ファイルとして保存せず、小さなレシピと描画コードから再生成します。表示時のGPUメモリや三角形数は保存容量と別で、`viewer-check.json` に記録しています。

`coordinateStep` は0.05ゲームm。座標と頂点番号は16bitで保存し、量子化後の輪郭も検査します。確認HTMLには共通のthree.jsと機体見本も含むため約895KBです。このHTML全体を「217KB」とは説明しません。

`viewer-template.html` は全体・真上・北側追加範囲・橋・高速道路・新交通高架・ランドマークへ切り替えられます。黄色い高さ8mの棒と現行ゲームの約4mの機体モデルを比較用に並べています。8m棒を現行機体の寸法とは説明しません。

## 再生成

Python 3.12で使用しました。制作専用の依存関係は `tools/requirements-pointcloud-map.txt`。ブラウザでゲームを遊ぶ人には不要です。大きな原データをGitへ入れないでください。

```sh
python -m pip install -r tools/requirements-pointcloud-map.txt
python tools/odaiba_pointcloud_fetch.py
python tools/odaiba_pointcloud_grid.py
python tools/odaiba_pointcloud_vectors.py
python tools/odaiba_pointcloud_terrain.py
python tools/test/odaiba_pointcloud_terrain_check.py
python tools/test/odaiba_transport_detail_check.py
python tools/test/odaiba_pointcloud_roof_check.py
python tools/odaiba_pointcloud_preview.py
node tools/test/odaiba_pointcloud_viewer_check.js
```

キャッシュ既定値はOSの一時ディレクトリ下の `core-breaker-odaiba-pointcloud`、出力先はこのディレクトリです。`ODAIBA_POINTCLOUD_CACHE` と `ODAIBA_POINTCLOUD_OUTPUT` で変更できます。空キャッシュでは約4.1GBを取得します。ZIPのSHA256を照合し、LASを一括展開せず順番に読みます。

## 確かめたことと限界

- 公開ZIP53件と地理院39タイルの取得記録・SHA256照合。
- 500KB以内、縮尺・切り出し範囲、元の座標原点、施設非依存、量子化後の輪郭、三角形の頂点参照・面積を検査。
- 地表の三材質が重ならず、地表全体を覆うこと、道路・芝生の保存後の色別描画が3距離×3角度×9点で正しく見えること、全地表の高さ0mを検査。
- 地下鉄道・道路トンネルの除外、交通経路の有限座標・縦勾配、歩道橋の幅と経路長を検査。
- オフラインの確認HTMLで全体・北側・交通構造・ランドマークを表示。JavaScript・WebGLエラー0、外部通信0、生成材質の再読込時の一致を検査。
- `roof-grid-check.json` は**建物と特徴建物の上面だけ**を1m格子で調べる予備検査です。生成交通構造、機体の横幅・実移動、橋や門の下の多層の到達性は対象外です。残る候補を実機体の落下・離脱の合格とは扱いません。
- 地形輪郭の確認後、基地→確認→プラント→確認→移動設備→実走・BOT対戦の順で進めます。

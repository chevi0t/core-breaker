# 双湾展示区（sowan）

お台場〜有明の湾岸を実寸1/3にした10対10・4プラントのマップ。地形は[点群による地形確認版](pointcloud-third/README.md)（ユーザーが選んだ1/3の新版、2026-11-10）をそのまま使い、`tools/build_sowan_third.py` で遊べる形（`prototype/maps/sowan.js`、city-layout-v1）へ変換する。PR #64 の旧半縮尺版は置き換えた。

```sh
# 写真の地面と木を作り直すときだけ（点群4GBの取得が要る。ふだんは photo.webp・trees.npz をそのまま使う）
ODAIBA_POINTCLOUD_CACHE=<置き場> python3 tools/odaiba_pointcloud_fetch.py && ODAIBA_POINTCLOUD_CACHE=<置き場> python3 tools/sowan_photo.py
python3 tools/build_sowan_third.py   # sowan.js と generation.json を書く
python3 tools/build_maps.py
python3 tools/test/make_dbg.py dbg && node tools/test/map_check.js dbg sowan
```

## 変換でしていること

- 地形確認版の座標（5cm格子）を、ゲームの4cm格子へ直し、z を中心へ寄せる（`zShift`）。マップの半分の大きさは境界より4m広い671m（Bot の通り道の4m格子を崩さないため）。
- 橋・高架・新交通は、床（厚さ1m）・側面・端面の三角形にする。床の上を歩け、下は高さ4mの機体がくぐれる（床の上面を6〜6.5m以上にする）。歩道橋・遊歩道・一般道の橋は、陸にある端を勾配0.3以下の坂で地面へ下ろす。高速道路と新交通の高架は降り口を作らない。折れ線は3次元で0.25mまで間引く（容量のため）。橋脚は窓の模様の無い灰色の柱。
- 水際（取得範囲の切れ目を除く）に深さ4mの岸壁。水面は -1.2m、川底は -4m。
- 地面は舗装も含めて点群のコンクリートの色、道路はアスファルト、緑地は芝（lawns）。これは写真の地面に対応していない本体向けの予備で、今の本体は下の「見た目」の写真を貼る。
- 基地は2つとも南側。プラントは候補地点の近くの空き地（占拠円14m）。再出撃はプラントから自軍ベース側へ46〜52m。両端のプラント（A・D）のリペアポッドは、map_check と同じ見方（プラントの中心から自軍ベースと反対側の半分、15m格子、180m以内、目の高さ4.6m、機体の高さ2.4mと3.9m）で見えない所を探し、建物の陰だけで隠れないときは高さ5.2mの塀を足す。
- カタパルトは各ベース4基（外側のプラントへ）と、A→B・D→C の2基。どれも30度。実際の飛び方（無入力、射出後60%からの抵抗あり）で測り、着地点から目標までの間がずっと地面（屋上・高架・水の上でない）で、着地点から Bot の通り道へ歩けるよう、4基の目標を動かした（`catapult-fit.json`）。屋上に降りた Bot が降り道を探してゲームを止めていたため（2026-11-10、ユーザーの「すげぇカクつく」）。
- Bot の通り道は4m格子から作り、橋の床の上の節点に床の高さを付け、床の中心線にも8mおきの節点を足す（本体は往復できない辺を捨てるので、高さの無い節点が海の上にあると橋の道が切れる）。

## 見た目（2026-11-11、ユーザーの「見た目の再現、本気が見てみたい」）

色は全部、東京都の点群の撮影色（CC BY 4.0）から作る。ほかの写真・地図の画像は使っていない。作るのは `tools/sowan_photo.py`（頭に手順）。

- **写真の地面・屋上**（`photo.webp`、8192×4096、約2.2MB）：点群を実寸0.5mの格子にし、いちばん高い点の色を真上から見た写真にした。地面・屋上・橋の床に貼るので、駐車場の白線、テニスコート、コンテナ、屋上の設備まで写る。1画素はゲームで約16cm。
- **影を消した**：点群の色には撮影時の影が写っていて、本体の太陽の影と向きが合わない。高さから計算した影と写真の暗さがいちばん合う時刻を東西50mの帯ごとに探すと、西の区画は13.7時ごろ、東は9.5時から14.2時へ順に撮られていた（太陽の赤緯5度＝4月上旬。桜が写っている）。計算した影のうち写真でも暗い所だけを、日なたと影の明るさの比で戻した。木の影は残している。影の縁や屋上の設備の周りに、少し明るさのむらが残る。
- **木**（`trees.npz`、約1万2千本から基地・プラントの周りなどを除いて約1万本）：レーザーが枝を抜けて複数回返る所（複数リターン）のうち、地面から2m以上で建物・橋の外のかたまりを木とし、梢ごとに分けた。高さと枝の広がりは点群の値の1/3。撮影は春先で枝の色が多いので、色は濃い緑を選び、明るさだけ写真から取った。写真で薄い桃色の木は桜の色にした。**当たり判定は無い**（機体も弾も通り抜け、Bot の視線にも関係しない）。
- **外壁**：点群の色は真上からの写真なので、壁の色と窓は分からない。高さと広さから決めた（60m以上はガラスか横連窓、低くて広い倉庫・展示棟は窓の無い板張り、ほかは格子の窓）。建物ごとの実物の再現ではない。
- **空と海**：雲のある空、波と空の映り込みのある紺の海（色は独自に選んだ）。
- 本体の仕組み（`district.photo`・`trees`・`sky`、`river.sea`、`facade`）は `prototype/maps/README.md`。ほかのマップの見た目は変わらない。
- 重さ：マップのファイルは約3.5MB（うち写真3.0MB、木0.1MB）。GPU のメモリは写真で約90MB（16ビット色）。描く三角形は木で約20万増える（遠い木は描かない）。

## 確かめたこと（2026-11-10）

- `build_maps.py` 通過、ファイル約426KB。
- `map_check.js`：施設は全部地面の上、ポッドA（143か所）・D（135か所）はどこからも見えない、再出撃46〜52m、Bot の通り道は全部つながり、プラントとカタパルトの近くに歩いて行ける節点がある、ページのエラー0。
  - レーダーの「★障害物に埋まっている」は、レーダー自身の建物（#156 で幅5.6m）を数えているだけ（ほかのマップも同じ）。
  - カタパルトの「★ずれが大きい」は、射出後60%からの抵抗で無入力だと着地点の手前（22〜35m）に降りるため（docs/DESIGN.md のカタパルトの節。ほかのマップも同じ）。抵抗の無い基準の放物線では10基とも目標の3m以内。
- `bot_battle.js` 10対10・150秒：エラーなし、撃破・プラントの移動あり。

## 止まる問題（2026-11-10）

1/3の縮尺なので高さ3〜12mの低い屋上が多く、Bot がジャンプやカタパルトで乗ると、歩いて降りられる道が無い。本体は降り道を探して道の点を全部（約1700）試し、そのたびに約1秒止まっていた（60秒で17〜25回）。本体の探し方を近い40個（150m以内）に絞る修正は別の PR。カタパルトの着地を地面にしただけでは止まりは減らない（低い屋上・囲まれた空き地が他にもある）。

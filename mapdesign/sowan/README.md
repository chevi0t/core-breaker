# 双湾展示区（sowan）

お台場〜有明の湾岸を実寸1/3にした10対10・6プラントのマップ。地形は[点群による地形確認版](pointcloud-third/README.md)（ユーザーが選んだ1/3の新版、2026-11-10）をそのまま使い、`tools/build_sowan_third.py` で遊べる形（`prototype/maps/sowan.js`、city-layout-v1）へ変換する。PR #64 の旧半縮尺版は置き換えた。

```sh
# 写真の地面と木を作り直すときだけ（点群4GBの取得が要る。ふだんは photo.webp・trees.npz をそのまま使う）
ODAIBA_POINTCLOUD_CACHE=<置き場> python3 tools/odaiba_pointcloud_fetch.py && ODAIBA_POINTCLOUD_CACHE=<置き場> python3 tools/sowan_photo.py
# 壁の色を取り直すときだけ（PLATEAU の区画130MBの取得が要る。ふだんは walls.json をそのまま使う）
SOWAN_PLATEAU_CACHE=<置き場> python3 tools/sowan_walls.py --fetch && SOWAN_PLATEAU_CACHE=<置き場> python3 tools/sowan_walls.py
python3 tools/build_sowan_third.py   # sowan.js と generation.json を書く
python3 tools/build_maps.py
python3 tools/test/make_dbg.py dbg && node tools/test/map_check.js dbg sowan
```

## 変換でしていること

- 地形確認版の座標（5cm格子）を、ゲームの4cm格子へ直し、z を中心へ寄せる（`zShift`）。マップの半分の大きさは境界より4m広い671m（Bot の通り道の4m格子を崩さないため）。
- 橋・高架・新交通は、床（厚さ1m）・側面・端面の三角形にする。床の上を歩け、下は高さ4mの機体がくぐれる（床の上面を6〜6.5m以上にする）。歩道橋・遊歩道・一般道の橋は、陸にある端を勾配0.3以下の坂で地面へ下ろす。高速道路と新交通の高架は降り口を作らない。折れ線は3次元で0.25mまで間引く（容量のため）。橋脚は窓の模様の無い灰色の柱。
- 水際（取得範囲の切れ目を除く）に深さ4mの岸壁。水面は -1.2m、川底は -4m。
- 地面は舗装も含めて点群のコンクリートの色、道路はアスファルト、緑地は芝（lawns）。これは写真の地面に対応していない本体向けの予備で、今の本体は下の「見た目」の写真を貼る。
- 基地は2つとも南側。プラントは6つ（2026-11-12、オーナーがカードで「数を増やす」：4つを5〜6つにし、南側や橋のたもとにも置く）。名前は青の基地に近い順で、北の道すじが A・C・E・F（前の A・B・C・D と同じ場所）、南の道すじが B（西の島の南の道沿い）と D（南の橋を東へ渡った先、大きな遊歩道の橋の東の入口からも約70m）。南の橋のすぐ西には占拠円の取れる空き地が無く、B は橋の入口から約170m 西になった。勝率は未確認。プラントは候補地点の近くの空き地（占拠円14m）。再出撃はプラントから自軍ベース側へ46〜52m。両端のプラント（A・F）のリペアポッドは、map_check と同じ見方（プラントの中心から自軍ベースと反対側の半分、15m格子、180m以内、目の高さ4.6m、機体の高さ2.4mと3.9m）で見えない所を探し、建物の陰だけで隠れないときは高さ5.2mの塀を足す。
- カタパルトは各ベース4基（外側のプラントへ）と、A→C・F→E の2基（北の道すじの次のプラントへ）。どれも30度。実際の飛び方（無入力、射出後60%からの抵抗あり）で測り、着地点から目標までの間がずっと地面（屋上・高架・水の上でない）で、着地点から Bot の通り道へ歩けるよう、4基の目標を動かした（`catapult-fit.json`）。屋上に降りた Bot が降り道を探してゲームを止めていたため（2026-11-10、ユーザーの「すげぇカクつく」）。
- Bot の通り道は4m格子から作り、橋の床の上の節点に床の高さを付け、床の中心線にも8mおきの節点を足す（本体は往復できない辺を捨てるので、高さの無い節点が海の上にあると橋の道が切れる）。

## 見た目（2026-11-11、ユーザーの「見た目の再現、本気が見てみたい」）

地面・屋上・木の色は、東京都の点群の撮影色（CC BY 4.0）から作る（`tools/sowan_photo.py`、頭に手順）。壁の色だけは PLATEAU（CC BY 4.0）から取る。ほかの写真・地図の画像は使っていない。

- **写真の地面・屋上**（`photo.webp`、2048×1024、約0.30MB）：点群を実寸0.5mの格子にし、いちばん高い点の色を真上から見た写真にした。地面・屋上・橋の床に貼る。道・芝・屋根・コンテナの色の並びが写る（白線などの細かい物は写らない）。1画素はゲームで約65cm。
- **影を消した**：点群の色には撮影時の影が写っていて、本体の太陽の影と向きが合わない。高さから計算した影と写真の暗さがいちばん合う時刻を東西50mの帯ごとに探すと、西の区画は13.7時ごろ、東は9.5時から14.2時へ順に撮られていた（太陽の赤緯5度＝4月上旬。桜が写っている）。計算した影のうち写真でも暗い所だけを、日なたと影の明るさの比で戻した。木の影は残している。影の縁や屋上の設備の周りに、少し明るさのむらが残る。
- **木**（`trees.npz`、約1万2千本から基地・プラントの周りなどを除いて約1万本）：レーザーが枝を抜けて複数回返る所（複数リターン）のうち、地面から2m以上で建物・橋の外のかたまりを木とし、梢ごとに分けた。高さと枝の広がりは点群の値の1/3。撮影は春先で枝の色が多いので、色は濃い緑を選び、明るさだけ写真から取った。写真で薄い桃色の木は桜の色にした。**当たり判定は無い**（機体も弾も通り抜け、Bot の視線にも関係しない）。
- **外壁**（2026-11-12、オーナーの「取得しきれん側面が似てないのを何とかしたい」「窓はなくていい 色が似てればいい」）：窓の模様をやめ、建物ごとに実物の壁の色で塗る（`walls.json`、作るのは `tools/sowan_walls.py`。頭に手順）。
  - 点群からは取れない：点群の色は真上からの写真で付けてあり、壁に当たった点も屋根と同じ色（同じ格子の屋根との差は中央値で 4/255）。
  - 出所は PLATEAU の建築物モデル LOD2 テクスチャ付き（港区・江東区・品川区、2025年度版、CC BY 4.0。範囲に掛かる69区画、約130MB）。壁の面の写真から建物ごとに色を1つ取る（740個の箱のうち537個）。マップに入るのは色だけで、PLATEAU の形や写真は入れていない。
  - 日の当たった向きの面だけを使う（撮影は午前で、東〜南東向きの壁が明るい）。日陰の面は青黒く写っていて、混ぜると赤茶の塔も青っぽい灰色になる。明るい所だけを平均する方法は、白いバルコニーに引っ張られるのでやめた。
  - かすみ（いちばん暗い所に乗っている色）を引き、同じ屋根を `photo.webp` と比べた倍率で色かぶりを直す。
  - マップへ入れるとき（`build_sowan_third.py`）：測った建物の色味の中央値を灰色に合わせ、色味の差を2.5倍に強める（`WALL_SATURATION`）。PLATEAU の写真は色が薄く、赤茶のれんがの塔も桃色がかった灰色にしか写っていないため。色の向きは測った値のままで、濃さだけを変えている。本体の光で日なたの面が測った色になるよう、明るさは1.3倍（`WALL_GAIN`）。
  - 取れなかった建物（南のふ頭の倉庫など、PLATEAU に写真付きの形が無い物）は、屋根の色に「壁÷屋根」の中央値を掛けた色。
  - 限界：色は建物ごとに1つ。れんがの赤茶は薄い桃色になるなど、濃い色は実物より薄い。完全な再現ではなく「色の向きが合う」まで。
- **色の手直し**：実物と違う建物は、開発者用ページで指して記録した場所（x・z）と、言葉で教わった色を `wall-overrides.json` に書く（`[{"at":[x,z],"color":"#rrggbb","note":"…"}]`）。
- **空と海**：雲のある空、波と空の映り込みのある紺の海（色は独自に選んだ）。
- **目印の建物**（2026-11-12、オーナーの「あとはランドマークの色と形状」）：`build_sowan_third.py` の `landmark_parts` で、箱を組んで作る。
  - 点群は真上からの形しか無く、PLATEAU の LOD2 も壁をまっすぐ下ろした箱（門の穴や格子のすき間は埋まっている）。そこで、位置・向き・幅・奥行き・高さは点群と PLATEAU から測り、横から見た形だけ、広く知られた姿をもとに組んだ。写真や地図の画像はなぞっていない。
  - 球のある局舎：低層の棟（高さ10）、2つの塔（38と39.5）、渡り廊下3段と柱の格子、球（半径5.3、頂上41。14角柱を7段重ねた物）。いちばん上の廊下の高さ36・格子のすき間・球の位置は点群の値。下の2段の高さは等間隔に置いた見積もり。球の色（銀）は選んだ色。
  - 門の建物：丸いアーチをやめ、左右の脚と上の棟の箱にした（四角い穴）。外形と高さ33は点群の値。穴の幅（19）と上の棟の厚さ（7.7）、下のガラスの吹き抜け（高さ9まで、色は選んだ色）は見積もり。
  - 壁の色は、その場所に元あった箱の色（PLATEAU から測った色）を使う。
- **大きな遊歩道の橋の円い広場**（2026-11-12、オーナーが開発者用ページで指して「夢の大橋こうやねん」）：床の帯に、半径約10mの円い広場を2つ足した（`deck-plazas.json`）。東京都の点群は海の上の橋に点が無いので、中心と半径は PLATEAU の橋梁モデル LOD2（江東区、2025年度版、CC BY 4.0）の床の輪郭に円を当てはめて測った（当てはめの外れは最大0.17m）。入れたのは中心と半径の数字だけ。同じ理由で、海の上の橋の床は写真に色が無く、岸や海の色の筋になっていたので、同じ橋の陸の上の床の色で埋めるようにした（`sowan_photo.py`）。
- 本体の仕組み（`district.photo`・`trees`・`sky`、`river.sea`、`facade`）は `prototype/maps/README.md`。ほかのマップの見た目は変わらない。
- 重さ：マップのファイルは約1.7MB（うち写真1.1MB、木0.1MB）。GPU のメモリは写真で約22MB（16ビット色）。描く三角形は木で約12万増える（遠い木は面を減らし、もっと遠い木は描かない）。
- 軽くした所（2026-11-11、オーナーの「色維持しつつどうやって軽くすっかなー」）：写真のうち見えない所（海など、点の無い所）は最寄りの色の筋をやめてぼかした色にし、WebP を method 6 で作る（2.24MB→1.77MB。見える所の色は同じ）。写真の細かさは 4096×2048（1画素がゲームで約33cm）にした（オーナー 2026-11-12「全部再現したら重くなっちゃうし、色とランドマーク形状がそれっぽかったらオッケー」）。8192×4096 だと足元の白線やコートの線まで写るが、写真が約1.8MB・GPU のメモリが約90MBになる。その後、ファイルを小さくするために 2048×1024（1画素がゲームで約65cm、写真 0.82MB→0.30MB、マップのデータ 1.64MB→0.93MB）にした（オーナー 2026-11-12「半分で0.3？すごいなやっちゃおう」）。`tools/sowan_photo.py` の `PHOTO_SIZE` で変えられる。
- 建物を指して実物を伝える開発者用ページ：`python3 tools/make_dev_page.py dbg` が `dbg/dev.html` を作る。照準の建物の番号・場所（緯度経度）・その場所のストリートビューのリンクをメモ帳に記録し、オーナーが「実物はこう」を言葉で書いてスレッドに貼る。出撃すると敵も味方もいない散策になり、T で飛べる（オーナー 2026-11-12「自由に空飛べるようにしてほしいのと、敵味方いない自由散策モードに」。本体は書き換えず、dev.html の中で本体の関数を包む）。ストリートビューの画像そのものは、保存も、形や色を取る材料にもしない（Google の規約）。

## 確かめたこと（2026-11-10）

- `build_maps.py` 通過、ファイル約426KB。
- `map_check.js`：施設は全部地面の上、両端のプラントのポッドはどこからも見えない、再出撃46〜52m、Bot の通り道は全部つながり、プラントとカタパルトの近くに歩いて行ける節点がある、ページのエラー0。
  - レーダーの「★障害物に埋まっている」は、レーダー自身の建物（#156 で幅5.6m）を数えているだけ（ほかのマップも同じ）。

## 止まる問題（2026-11-10）

1/3の縮尺なので高さ3〜12mの低い屋上が多く、Bot がジャンプやカタパルトで乗ると、歩いて降りられる道が無い。本体は降り道を探して道の点を全部（約1700）試し、そのたびに約1秒止まっていた（60秒で17〜25回）。本体の探し方を近い40個（150m以内）に絞る修正は別の PR。カタパルトの着地を地面にしただけでは止まりは減らない（低い屋上・囲まれた空き地が他にもある）。

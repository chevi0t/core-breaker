## 目視と再現

[最新本体の比較ZIP](replay/comparison.zip)を解凍し `index.html` を開く。基準と**不採用候補**の各2リプレイ。時刻・機体・大破・コア命中・補給開始・遮蔽破壊から比較できる。位置は0.25秒、イベントは0.05秒。実行時のソースSHAを記録し、4記録の初期状態・終局HP・撃破・占拠が対戦器と一致した（[照合](recorder-consistency.json)）。

- [before.json](before.json)：基準12戦。最終登録と[物理・施設・navが全3戦場で一致](registered-data-check.json)するため、現配置の記録として使う。新たに12戦を実行したという意味ではない。
- [after.json](after.json)：不採用候補12戦。[comparison.json](comparison.json) に試合別・集計・Wilson区間。
- [candidate-map.js](candidate-map.js)：比較した `repair3` の正確な入力。最終登録ファイルは `prototype/maps/circulation.js`（`reviewed250`）。
- [source-manifest.json](source-manifest.json)：ゲーム本体・検証器・地形入力の版。

`make_dbg.py dbg --trace` の後、`map_battle.js dbg <同じIDを2回ずつ> 301 <出力> <seed> --paired-rosters --map-source <入力.js>` で再実行する。候補を生成するなら `generate_map.js ... --revision repair3`。最終登録は同じシードで `--revision reviewed250`。生成の記録は毎回 `mapdesign/<id>/v3/runs/` 以下の新しいディレクトリへ保存し、本体・生成器のSHAと候補入力も残す。同条件の再実行でも過去の失敗を上書きしない。

# 翠河城下・地形試作（ローカル）

ユーザー指定の旧ブロア市街地「熱戦の河畔」を地形・経路の基準とする。公式参照は https://borderbreak.com/map/2#opr-3 、俯瞰 https://borderbreak.com/content/map/bIt9XY4uxe5Gs1lvtH.jpg 。別作戦153のバリケードや施設配置は取り込まない。公式画像・モデルはゲームデータへ同梱しない。ゲーム内の名称・形状データは自作。

観察：左右に高台ベース、中央を北西から南東へ流れる川、左の丘陵と小街区、右の大きな城下と丸い高台街区、北側の扇形の城壁区画。中央主橋の下は複数アーチ、下流に細い渡河路。川底・河岸通路から街路へ上る坂。左右を鏡像化しない。

推定：原図は斜め俯瞰であり、画像のピクセルを実測の平面距離とは扱わない。10mグリッドを目安に仮の平面登録を行った（画像u,vからゲームx=(v-550)*0.85、z=(800-u)*0.65）。各輪郭・道路・建物は手で読んだ点をレシピ化。標高は画像からの相対関係に基づく仮値：川床-2m、水面-0.5m、街路10〜14m、西丘24m、東丘32m、西基地40m、東基地48m、城の中庭18m、奥の上段28m（城壁は別体）。数値の正確な復元は主張しない。

`tools/terrain_recipes/river_castle.json` → `node tools/terrain_recipe.js tools/terrain_recipes/river_castle.json prototype/maps/river_castle.js` → `python3 tools/build_maps.py`。

共通生成器に斜め外周、手描き標高領域、河川、アーチ橋を追加。既存の支持面・衝突・nav形式を使う。高さ乱数は使わない。建物は個別の位置・寸法を持つ簡略プレースホルダーで、厳密な間取り・屋根形・建物数は未再現。現段階の足りない部分と実走結果はレビュー資料に記録する。公開マップの差替・push・PR・マージ・公開は未承認。

## 確認した範囲

主要13経路×軽量/重量×往復の52走行、橋上/橋下支持面、両機種のアーチ通過、天井への射撃とジャンプ、橋付近カメラ、基地と5プラントの再出撃位置を確認。カタパルト8軌道と18制御ケース、20機60秒の通常BOT戦でエラーなし。既存3レシピ×3seedの再生成一致と14不正入力の拒否を確認。全域の穴検査やPvP勝率検証は行っていない。小さい孤立nav成分は残るが、指定した施設・経路アンカーは主成分に接続する。

試遊版は `python3 tools/build_terrain_preview.py tools/terrain_recipes/river_castle.json /workspace/river-castle-review --skip-escape` で作成。出力先で `python3 -m http.server 8000`、PCから `http://localhost:8000/game/` を開き「翠河城下・地形試作」を選ぶ。既存の都市マップのモバイル除外条件は維持。

主橋・川沿い・中庭と左右の坂・東西街区を撮影。撮影のみ霧と視野角を調整し、ユニットを非表示にした。参考写真の石積み装飾や建物意匠は未再現。川岸・道路・外周は10mグリッドの粗さが残り、地形の忠実度は完成版ではない。川の上流端は外周へ伸びる簡略形。公式と一致する高さ・距離とは主張しない。性能比較は20機、同じChromium/seed/viewportでcityと本試作を各2回。SwiftShaderのCPU/描画測定で、実GPU・実スマホ性能や同等FPSを保証しない。

変更はローカル専用。取り消す場合はこのブランチの追加差分を外す。公開ベースラインは841e636で、公開中のマップを差し替えない。

## ユーザー画像による読み違いの修正

扇形の輪郭を丸ごと60mの台地と解釈していたが、輪郭は城壁であり誤りだった。提供された地上画像を優先し、街路14mから中庭18m、左右の坂から上段28mへ接続する仮配置へ変更。奥と側面の城壁、建物を別の構造物にした。これらの高さは計測値ではなく、中庭の完全な平坦さも確定していない。階段は現段階では滑らかな坂で代用し、城の意匠・背後の背景山は未再現。旧60m版のスクリーンショットは比較用に限り保存し、現行版とは明確に区別する。

## 番号付き指摘への修正（e30f039以後・ローカル）

3枚のユーザー参照画像を実ファイルとして読み、各地区の配置を見直した。④C詳細は一時HTTP503だったが、後の正規取得に成功し画素を確認済み。公式/ユーザー画像はゲームや配布物へ同梱しない。

- ①手前の小街区：隣接街路10mに対し標高20mの小さな段丘。大高台52.5mとは区別。
- ②山城：12棟の平屋根を標高20〜69.5m、段差4.5mで連ねる。通常ジャンプと自然なブースト回復で軽量・重量が登頂。上の66.5m広場は周囲の建物で囲み、後方の低い中庭とは別地形のまま。BOTは通常の坂を使う。屋根間ジャンプのBOT経路生成は未実装。
- ③ゲート：既存の自動砲台を両軍2基ずつ、実際の支持台上へ設置。外向きの敵への発砲を標本確認。参考の野外G位置は有人砲台だが現行ゲームに同機能がないため、扱いを質問中。勝手に自動砲台には置き換えていない。
- ④C：街路に向いた低層列と路地、細い高塔、河岸の長い切妻棟＋小塔へ変更。河岸の坂を塞がない位置へ調整。
- ⑤B：長い建物4棟を異なる角度で内側の小空間を囲む配置へ。道は外側を回り、主橋と河岸へ接続。
- 地表：道路輪郭を格子の階段から切り出し、外周も多角形に沿って切り、法線を平均化。地面を道路/土の断片だけに分割する案は微小な支持面の抜けを生じたため採用せず、連続した地面を保持。急崖・水際の角張りは残る。形状は引き続き仮配置で、完全再現とはしない。

## 35c9de7後の限定仕上げ

水面下の縞は、生成済みの川床と実行時に追加する川床が同じ高さで重複する描画競合だった。smoothTerrain指定の生成地形だけで後者を省略。川の位置・高さ・橋は変更していない。

道路は連続地面に重ねた表示色なので、支持面/弾/カメラ用の重複登録を省略した。元地面の判定は維持。道路内部の三角形を先に判定して不要な細分を減らした。生成三角形20,254→19,681、実行時描画頂点15,887→15,461、衝突頂点20,355→14,069、衝突バッファ370,728→257,370bytes。建物/屋根道/高さ/nav/プラント/砲台は同じ。

残る10m格子の水際・急崖の輪郭は、この小変更では解消しない。高さを保って輪郭を滑らかにするには岸線と高台境界に沿った局所再三角形化と接合検証が必要。全面細分や陰影だけで完成とする変更は避け、今回の限定仕上げはここで止める。野外G砲台の方式も未確定のまま。

支持面の扱いが変わるため116走行・21項目と屋根/砲台13判定を再確認、全件通過。カタパルトと60秒BOTは直前35c9de7の証跡を再利用し、この仕上げ後は再実行していない。全域穴検査も追加しない。

35c9de7→限定仕上げの同条件20機/順序反転2回：CPU中央値8.6/6.0→5.2/6.2ms、CPU95%点15.8/9.2→18.1/17.2ms。描画+finish中央値3.5/3.0→3.1/6.6ms。ばらつきが大きく、時間の一貫した改善は確認できないため、性能懸念を解決済みとはしない。描画計数はcloakの最終パスで0にリセットされないよう全パス合計へ修正し、同じ方法で両版を再測定。三角形・衝突データの削減は確認できたが、実GPU同等性能は未検証。

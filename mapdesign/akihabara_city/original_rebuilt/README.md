# 星路駅前試験区・初版から路地を残して再構築

2026-10-23、ユーザー指定の再試作。簡略化前の初版を出発点に、高架延長 → 高架下店舗 → 100KBのゲーム用街区、の順に作る。前の簡略化・試走・100KB案の建物配置を入力に使わない。

600m四方、両基地は既存の採用位置を維持し、プラント・Botを配置しない地形確認段階。初版の道路と機体が通れる路地を先に保護し、その外側で建物を区画単位に単純化する。河川以外の地面と基地を平坦化し、川底・水面・護岸・徒歩復帰路を作る。過去の北東10棟への集約は、初版の通路を跨ぐ固定配置としては使用しない。

仮説：通路保護を簡略化より前に行えば、初版の通れる路地を減らさず、街データを100KB程度へ収められる。M31/M32/M36/M39に従い、形状の連続と実物理での移動を分けて確認する。途中2段階の形状・通路保護・容量・代表経路の実走と、前案との比較を保存する。

## 通路の保護

初版の道路全体と建物の外形を参照し、幅3.2m以上で道路につながる細い接続部分を抽出する。機体は半径1.3m・高さ4m。広い空地の全面を路地として扱わず、建物間の接続を優先する。保護範囲は約143,118㎡。店舗追加・街区統合・輪郭の丸めの後に、保護範囲へ実体が侵入した面積が0㎡であることを確かめる。1cm格子へ保存した後も同じ照合を行う。

普通の棟は2.4m以下の隙間を統合候補にするが、保護した通路を最後に切り戻す。容量を減らすために通路の保護幅を下げる処理は入れない。ランドマーク18か所は色と大きな外形・代表高さを維持し、北西パッドの着地点は95m。西側の東西高架脇の拡幅も建物を削る方向で引き継ぐ。前案で北東を10棟へまとめた範囲は、今回は初版の道路・路地に沿って区切る。

川の輪郭は初版の標高欠測域から取り直し、旧駅側の採用済みの岸の整形を加える。水域は24,224㎡。前案の24,536㎡との差は、面削減前の境界へ戻したことによる。川底-9m・水面-5.5mはゲーム用の仮値。岸から街路への復帰斜面以外の地面は平らにする。

[元の道路・建物外形・通路保護範囲の照合資料](source-layout.geojson.gz)は研究用のgzip圧縮GeoJSONで、ゲームは読み込まない。

1KB=1,000B。100KBの上限はゲームが必要とする配置・形状・代表経路をすべて含んだJSONのgzip前に適用する。通路を切り残す外周が増え、前案より面数は増えている。入力の初版は187,604面。FPSや実行時メモリの比較は今回測っていない。

## 検査と今回の判断

[初版からの再構築・前案比較の検査](original-check.json)では、初版の建物データと第1・第2段階の全頂点列が一致すること、配置JSON・gzip・単体HTMLが同じ内容を持つこと、面数・18か所の配色・基地の更地777地点を確認する。

初版から抽出した28通路を、軽量/重量機×30/120Hz×往復の224条件で同じ座標から実走した。前案では通路ID 5・12・16・17の32条件が失敗し、本案では失敗0。通路の選定と地形生成は前案の形状を使わず、前案を読み込むのは比較テストだけ。

同じ検査で基地からパッド・上下の南北線を徒歩で12通り、射出から高層棟への着地を4通り、以前問題になった3地点へ落下して周囲25m以上へ脱出する12通りを確認する。落下後は着地した高さの通路を探索し、その経路を本体の物理で歩く。以前の「穴を8mまで埋める形」を前提にした試験にはしない。

[川からの復帰と視界](recovery-check.json)は出口8か所の32通りと、路地24地点・1,273条件の旋回・照準を検査。[本体操作の検査](movement-check.json)は実キー入力、9開始地点、歩行・ブースト・ジャンプ、壁・屋根・橋・射線・境界など31項目。復帰・路地・高架・パッドはブースト容量を0にして確認する。

中間プレビューもそれぞれオフラインで5視点・7地物の切替、回転・拡大・平行移動、4m比較機体、スマートフォン幅を検査した（[高架段階](01_rail/browser-check.json) / [店舗段階](02_shops/browser-check.json)）。ブラウザエラー・外部通信は0。

通路を先に保護する作り方を、比較確認用の新案として保持する。全街路の到達性、Botの利用率、対戦バランスは未測定。地形と基地の確認後にプラント・経路・Bot戦へ進み、通常配信やZIPの更新は行わない。

## 再生成

Python依存は `tools/plateau/requirements-compact.txt`、配置の展開にはNode.js 18以降と同梱Three.js、ブラウザ検査にはPlaywright/Chromiumを使う。入力はGit内の初版HTML・集計・出典記録と、設定JSONだけ。取得キャッシュと前案の形状は不要。

```sh
python3 tools/plateau/rebuild_original.py mapdesign/akihabara_city /tmp/city-original
node tools/test/city_original_check.js /tmp/city-original
node tools/test/plateau_preview_check.cjs /tmp/city-original/01_rail/preview.html
node tools/test/plateau_preview_check.cjs /tmp/city-original/02_shops/preview.html
node tools/test/city_recovery_check.js /tmp/city-original
node tools/test/city_trial_check.js /tmp/city-original
```

設定は `research/maps/akihabara-original-rebuild.json`。共通のゲーム本体・試走の物理・カメラ・配置の展開器は変更しない。元の100KB案の再生成HTMLと配置JSONがバイト単位で変わらないことも照合する。[出典と加工内容、謝辞](CREDITS.md)。

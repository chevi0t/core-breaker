## 基地の更地化と地面・線路間の簡略化（2026-10-23）

赤枠で指定された北西約17,094㎡・南東の陸上約12,352㎡を平らな広場にした。枠内の建物は高層棟も含めて撤去し、川の輪郭と水域24,536.47㎡を維持する。青基地は矢印の東側 `(190,250)` → `(260,250)` へ70m移動。橙基地 `(-238,-243)` と各基地の半径28mは維持した。枠外の北西高層棟と屋上へ登る緑のジャンプパッドは残す。南東棟は更地化の対象なので、そこへ向かうパッドを撤去した。防衛・補給・プラント・Botは位置確認後。

街区の地面と車道は高さ-2mの平面にまとめ、路面の細かな凹凸・縁石・細分化を省いた。川底-9m・水面-5.5m・上下高架・駅屋根・川からの復帰斜面・旧駅の高台と接続斜面は残す。舗装の輪郭は40cm以下を目安に丸め、岸と外周で切り直す。高さはゲーム用で、現実の標高ではない。

南北の2本の高架の間も埋めた。上は8mと10mの床をつなぐ緩い接続面、下は店舗帯5区画。元の細い棟片7か所を除き、東西高架下の店舗も南北の走行空間を避けて5区画に調整した。下を横断する道路と川は塞がず、線路間の床の上面・下面・側面に描画と同じ接触・射線判定を付ける。

地面・舗装の基礎メッシュは加工前17,177面から1,475面へ約91%減った。その後の広場・護岸・復帰斜面などを含む全体は32,487面、HTMLは3,312,654バイト（約3.31MB）。音・ゲーム本体も含むため、面数とファイル容量の削減率は異なる。

## 色・路地・店舗と基地

道路は暗い舗装色、地面はコンクリート色にし、建物には棟ごとの色、暗めの屋根、窓の帯を付けた。窓はシェーダーで描き、箱や画像素材を増やさない。道路につながる幅5m以上の空地から過剰な充填を約7,100㎡除去し、狭い隙間の充填は残す。

コアと傘を本体から描き、広場の地面の高さへ合わせる。北西のジャンプパッドは垂直に上昇し、屋根より高くなってから空中操作で95mの屋上へ移る。上昇量は屋根より50mの余裕を取り、重量機もブーストなしで横移動できる時間を確保した。敵味方とも利用可能。

## ランドマーク配色と路面補修（2026-10-23）

ユーザー指定の白・赤・黒・青・ライムグリーンとガラス張りを19か所へ適用した。今回の更地化で北西広場内の青い棟1か所を撤去し、現在は18か所。対応する上部の屋根や段にも同じ配色を付ける。施設の位置・旧称を含む照合と色指定は[研究記録](../../../research/maps/akihabara-landmarks.json)。ロゴや写真は使わず、ゲームの地図には色を表示する。ガラスは格子と視点に応じた反射で表現し、壁の遮蔽を維持する。

南北の線路をくぐる道路2本と、東西高架をくぐる大通りの区間を連続した緩い路面へつないだ。元の道路面が欠けた区間を埋め、走行帯の両脇と出入口は元の地面へすり付ける。同じ面を描画・接地・射線に使用し、機体の段差許容をさらに緩める方法は取らない。道路に接する古い橋片1か所と高架帯の建物細片24か所を除去。歩道橋は歩行面を残し、厚い三角形の下面を0.35mの床へ整形した。

川沿いの旧駅付近は、粗い盛土と小屋根を整理し、高さ5.2mの主要上面と滑らかに接続する斜面へ変更した。格子ごとの陰影もならし、川側の壁に模式的なレンガ・アーチを描く。岸のギザギザは陸地484㎡を切り下げて直線へそろえた。川を埋めず、隣の高層棟と橋を残す。店舗内部や歴史建築の精密な復元ではない。「川沿いの高架店舗」から上面まで徒歩で移動できる。

## 川からの復帰と路地の視点（2026-10-23）

両岸に4か所ずつ、合計8か所の幅8mのスロープを追加した。緑の斜面と矢印が目印で、Mの地図にも道路までの経路を緑で表示する。ジャンプやブーストを使わず、川底から岸へ歩いて戻れる。岸の先は近くの既存道路まで接続し、接続部を整地した。通路を塞ぐ低層棟・充填棟は接続部分だけを切り開き、頭上の床・駅屋根は通れる高さを残す。

路地では、カメラの後方距離に加えて肩位置も調整する。横の余裕が小さい場所は中央寄りの視点にし、カメラ本体と画面の端、自機への見通しが壁に入らないよう判定する。壁が迫ったときはすぐ寄せ、開けた場所ではゆっくり通常位置へ戻る。極端に近い場合は描画中だけ自機モデルを隠し、元の表示に戻す。接触判定・被弾・射撃の規則は維持する。照準のレイも実際のカメラ付近から始め、視点が寄った際に手前の遮蔽物を飛ばさない。

## 接続したもの

確認済みの[高架・駅・店舗付きメッシュ](../rail/README.md)を、本体 `prototype/index.html` から作る専用の試走HTMLに組み込む。入力、機体の組み立て、武器、歩行・ブーストの速度、ジャンプ、重力、着地、ブースト消費は本体のコードを使用する。

- 建物・駅屋根・高架・店舗は、描画と同じ多角形の角柱約1,000個で壁・床・天井を判定する。穴や斜めの壁を保持し、機体半径1.3m・高さ4mを使う。
- 地面と道路は簡略化後の面上で高さを求め、橋梁は床・下面・壁の三角形を判定する。都市モデルの道路縁を歩いて越えられるよう、試走版だけ段差の許容を0.4m増やす。登れる斜面の傾きは本体と同じ。
- 壁・屋根・橋・護岸は弾と視線を遮る。描画は層単位にまとめ、レイ判定用の形だけ32m街区に分ける。カメラ用には近くの街区を抽出し、画面端を含む複数のレイと体積の余白を確認する。
- 四辺は機体中心を±298.7m以内へ制限する。ジャンプ・ブースト・吹き飛ばし相当の高速移動でも境界の外へ出ない。薄い青色の境界面を表示する。
- 地面を省略していた川に、仮の川底・護岸・水面を追加する。川底は表示基準から-9m、水面は-5.5m。現実の水位・水深ではない。既存ゲームの水と同じく水面は見た目だけで、機体は川底を歩く。南北高架下の店舗を川へ増やさない。
- 面削減で生じた四隅の小欠け212㎡は平らな地面で閉じ、川とは区別する。ミニマップにも川・建物・高架・自機を表示する。

公開ゲームの `prototype/index.html`、既存マップ、生成済み `maps.js` は変更していない。試走HTMLは確認用の成果物で、通常のマップ選択へ配信する段階ではない。残りの対戦用施設・Bot経路・全街路の到達性・公平さは未確定。これらは基地位置の確認後に進める。

## 検査

[実移動の検査記録](movement-check.json)と[生成元・ハッシュ・面数](generation.json)を保存する。`city_trial_check.js` はオフラインChromiumで実キー入力を通して歩き、その後は同じプレイヤーの本体 `physics` を動かす。

開始9地点の接地、歩行とブースト、通常ジャンプと着地、屋根と上下高架への落下着地、天井への衝突、高架からの降下、外壁への歩行・ダッシュ、壁と屋根での射線遮断、橋の上と下、四辺・四隅への高速移動、軽量機と重量機を検査する。Escでメニューに戻り、開始地点を切り替えられることも確認する。これは抽出した代表地点の機能検査で、全通路でスタックしないことの証明ではない。

共通の本体やBotは変更していないので、試走版だけを専用検査する。配置確定前のBot戦や配布ZIPの作成は行わない。M01/M02/M28/M30の教訓に従い、元の形状表示と今回の実移動確認を区別する。

`city_recovery_check.js` は追加した出口8か所を、軽量・重量機と1/30秒・1/120秒刻みの32通りで川底から既存道路まで歩かせる。ブースト容量を試験中だけ0にし、ジャンプ・ブースト入力を使わない。路地24地点では上下の視線と全周の旋回を変え、画面端の侵入・カメラの幅・開けた場所への復帰・手前の壁と照準の一致を確認する。M31/M32の教訓に従い、接地できることと脱出できることを区別している。

`city_district_check.js` は、軽量・重量機と同じ2つの時間刻みで復元路地12区間を48通り、基地からパッドへの徒歩を4通り、パッドから屋上への射出・空中操作・着地を4通り、交差部の南北線通行を8通り確認する。ブースト容量を0にし、本体の `jumpPadUpdate` と `physics` を使う。基地の平坦さ・指定区域・コアの位置、地上に露出する店舗の外壁も検査。通行の機能検査であり、Botの利用率や戦術バランスの試験ではない（M01/M02/M33）。

## 再生成

`tools/plateau/requirements-compact.txt` のPython依存と、リポジトリのPlaywrightを使用する。入力はGit内の圧縮済みプレビューと衝突用体積案で、取得キャッシュやNPZは不要。

```sh
python3 tools/plateau/build_trial.py mapdesign/akihabara_city/rail /tmp/city-trial
node tools/test/city_trial_check.js /tmp/city-trial
node tools/test/city_recovery_check.js /tmp/city-trial
node tools/test/city_district_check.js /tmp/city-trial
node tools/test/city_streets_check.js /tmp/city-trial
node tools/test/city_flat_check.js /tmp/city-trial
```

本体の接続箇所が変わった場合、生成器は停止する。生成HTMLを手で修正せず、`tools/plateau/build_trial.py` と `trial_runtime.js`、カメラの `trial_camera.js`、出口の `trial_river.py`、街区加工の `trial_district.py`、路面と旧駅の整形の `trial_streets.py`、地面と線路間の簡略化の `trial_simplify.py` を直して再生成する。基地・パッド・通路幅・補修箇所の設定は `research/maps/akihabara-trial.json`。

地理データと加工物の出典は[地形のクレジット](../rail/CREDITS.md)。試走用の川底・護岸・水面も地理データの加工としてCC BY 4.0。音とThree.jsを含めたクレジット全文をHTMLの「出典・ライセンス」に同梱している。公開データとソフトウェアを整備してくださった皆さまに感謝します。

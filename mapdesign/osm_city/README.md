戦場は648×632m、10対10・600秒。青基地は南西、橙基地は北東角(270,-260)。Aは右下の街区(268,212)、Bは中央の建物のすぐ東にある街路(60,44)。Cは公園北側(-208,-155)。Bは到着時間差を調整した位置を採用し、A・Cは前版の位置を使う。A・Cの補給所の壁は両軍の出撃帯を空ける。基地の判定半径は50m。全プラントを両基地の中心から180m以上離している。公園の主台地は18m、北側9m、南側7m。横道は-8m、縦道の橋は0mで4か所の立体交差を作る。橋の厚さ1m・桁下7m。高台と道路の高さはゲーム用設定で、実測標高ではない。

68件の建物形状を328個の箱へ近似し、道路資材6群と補給所の防壁6個を含め340箱。道路の表示は1メッシュ、建物の壁と屋根は2メッシュへ統合する。建物輪郭の押し出しで道路を塞いだ連絡部分2か所は、下端8mの空中スラブへ修正した。最高の建物は243m。機体の判定高は4m、初期表示モデルは3.982m。4本のジップラインで高さ123〜153.6mの屋上へ上がれる。

## 再生成

入力は https://api.openstreetmap.org/api/0.6/map?bbox=139.6865,35.6855,139.6960,35.6940 で取得したOSM XML。入力のSHA-256は `validation.json` を参照。地理形状の出力後、本体で通行経路を完成させる。

```sh
node tools/generate_osm_city.js source.osm mapdesign/osm_city/osm_city.js
python3 tools/build_maps.py --check prototype/maps/*.js mapdesign/osm_city/osm_city.js
python3 tools/test/osm_import_check.py
node tools/test/osm_city_check.js dbg/osm-city-v2 mapdesign/osm_city/osm_city.json /tmp/osm-check
```

Node.js・Python 3・Playwright/Chromium が必要。初版の平坦配置は `mapgen_osm.py --revision 1`。マップは開発候補で、既存 `prototype/maps.js` には登録していない。変換仕様は [調査記録](../../research/maps/osm-city.md)、地理データの条件は [CREDITS.md](CREDITS.md)。試作ZIPには入力OSM・加工済みデータ・変換器・俯瞰図・断面図を同梱する。

## 確認結果

- XML・高さの単位・地下除外・分割輪郭・格子統合の4試験に成功。既存7マップと候補の構造検査に成功。
- 本体の物理・射撃で7,347件を確認。軽量/重量・両軍の16徒歩経路、4交差点の上下/両方向の32実走、8件の屋上着地、8件のカタパルト着地に成功。橋の床が下段の射線を遮り、新基地のコア・レーダー・基地判定・防衛得点も一致する。
- 経路は367節点・1,786リンク。全リンクを本体の通行判定で往復検査。下段の坂で頭が橋に引っかかる経路と、地上押し出しが道路を塞ぐ箇所は実走中に発見し、修正後に上記検査を再実行した。
- 10対10の本体Botを150秒進め、両軍の撃破・プラントの所有権変化を確認。エラー0。1試合の機能確認で、公平さを判定したものではない。
- `quick_check.js 6cf1097` に成功（武器・パーツ・既存マップのデータ差分なし、city/dock各60秒）。全294武器の発射検査は第2版でエラー0。本体・装備はその版から変更していない。
- 第2版の本体で既存city/wide/mesa/dockの150秒指定の回帰試験に成功。実進行は154/153/152/99秒、dockはコア破壊で終了。全4マップでエラーなし。

試作ZIPの各ハッシュは `validation.json` に記録する。第6配置のHTML・音・ライブラリは、オフライン出撃・移動・射撃に成功した第2版と同一で、マップデータと説明・図を更新した。照準・反動・武器性能は変えていない。ZIPは採用済みのブースト音を引き継ぐ。3戦場の自律選抜、編成入替比較、200〜2000試合の統計評価、ブラウザで直接OSMを選んで変換する画面は未実施。

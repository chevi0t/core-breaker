# 星路駅前・四街区争奪戦（通常本体への統合）

確認済みの都市対戦試作を通常の `prototype/index.html` のマップ選択へ登録する。独立した試走HTMLを起動する形から、既存の機体・武器・HUD・設定・対戦進行をそのまま使うマップへ移した。IDは `hoshimichi`。

## 引き継ぐ配置

600m四方、10対10、上限10分、4プラントは中立から開始。北西と南東の基地は半径28m。各基地にカタパルト4基・砲台4基・レーダー1基・補給ポッド2基、各プラントにポッド1基。橙側だけの高層棟用ジャンプパッドは撤去済み。

| プラント | x,z（m） | ユーザー図の赤丸 |
| --- | --- | --- |
| A | 51, -23 | 中央東、白いランドマークの西 |
| B | -70, -56 | 中央西、南北高架の西 |
| C | 196, -218 | 北東の道路 |
| D | -250, 215 | 南西の川沿い |

元の形状・対戦配置は `source/` のJSON。入力は対戦試作commit `5649404` と同一のハッシュを保持する。路地、駅屋根、上下の線路、配色、川の8本の復帰路、A/Bポッドの窪地と坂も引き継ぐ。ユーザー指定の地上通路の部分だけ、下層を切って上面を残す。初期配置とBotの通常の役割を維持し、勝率は未確定とする。

統合時、南東基地の4番目のカタパルトだけは、建物の角へ接触せず降りられる街路へ着地点を `(230,116)` から `(218,152)` へ調整した。元の入力は変更せず、変換器と `import.json` に差分を記録する。

## 地上と空中の追加経路（2026-10-23）

ユーザー図の赤矢印は、幅12m・路面y=-1.98m・天井高約6.5mの平坦な4通路として開く。北側で南北高架をくぐる東西路、駅中央の東西路、その西端と東端の南北路。重なる16体積の下層だけを切り、上の線路・駅屋根・建物の上階を維持する。通常の地面の2cm上に舗装を重ね、地図には薄い破線で開口を示す。新しい歩行経路を既存の街路へ接続し、プレイヤーとBotの双方がジャンプなしで通れる。天井の接触・弾・視点も同じ形状を使う。

共有の垂直ジャンプパッド10基を、高架を両方向へ越える街路と東西の街区に追加。踏み口の頭上を空け、通常の空中操作で屋根へ着地し、その先の道路へ降りられる位置を選ぶ。屋根の途中で低い段へ下りた後、再び登れなくなる配置は候補から除く。基地専用の巨大パッドは戻さない。

両基地の8台は飛行4.2秒の高角軌道にし、最高点は路面から約75m。D→Aは5.4秒、C→Bは6.4秒で街区を越え、占拠円の手前の道路へ着地する。いずれも両軍が使える。操作禁止は最初の1秒だけ。無入力なら指定の道路へ届き、解除後は空中ダッシュと滞空で調整できる。途中で接地した場合も操作禁止を残さない。既存のパッド物理とカタパルトの指定時間の処理を使い、星路の設定で高さを選ぶ。具体的な踏み口・屋根・退出路、通路座標・加工元の高さは [import.json](import.json)。

## 本体との接続

本体の地面・接触・射線・視点とBot経路に、都市データのあるマップだけが使う処理を追加した。従来マップは既存の処理を使う。基地の座標を任意のXZ位置へ置けるようにし、コア・傘・索敵・施設・防衛得点を同じ基準で扱う。再出撃は基地側46〜52mの安全な陸上候補を使う。

形状から描画と接触・射線の面を作り、街路の928節点・1,447辺を使用する（入力929節点・1,450辺から通行不可の辺と孤立節点を除外）。川底・坂・橋の高さを含むXYZ座標を1cm格子のint16で可逆に保存する。マップを切り替えると都市の判定形状と材質を破棄する。地図の元画像・座標の展開はキャッシュし、繰り返し切り替えても形状を積み重ねない。

都市データは `prototype/maps/hoshimichi.js` → `tools/build_maps.py` → `prototype/maps.js` に同梱する。地形の追加ダウンロードや、配布に新しい実行ファイル・JSファイルを要求しない。通常本体のThree.js・フォントの取り扱いは同じ。

登録するマップJSON全体は **87,838 B**、コメントを含むマップファイルは **88,076 B**。形状と施設・Bot経路・再出撃データを合わせた非圧縮値で100,000 B以下。変換器の入力ハッシュと容量は [import.json](import.json)、地理データの出典・加工内容・謝辞は [CREDITS.md](CREDITS.md)。

## 再生成と検査

生成にNumPy・Shapely 2を使う（ゲームへの同梱は不要）。`PYTHONPATH` はそれらを入れた環境に合わせる。

```sh
PYTHONPATH=/path/to/plateau-python python3 tools/import_city_map.py
python3 tools/build_maps.py
python3 tools/test/city_map_format_check.py
python3 tools/test/make_dbg.py dbg
node tools/test/catapult_control_check.js dbg
node tools/test/hoshimichi_mobility_check.js dbg
node tools/test/hoshimichi_check.js dbg 600
node tools/test/hoshimichi_integration_check.js dbg
node tools/test/map_check.js dbg hoshimichi
node tools/test/quick_check.js origin/main 60
node tools/test/kanto_mobility_check.js dbg
```

[カタパルトの操作解除](../catapult-control-check.json)は台地・星路・環都の全30台、軽量/重量・両軍・30/120Hzの240条件で、無入力の着地と1秒後のShift・Space長押しを確認する。天井で1秒以内に着地する8条件でもダッシュと地上ジャンプが使える。

地上4通路の徒歩往復48条件（軽量・標準・重量機、30/120Hz）、本体Bot16条件、上面16地点と天井への射撃を検査する。パッド10基は屋根から反対側の道路までの実走120条件と、本体Botによる屋上到達40条件。カタパルト10基は両軍・軽量/重量・30/120Hzの80条件。結果は [mobility-check.json](mobility-check.json)。

対戦施設の専用検査はカタパルト60条件（軽量・標準・重量機、30/120Hz）、占拠・再出撃192サンプル、両基地から4地点への徒歩8経路、補給の制約、隠れたポッドの視認、砲台・レーダーを本体で確認する。最初の接地と停止後の位置を別々に検査し、初回接地の目標誤差は最大2.03m。対戦の記録は [battle-check.json](battle-check.json)。本体20機の確認試合は600秒で正常終了し、撃破259回・占拠27回・射出台使用182回、ブラウザエラー0だった。

通常HTMLでの操作、従来マップとの切替と破棄、既存配置の同値性の結果は [integration-check.json](integration-check.json)。既存武器・パーツの値は簡易検査でも変更0を確認する。これらは動作確認で、200〜2,000試合による勝率の検証やFPSの測定は行っていない。
